时间 O(n)空间 O(1)内存 ≈ 46.6 MB用例 72/72

src/栈、队列与优先队列/LC0621_TaskScheduler.java提交区
public int leastInterval(char[] tasks, int n) {
        int[] count = new int[26];
        for (char task : tasks) {
            count[task - 'A']++;
        }
        // maxFreq     ：出现次数最多的任务的次数（如 A×3、B×3 时 maxFreq = 3）
        // maxFreqTasks：并列达到 maxFreq 的任务个数（如 A×3、B×3 时 = 2）
        int maxFreq = 0, maxFreqTasks = 0;
        for (int i = 0; i < 26; i++) {
            maxFreq = Math.max(maxFreq, count[i]);
        }
        for (int i = 0; i < 26; i++) {
            maxFreqTasks += count[i] == maxFreq ? 1 : 0;
        }
        // 公式：(maxFreq-1) 轮骨架，每轮 n+1 格；最后一轮 maxFreqTasks 个并列最多频任务收尾。
        // 若任务种类足够多、空位能被填满，最短就是 tasks.length，故取二者较大值。
        return Math.max(tasks.length, (maxFreq - 1) * (n + 1) + maxFreqTasks);
    }

任务调度器：公式法（最大频率骨架），max(maxFreq-1)*(n+1)+并列最多频任务数 与 tasks.length，O(n)/O(1)，一次Accepted（72/72）

思路拆解

公式速记

  • ans = max(tasks.length, (maxFreq - 1) * (n + 1) + maxFreqTasks)
  • maxFreq：出现次数最多的任务的次数
  • maxFreqTasks：出现次数恰好等于 maxFreq 的任务个数（并列最多频任务数，不是任务种类数）
  • (maxFreq-1)*(n+1)：前 maxFreq-1 轮骨架，每轮 n+1 格 = 1 个最多频任务 + n 个冷却/填充位（其余任务或 idle 填）
  • +maxFreqTasks：最后一轮把并列最多频任务紧凑收尾，它们后面没有同类任务、无需再隔 n
  • 任务种类足够多时空位能被填满，最短就是 tasks.length，故取二者较大值

问题本质与解法选择

  • 题目：同类任务之间必须隔 n 个间隔，求完成所有任务的最短时间间隔（空闲 idle 也占间隔）。
  • 朴素模拟（优先队列每轮取剩余最多的任务 + 冷却队列）正确但轮数可达约 10^6；观察发现答案只由「出现次数最多的任务」决定，可用数学公式 O(n) 直接算出。
  • 解法选择：统计频率 → 求最大频率 maxFreq 与「并列达到最大频率的任务个数」maxFreqTasks → 代入公式。

关键设计决策

  • 把最频繁任务排成骨架：maxFreq 个 A，之间各隔 n 个空位。
  • 前 maxFreq-1 轮每轮占 n+1 格（放上所有最多频任务 + 空位由其他任务或 idle 填充）；最后一轮 maxFreqTasks 个最多频任务一起收尾——它们后面没有同类任务，冷却只约束「两个相同任务之间」，所以可以紧凑排列、无需再隔。
  • 公式：(maxFreq - 1) * (n + 1) + maxFreqTasks。
  • 但若任务种类足够多，空位能被填满甚至不够用，此时最短就是 tasks.length，所以答案取 max(tasks.length, 公式)。
  • 关键细节：maxFreqTasks 是「出现次数恰好等于 maxFreq 的任务个数」，不是「出现过的任务种类数」（曾统计错导致 22 vs 16）。

具体 case 推演

  • 示例1：A×3、B×3、n=2 → maxFreq=3，maxFreqTasks=2 → 2×3+2=8，max(6,8)=8。排布 [A B _][A B _][A B]。
  • 最多频+多样：A×6、B~G 各 1、n=2 → maxFreq=6，maxFreqTasks=1（只有 A 并列最多）→ 5×3+1=16 > 12 → 16。若误用种类数 7 会得到 22（错）。
  • 无需 idle：A~G 各 1、n=2 → maxFreq=1，maxFreqTasks=7 → 0×3+7=7 = tasks.length → 7。

边界与细节

  • n=0：公式 (maxFreq-1)×1+maxFreqTasks，取 max 后结果 = tasks.length（无冷却，可连续执行）✓
  • 单任务：maxFreq=1 → 结果 1 ✓
  • 全相同 A×3、n=2：maxFreq=3，maxFreqTasks=1 → 2×3+1=7 ✓

复杂度与下限论证

  • 时间 O(n)：一遍统计频率 + 两遍固定 26 循环，总 O(n)。
  • 空间 O(1)：count[26]。
  • 下界论证：任何方案都 ≥ tasks.length（每个任务至少要执行一次），且 ≥ (maxFreq-1)×(n+1)+maxFreqTasks（最多频任务之间的冷却约束）；这两个下界可以同时构造达到，故取 max 即最短。O(n) 时间已是下限（至少得读一遍全部输入）。
