题目描述

给定一个二叉树的根节点 root ，和一个整数 targetSum ，求该二叉树里节点值之和等于 targetSum 的 路径 的数目。

路径 不需要从根节点开始，也不需要在叶子节点结束，但是路径方向必须是向下的（只能从父节点到子节点）。

我的解法

写法 1 · 双重DFS

时间 O(n²)空间 O(n)内存 ≈ 43.3 MB用例 130/130

LC0437_PathSumIii.java · 双重DFS提交区
int ans;
    public int pathSum(TreeNode root, int targetSum) {
        ans = 0;
        dfs(root, targetSum);
        return ans;
    }

    private void dfs(TreeNode root, int targetSum) {
        if (root == null) {
            return;
        }
        countFrom(root, 0, targetSum);
        dfs(root.left, targetSum);
        dfs(root.right, targetSum);

    }

    private void countFrom(TreeNode root, long cur, int targetSum) {
        if (root == null) {
            return;
        }
        cur += root.val;
        if (cur == targetSum) {
            ans++;
        }
        countFrom(root.left, cur, targetSum);
        countFrom(root.right, cur, targetSum);
    }

写法 2 · 前缀和+回溯哈希

时间 O(n)空间 O(n)内存 ≈ 44.7 MB用例 130/130

LC0437_PathSumIii.java · 前缀和+回溯哈希提交区
int ans;
    public int pathSum(TreeNode root, int targetSum) {
        ans = 0;
        Map<Long, Integer> map = new HashMap<>();
        map.put(0L, 1);
        dfs(root, targetSum, 0, map);
        return ans;
    }

    private void dfs(TreeNode root, int targetSum, long sum, Map<Long, Integer> map) {
        if (root == null) {
            return;
        }
        sum += root.val;

        ans += map.getOrDefault(sum - targetSum, 0);
        map.merge(sum, 1, Integer::sum);

        dfs(root.left, targetSum, sum, map);
        dfs(root.right, targetSum, sum, map);

        Integer cnt = map.merge(sum, -1, Integer::sum);
        if (cnt == 0) {
            map.remove(sum);
        }
    }

思路拆解

问题本质：统计树中所有「父→子」方向的连续路径，节点和等于 targetSum。起点、终点都不固定，暴力枚举每个起点的做法是 O(n²)；换「以终点为核心」的视角：对每个节点当终点，只关心「前面是否存在某个起点使该段和为 target」。

解法选择：DFS 时维护「根到当前节点」的前缀和 sum，「以当前节点为终点的路径和为 target」⇔「此前出现过的某个前缀 = sum - target」。用哈希表登记「已见前缀 → 出现次数」，每个节点 O(1) 查询 + O(1) 登记，整体 O(n)。这是 560 和为 K 的子数组 的树上前缀和版；与数组版的关键差别是树上必须「回溯」——离开子树时撤销当前前缀，否则兄弟分支会共享前缀、把不存在的跨分支路径算进去。

关键设计决策：

  1. map.put(0L, 1)：空前缀代表「从根开始」，否则所有从根出发且和为 target 的路径漏计（单节点 [5]、target=5 靠查 map[0] 命中）。
  2. 先查后登记：先 ans += map.getOrDefault(sum - targetSum, 0)，再登记当前 sum；顺序反了在 target=0 时会把「零长度路径」误算、且同一批前缀被重复配对。
  3. 回溯撤销：子树返回后 map.merge(sum, -1, Integer::sum) 把当前前缀频次减一，保证「已见前缀」只包含当前路径上的祖先。
  4. long sum：节点值 ±1e9、最多 1000 层，前缀和可达 ±1e12，int 会溢出。

具体 case 推演（右链 1→2→3，target=3，期望 2）：

  1. 初始 map={0:1}，ans=0
  2. 节点 1：sum=1，查 map[1-3=-2] → 0；登记 map[1]=1；返回后撤销
  3. 节点 2：sum=3，查 map[3-3=0] → 1，ans=1（路径 [1,2]：空前缀 → 前缀 3 的段）；登记后撤销
  4. 节点 3：sum=6，查 map[6-3=3] → 1，ans=2（路径 [3]：前缀 3 → 前缀 6 的段）；登记后撤销
  5. 总 ans=2 ✓

撤销必要性 case（树 [3,1,2]，target=1，期望 1）：

  1. 节点 3：sum=3，查 map[2] → 0；登记 map[3]
  2. 左子 1：sum=4，查 map[4-1=3] → 1，ans=1（路径 [1]）；登记 map[4]；返回后撤销 map[4]
  3. 右子 2：sum=5，查 map[5-1=4] → 0（若没撤销，残留的 map[4] 会被查中，把跨分支的假路径「左子 1 → 右子 2」误算成第 2 条）
  4. 总 ans=1 ✓

边界与细节：

  • 空树：dfs 的 root==null 直接返回，ans 保持 0
  • 全零树 target=0：相同前缀多次出现，map 频次累加，每条以不同起点为终点的路径单独计数
  • 命中后无需停止：哈希查询天然把「继续向下后再次命中」的路径也计入

复杂度下限论证：必须访问每个节点才能统计以其为终点的路径，时间下界 O(n)；前缀和哈希让每个节点 O(1) 查询/登记，达到下界。空间 O(n)（哈希表最多 n 个前缀 + 递归栈 O(height)）。对比写法 1 双重 DFS（每起点向下累加，最坏 O(n²)）：正确但把大量重复的路径和重新算了一遍；前缀和版用「终点视角 + 哈希」消除重复计算，n≤1000 时两者都能过，但前缀和版才是本题最优复杂度。
