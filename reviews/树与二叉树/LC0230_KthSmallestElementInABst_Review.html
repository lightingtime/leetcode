230. 二叉搜索树中第 K 小的元素 (Kth Smallest Element in a BST)

> https://leetcode.cn/problems/kth-smallest-element-in-a-bst/

难度：Medium ｜ 分类：树与二叉树

标签：树、深度优先搜索、二叉搜索树、二叉树

题目描述

给定一个二叉搜索树的根节点 root ，和一个整数 k ，请你设计一个算法查找其中第 k 小的元素（k 从 1 开始计数）。

示例 1：

输入：root = [3,1,4,null,2], k = 1

输出：1

示例 2：

输入：root = [5,3,6,2,4,null,null,1], k = 3

输出：3

提示：

树中的节点数为 n 。

1 4

0 4

进阶：如果二叉搜索树经常被修改（插入/删除操作）并且你需要频繁地查找第 k 小的值，你将如何优化算法？

LC0230_KthSmallestElementInABst.java · 递归中序 DFS（实例字段计数）提交区
    TreeNode cur;
    int count;
    public int kthSmallest(TreeNode root, int k) {
        count = 0;
        cur = null;
        dfs(root, k);
        return cur.val;
    }

    private void dfs(TreeNode node, int k) {
        if (node == null) {
            return;
        }
        dfs(node.left, k);
        count++;
        if (count == k) {
            cur = node;
        }
        dfs(node.right, k);
    }

思路拆解

问题本质：BST 的关键性质——中序遍历结果就是升序序列。因此「第 k 小」等价于「中序遍历的第 k 个节点」，k 从 1 计数。

解法选择理由：递归中序 DFS，配合实例字段计数器。每次查询重置 count 和 cur，完整中序遍历，当 count 数到 k 时把当前节点记到 cur。单次查询下界 O(n)（最坏需访问全部节点才能确定第 k 小，如 k=n 且退化成链），此解达到。

关键设计决策：

  1. 中序顺序 = 左 → 中 → 右：先递归左子树，再 count++ 访问当前节点，再递归右子树。
  2. 用实例字段 count/cur 传递状态：递归里不需要返回值传来传去，找到后记到 cur。
  3. 每次查询前重置 count=0、cur=null，保证同一个实例多次调用互不污染（这是容易漏的细节）。
  4. 完整遍历、不提前停：逻辑最简；提前停需要额外的 found 标志，收益只在 k 很小时明显。

具体 case 推演（示例2：[5,3,6,2,4,null,null,1]，k=3，中序应为 1,2,3,4,5,6）：

  1. dfs 沿左走到最左 1（count=1）
  2. 回溯到 2（count=2）
  3. 回溯到 3（count=3 == k → cur=3）
  4. 继续遍历完剩余节点（count 继续增大，但 count==k 只触发一次，cur 不被覆盖）

返回 3 ✓

边界与细节：

  • k=1：第一个中序节点即最小值（沿左走到最底）。
  • k=n：最后访问的节点即最大值。
  • 单节点：count 直接到 1 → 返回自身。
  • 退化链（左链/右链）：递归深度 = 链长，n ≤ 10^4 在栈深度安全范围内；迭代版可彻底规避。
  • 值域端点 0 / 10^4：只比较大小关系，无溢出。

复杂度与下限论证：每个节点访问一次 → O(n) 时间；递归栈深度 O(h)，最坏（链）O(n) → 空间 O(n)。单次查询在无额外数据结构时，最坏必须访问 O(n) 个节点，此解达到该下界。

进阶问法（频繁查询 + 频繁修改）：基础解每次查询 O(n) 不满足。标准优化是在每个节点维护「子树大小 size」，查询时比较 k 与左子树大小决定走向，O(h)；插入/删除同步维护 size；配合平衡树（AVL/红黑）可到 O(log n)。
