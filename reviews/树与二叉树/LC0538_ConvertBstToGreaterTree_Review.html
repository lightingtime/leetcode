538. 把二叉搜索树转换为累加树 (Convert BST to Greater Tree)

> https://leetcode.cn/problems/convert-bst-to-greater-tree/

难度：Medium ｜ 分类：树与二叉树

标签：树、深度优先搜索、二叉搜索树、二叉树

题目描述

给出二叉 搜索 树的根节点 root，该树的节点值各不相同，请你将其转换为累加树（Greater Sum Tree），将其转换为一个更大的树，使得原始二叉搜索树中的每个节点值都变为原本值加上原本二叉搜索树中所有比该节点值大的节点值的总和。

提醒一下，二叉搜索树满足下列约束条件：

节点的左子树仅包含键 小于 节点键的节点。

节点的右子树仅包含键 大于 节点键的节点。

左右子树也必须是二叉搜索树。

注意：本题和 1038: https://leetcode.cn/problems/binary-search-tree-to-greater-sum-tree/ 相同

    public TreeNode convertBST(TreeNode root) {
        // TODO: 在这里实现你的解法
        sum = 0;
        dfs(root);
        return root;
    }

    private void dfs(TreeNode root) {
        if (root == null) {
            return;
        }
        dfs(root.right);
        root.val += sum;
        sum = root.val;
        dfs(root.left);
    }

思路拆解

问题本质

把每个节点改成「原树中所有 ≥ 它的节点值之和」。BST 的性质决定了这个和可以沿着「降序遍历」累积出来：值域从大到小扫一遍，边扫边累加，每个节点的新值 = 已经扫过的更大值之和 + 自身原值。

为什么用反向中序遍历 + 全局累加和

  • 中序遍历（左→根→右）得到升序；反过来（右→根→左）就是降序，恰好按「从大到小」访问每个节点。
  • 维护累加和 sum：访问某个节点时，sum 里已经存的是「所有比它大的节点值之和」；把 sum 加回当前节点，再把新值并入 sum，下一个更小的节点自然继承。
  • 不用额外数组存节点序列：一趟递归同时完成「降序访问 + 累加」，时间 O(n) 已是下限。

关键设计决策

  • 状态：long sum 成员变量，跨递归共享。Java 基础类型按值传递，若用方法参数传 int，每层递归拿到的只是副本，累加结果带不回来。
  • 递归顺序：先右子树 → 当前节点 → 左子树。右子树里全是更大的值，必须先算完，当前节点才能拿到正确累加和。
  • 更新公式顺序不能反：root.val += sum; sum = root.val;——先加旧 sum，再把自己新值并入。
  • 空节点直接返回；convertBST 入口把 sum 归零，保证多次调用不串值。

小 case 推演

树：根 2，左 1，右 3（期望结果：3 不变、2→5、1→6）：

  1. sum = 0
  2. 访问右子树 3：3 + 0 = 3，sum = 3
  3. 访问根 2：2 + 3 = 5，sum = 5
  4. 访问左子树 1：1 + 5 = 6，sum = 6

结果：右 3、根 5、左 6，与题目期望一致 ✅。若按「先序逆序（右→左→根）」访问，顺序会变成 3、1、2，得到 3、4、6 ❌——顺序是正确性关键。

边界与细节

  • 空树：返回 null。
  • 单节点：没有更大的值，值不变。
  • 左链/右链：递归深度 O(n)，本题规模下安全。
  • 负数节点：累加与正负无关，直接加（如 -3 只有右子 1，结果为 -2）。
  • 累加和可能超出 int：用 long 零成本防御。

复杂度与下限论证

  • 时间 O(n)：每个节点恰好访问一次；任何解法都必须修改每个节点，O(n) 是下限。
  • 空间 O(h)：递归栈深度 = 树高，最坏 O(n)（链状）。
  • 成员变量 sum 只占 O(1) 额外空间；若要求严格 O(1) 空间可改 Morris 反向中序遍历，但本题递归已是最简洁且足够的最优解。
