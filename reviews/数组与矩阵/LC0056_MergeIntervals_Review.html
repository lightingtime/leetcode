LC0056 · 合并区间 Merge Intervals

排序 + 单遍合并：把二维重叠问题降维成一维扫描
✓ Accepted 172/172 难度 Medium 分类 数组与矩阵 提交一次通过 · 最优解 2026-08-06

我的解法

思路：排序 + 单遍合并。先按区间左端点升序排序，让所有可能重叠的区间变成「相邻」； 然后线性扫描，维护结果里最后一个区间 last：当前区间与 last 重叠或首尾相接 （last[1] >= interval[0]）就延伸右端点；否则新开一个区间加入结果。

时间 O(n log n) 空间 O(n) 满足题目复杂度要求

src/LC0056_MergeIntervals.java提交区
public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> list = new ArrayList<>();
    for (int[] interval : intervals) {
        if (list.isEmpty()) {
            list.add(new int[]{interval[0], interval[1]});
        } else {
            int[] last = list.get(list.size() - 1);
            if (last[1] >= interval[0]) {
                if (last[1] < interval[1]) {
                    last[1] = interval[1];
                }
            } else {
                list.add(new int[]{interval[0], interval[1]});
            }
        }
    }
    return list.toArray(new int[0][]);
}

边界语义：重叠判定用 last[1] >= interval[0]，= 时也算重叠 （如 [1,4] 与 [4,5] 合并为 [1,5]）；包含场景只需比较右端点取大，左端点已被排序保证有序。

算法判定：排序 + 单遍合并，已是最优

  • 时间复杂度 O(n log n)：排序是瓶颈；合并本身只有 O(n) 单遍扫描。
  • 空间复杂度 O(n)：结果列表最多 n 个区间，另计排序 O(log n) 栈空间。
  • 正确性：左端点升序后，重叠只可能发生在相邻区间，扫一遍即可收拢所有合并。
  • 边界覆盖：空输入、单元素、全相同、大数、包含、首尾相接（= 算重叠）、互不重叠全部通过。
  • 结论：与标准解法一致，无需再优化。

可微调点（不改变复杂度）

  • 内层 if (last[1] < interval[1]) last[1] = interval[1]; 可简写为 last[1] = Math.max(last[1], interval[1]);。
  • 开头 list.isEmpty() 分支可并入判断：list.isEmpty() || last[1] < interval[0] 时新开区间，else 里直接取 max，逻辑更扁平。

分类提醒 · 数组与矩阵

矩阵题先想如何用行列信息/排序/原地操作降维。

区间类问题（合并、插入、最少箭矢）的通用起手式：先排序把「任意两两关系」变成「相邻关系」， 再单遍扫描；重叠判定记住边界相接（end1 >= start2）通常也算重叠。

排序降维 · 本质梳理

  • 为什么要排序：不排序时，每个新区间可能和「任意」已收集区间重叠，需要反复回看； 按左端点排序后，新区间只可能和「最后一个」区间重叠，把 O(n²) 的两两比较降成 O(n) 的相邻比较。
  • 为什么只需维护最后一个：排序保证新区间的左端点 ≥ 所有已收集区间的左端点， 所以它只会与右端点最大的那个（也就是结果末尾的 last）发生关系；与 last 不重叠， 就与之前所有区间都不重叠。
  • 包含场景：新区间整体落在 last 内部时（last[1] >= interval[1]）， 什么都不用改，这正是「只取右端点最大值」能自动处理的。
  • 相接边界：题目把 [1,4] 与 [4,5] 视为重叠， 所以判定式必须用 >= 而不是 >。
