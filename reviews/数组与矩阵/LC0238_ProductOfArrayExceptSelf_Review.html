LC0238 · 除自身以外数组的乘积 Product of Array Except Self

前缀积 × 后缀积：不用除法的两趟遍历

我的解法

思路：前缀积数组 × 后缀积数组。每个位置的答案 = 左边所有数的乘积 × 右边所有数的乘积。 第一趟正向填 leftMul[i]（nums[0..i-1] 的累积积），第二趟反向填 rightMul[i]（nums[i+1..n-1] 的累积积），第三趟按位相乘写回结果。

时间 O(n) 空间 O(n) 满足 O(n) 时间要求，进阶 O(1) 额外空间未达

public int[] productExceptSelf(int[] nums) {
    int[] leftMul = new int[nums.length];
    leftMul[0] = 1;
    for (int i = 1; i < leftMul.length; i++) {
        leftMul[i] = leftMul[i - 1] * nums[i - 1];
    }
    int[] rightMul = new int[nums.length];
    rightMul[nums.length - 1] = 1;
    for (int i = nums.length - 2; i >= 0; i--) {
        rightMul[i] = rightMul[i + 1] * nums[i + 1];
    }
    for (int i = 0; i < nums.length; i++) {
        nums[i] = leftMul[i] * rightMul[i];
    }
    return nums;
}

边界语义：左/右两端用 1 作为「空乘积」的起点；含 0、多个 0、负数都能被纯乘法正确覆盖， 不依赖除法所以没有除零问题。

算法判定：时间达标，空间未达进阶要求

  • 时间复杂度 O(n)：三趟线性扫描，符合题目 O(n) 要求。
  • 空间复杂度 O(n)：两个辅助数组，暂未满足进阶的 O(1) 额外空间。
  • 正确性：左右两段积互不包含自身，相乘即答案；纯乘法天然兼容 0 与负数。
  • 边界覆盖：空输入、单元素、最短长度 2、全相同、单个/多个 0、负数、大数全部通过。
  • 结论：思路正确、可 AC；进阶空间优化留待重写。

优化方向（宽泛提示，不替写）

题目已说明「输出数组不计入额外空间」——想想 leftMul 能不能直接借用答案数组来存； 右边那段积其实不需要第二个数组，反向遍历时用一个滚动变量边走边累乘即可。 省掉第二个数组和第三趟循环后，额外空间就是 O(1)。

分类提醒 · 数组与矩阵

矩阵题先想如何用行列信息/排序/原地操作降维。

数组题的常见套路：遇到「每个位置要整段信息、又不能 O(n²)」时，先想前缀/后缀累积； 留意题面里「输出数组不算额外空间」这类进阶设定，它往往是空间优化的钥匙。

前缀积 · 本质梳理

  • 为什么不能用除法：题目明确禁止；且数组中若有 0，总积为 0，除零直接崩。
  • 为什么拆成两段积：answer[i] 不含 nums[i]，等价于 「左边全部 × 右边全部」，两段各自是连续区间积，正好用一次线性扫描的累积来算。
  • 为什么边界用 1 起步：空区间的乘积约定为 1（乘法单位元）， 所以 leftMul[0] = 1、rightMul[n-1] = 1。
  • 为什么空间还能省：leftMul 每个位置只需要「上一个累积 × 当前左边一个元素」， 累积过程可以落在最终答案数组上（它本来就要输出）；右侧同理只需一个向后滚动的变量。
