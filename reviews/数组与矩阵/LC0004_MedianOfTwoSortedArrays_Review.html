我的解法

思路：把「中位数」转化为「两数组第 k 小」。 kthSmallest 每轮取两侧「有效部分」的第 k/2 个元素当候选 （候选下标 = p + k/2 − 1，数组不够长时封顶到最后一个），比较后排除 较小一侧的候选及其前面所有元素，k 减去实际排除的数量；出口有两个：某一边已排空时 直接从另一边取第 k 个，k == 1 时取两边头部较小值。

main 方法按总长奇偶把中位数换算成 1 基排名：奇数 → 第 totLen/2 + 1 小； 偶数 → 第 totLen/2 小与第 totLen/2 + 1 小取平均。

时间 O(log(m+n)) 空间 O(1) 迭代版：p1/p2 为有效起点，循环替代递归

public double findMedianSortedArrays(int[] nums1, int[] nums2) {
    int len1 = nums1.length, len2 = nums2.length;
    int totLen = len1 + len2;
    // 中位数换算成「第 k 小」（1 基排名，不是数组下标）
    if (totLen % 2 == 1) {
        return kthSmallest(nums1, nums2, totLen / 2 + 1);
    }
    int k1 = totLen / 2, k2 = totLen / 2 + 1;
    return (kthSmallest(nums1, nums2, k1) + kthSmallest(nums1, nums2, k2)) / 2.0;
}

private int kthSmallest(int[] nums1, int[] nums2, int k) {
    int len1 = nums1.length, len2 = nums2.length;
    int p1 = 0, p2 = 0; // 有效起点，只会向右移动
    while (true) {
        if (p1 >= len1) {
            return nums2[p2 + k - 1];
        } else if (p2 >= len2) {
            return nums1[p1 + k - 1];
        } else if (k == 1) {
            return Math.min(nums1[p1], nums2[p2]);
        }
        int cand1 = Math.min(len1 - 1, p1 + k / 2 - 1);
        int cand2 = Math.min(len2 - 1, p2 + k / 2 - 1);
        if (nums1[cand1] <= nums2[cand2]) {
            int removed = cand1 - p1 + 1;
            p1 = cand1 + 1;
            k -= removed;
        } else {
            int removed = cand2 - p2 + 1;
            p2 = cand2 + 1;
            k -= removed;
        }
    }
}

解题过程

01 · 概念理解：为什么较小候选排不到第 k 位理解 ▸

官方题解「第 k 小」的证明逐步讲通：假设 A[k/2−1] ≤ B[k/2−1]， 比 A[k/2−1] 小的元素在 A 里最多 k/2−1 个、在 B 里最多 k/2−1 个 （因为 B[k/2−1] 已经不比它小，B 中更小的只能出现在更前面），合计最多 k−2 个——它最多排第 k−1 位，所以 A 的前 k/2 个元素都不可能是第 k 小，可以整体排除。

02 · 逐步拆解写法：出口、候选、排除、k 更新拆解 ▸

一次只讲一块：先定义 p1/p2（两个数组的有效起点，只会右移）， 再写三个出口（一边排空 ×2、k == 1）；随后是候选下标 p + k/2 − 1（越界封顶到 len−1）、排除数量 候选下标 − 旧起点 + 1（两头含候选）、k 减去实际排除数量而非 k/2。 迭代版用 while(true) 原地更新指针，等价于递归传参。

03 · 踩坑：第 k 小是排名，main 里当成了下标8 个用例失败 ▸

辅助函数出口是 nums2[p2 + k − 1]、k == 1 返回头部， 说明 k 是从 1 数起的排名；但 main 里按 0 基下标算中间位置（totLen/2、 totLen/2 − 1）直接传入，整体偏小 1：

main 方法 · 错误示范0 基下标 vs 1 基排名
// 示例1：期望 2.0，实际 1.0（取到第 1 小而非第 2 小）
// 示例2：期望 2.5，实际 1.5（取到第 1、2 小而非第 2、3 小）
// 空数组：k=0 → nums2[-1] 越界

本质：下标 i 的元素是「第 i+1 小」，下标和排名永远差 1。

04 · 修复：排名 = 下标 + 1，本地 9/9 通过已解决 ▸

三个传参各 +1：奇数 totLen/2 + 1；偶数 totLen/2 与 totLen/2 + 1。两个示例 + 7 个边界（空数组、全相同、单元素、负数、 大小悬殊、极端大数）全部通过。

算法判定：满足题意 O(log(m+n))，进阶可优化

  • 时间复杂度 O(log(m+n))：每轮排除一侧的前 k/2 个候选，k 至少减半，轮数 O(log(m+n))，满足题目要求。
  • 空间复杂度 O(1)：只用两个指针 + 常数个变量，迭代无递归栈。
  • 正确性：三个出口（一边排空 ×2、k==1）+ 候选封顶 + k 减实际排除数量，缺一不可。
  • 进阶方向：本类题还有「划分数组」写法，时间复杂度 O(log(min(m,n)))，长度悬殊时更优；列为重点复习内容。

套路沉淀

#17 第 k 小 / 中位数的排名换算：1 基第 k 小 vs 0 基下标 调用前先确认被调函数的 k 是「第几个」（1 基）还是「下标」（0 基）；「第 k 个」的下标 = 起点 + k − 1， 下标 i 的排名 = i + 1。
