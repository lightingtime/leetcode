我的解法

思路：两次二分找插入点。定义 findFirstIndex(nums, t) 返回第一个 >= t 的下标（lower bound，不存在时返回 n）；左边界 = findFirstIndex(nums, target)， 右边界 = findFirstIndex(nums, target + 1) - 1。若左边界越界或 nums[left] != target 说明目标不存在，返回 [-1, -1]。

二分用全开区间 (left, right) 红蓝染色模板：left = -1（确定 < target 的哨兵）、 right = n（确定 >= target 的哨兵），while (left + 1 < right)， nums[mid] < target 时 left = mid，否则 right = mid， 循环结束 right 即第一个满足位置。

时间 O(log n) 空间 O(1) 满足题目复杂度要求

public int[] searchRange(int[] nums, int target) {
    // TODO: 在这里实现你的解法
    if (nums.length == 0) {
        return new int[]{-1, -1};
    }
    int left = findFirstIndex(nums, target);
    int right = findFirstIndex(nums, target + 1);
    if (left >= nums.length || right < left || nums[left] != target ) {
        return new int[]{-1, -1};
    }
    return new int[] {left, right - 1};
}

private int findFirstIndex(int[] nums, int target) {
    int left = -1, right = nums.length;
    while (left + 1 < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid;
        } else {
            right = mid;
        }
    }
    return right;
}

边界语义：全开区间 (left, right) 两端都是哨兵（-1 与 n），循环在 left + 1 == right 时结束，答案恒为 right；两种移动对称（都收 mid）， 没有 +1/-1 的纠结。空数组时 findFirstIndex 直接返回 0，外层靠 left >= nums.length 兜底。

解题过程

01 · 下界区间端点选错：right 取 n-1差一/越界 ▸

找「第一个 >= target」的答案可能是 n（target 大于所有元素），闭区间 right = n-1 配 while (left < right) 在 target 大于所有元素时停在 n-1 且不验证该元素，返回 n-1 而非插入点 n；空数组时 right = -1 循环不执行直接返回 0， 后续解引用越界。

02 · left=mid 配下取整：死循环卡死 ▸

区间只剩两个元素时 mid == left，else 分支 left = mid 原地踏步， 循环永不退出（本地测试整体卡死超时）。用 left = mid 收拢时必须让 mid 上取整， 或改排除式 left = mid + 1。

03 · lower bound 比较符方向/等号归属错区间错位 ▸

写成分支方向相反（nums[mid] > target 收 right、else left = mid） 实际收敛到「最后一个 <= target」，两次调用组合出的区间整体错位；随后又写成 nums[mid] <= target 收缩右边界，把小于 target 的值也当候选保留。 正确写法：nums[mid] < target 排除 mid（left = mid）， >= target 保留 mid（right = mid）——相等时 mid 恰是候选。

04 · 为凑末尾差一去掉了 right-1 补偿右边界多 1 ▸

target 在末尾时 lower_bound(target+1) 因右端点取 n-1 停在 n-1，减 1 后差一，于是改成不减 1； 结果非末尾用例的右边界整体多 1。根因是右端点应取 n（开区间），而不是去掉 -1 补偿。

05 · 全开区间模板返回错哨兵：left 而非 right越界/错位 ▸

循环结束返回 left，但 left 是最后一个「不满足」的哨兵、right 才是第一个「满足」的位置； 返回 left 会得到 -1（target 小于所有元素或首元素即满足）或前一位，导致 nums[-1] 越界或整体结果错位。

06 · 统一全开区间模板：本地全过已解决 ▸

固定为 left=-1, right=n, while(left+1<right), 返回 right 的红蓝染色写法， 两种移动对称收 mid，没有差一纠结。3 示例 + 8 边界（单元素命中/未命中、全相同、开头/结尾、 小于最小值/大于最大值、大数）全部通过。

算法判定：两次二分找边界，已是最优

  • 时间复杂度 O(log n)：两次独立二分，2·log n 仍是 log n 量级；有序数组区间查询的下界就是二分，无法再快。
  • 空间复杂度 O(1)：只用了 left、right、mid 三个变量。
  • 正确性：lower bound 用全开区间哨兵模板，右端点恒为 n，>= 归 right（保留候选）、< 归 left（排除），答案恒为 right，规避了全部差一/等号陷阱。
  • 边界覆盖：单元素、全相同、开头/结尾、越界（小于最小/大于最大）、空数组、大数全部通过。
  • 结论：与标准解法一致，无需再优化。

分类提醒 · 数组与矩阵

矩阵题先想如何用行列信息/排序/原地操作降维。

有序数组 + O(log n) 查找 = 二分；「找重复区间的首尾」= 两次 lower bound（target 与 target+1）， 比写两个不同二分更不易错。

套路沉淀

本轮沉淀 5 条套路（lc-analyze/references/patterns.md），核心两条：

二分下界（lower bound）的右端点必须用开区间 n：答案可能是插入点 n（target 大于所有元素）， 闭区间 n-1 配 while(left<right) 会停在 n-1 且不验证该元素；空数组时 right=-1 循环不执行直接返回，造成越界。
全开区间 (L,R) 红蓝染色模板：初始 L=-1（不满足哨兵）、R=n（满足哨兵）， while(L+1<R)，mid 严格落在内部，排除/保留都收端点（L=mid 或 R=mid），结束时答案在边界， lower bound 的答案是 R。两种移动对称，没有 +1/-1 纠结。

错误习惯复盘

  • 二分下界区间端点选错：right 取 n-1 而非开区间 n，target 大于所有元素时差一，空数组时直接越界。
  • left=mid 配下取整死循环：两元素区间 mid==left 原地踏步；left=mid 收拢必须让 mid 上取整，或改排除式 left=mid+1。
  • lower bound 分支方向写反：nums[mid] > target 收 right、else left=mid 实际在找最后一个 <= target。
  • 比较符等号归属错：nums[mid] <= target 保留会把「小于」也当候选；相等时 mid 是候选，等号必须与保留侧同侧。
  • 为凑末尾差一去 right-1 补偿：根因是右端点应为 n（开区间），不是去掉补偿。
  • 全开区间模板返回错哨兵：循环结束应返回 right（第一个满足），left 是最后一个不满足。
