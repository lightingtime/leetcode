public int[] searchRange(int[] nums, int target) {
        if (nums.length == 0) {
            return new int[]{-1, -1};
        }
        int left = findFirstIndex(nums, target);
        int right = findFirstIndex(nums, target + 1);
        if (left >= nums.length || right < left || nums[left] != target ) {
            return new int[]{-1, -1};
        }
        return new int[] {left, right - 1};
    }

	private int findFirstIndex(int[] nums, int target) {
        int left = -1, right = nums.length;
        while (left + 1 < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < target) {
                left = mid;
            } else {
                right = mid;
            }
        }
		return right;
	}

排序数组找首尾：两次二分分别找 target 与 target+1 的插入位置，O(log n)/O(1)，一次 Accepted（88/88）

思路拆解

问题本质：有序数组中找 target 的左右边界 = 两个二分：第一个 ≥ target 的位置，与第一个 > target 的位置，右边界 = lowerBound(target+1)-1。

关键设计：只写一个 lowerBound（返回第一个 ≥ x 的下标）：左开右开区间 (left=-1, right=len)，mid 小于 x 时 left=mid（排除左侧），否则 right=mid，循环 left+1<right 结束后 right 即答案。对 target 和 target+1 各调一次，逻辑完全复用，避免两份边界二分不一致。

边界：空数组直接返回 [-1,-1]；target 不存在时 left>=len 或 nums[left]!=target，返回 [-1,-1]；target 是最大元素时 target+1 让 lowerBound 返回 len，right-1 仍正确；全数组等于 target。

复杂度：O(log n) 时间、O(1) 空间，最优。

错误习惯复盘

二分下界区间端点选错：right 初始化为 nums.length-1 且 while(left<right) 在区间只剩一个元素时退出而不验证该元素是否满足条件，target 大于所有元素时返回 n-1 而非插入点 n，导致「target+1 的 first index - 1」整体差一；空数组时 right=-1 循环不执行直接返回 0，后续解引用越界（累计 1 次）

二分 left=mid 配下取整死循环：区间只剩两个元素时 mid==left，else 分支 left=mid 原地踏步，循环永不退出（本地测试整体卡死超时）；用 left=mid 收拢时必须让 mid 上取整，或改排除式 left=mid+1（累计 1 次）

lower bound 分支方向写反：找第一个 >= target 的位置时，nums[mid] < target 才排除 mid（left=mid+1），nums[mid] >= target 时 mid 仍是候选（right=mid）；写成 nums[mid] > target 收 right、else left=mid 实际在找最后一个 <= target，searchRange 两次调用组合出的区间错位（累计 1 次）

lower bound 保留/排除条件写反：nums[mid] <= target 时收缩右边界，把小于 target 的值也当候选保留；nums[mid] > target 时反而排除 mid。应为 nums[mid] < target 排除 mid（left=mid+1）、nums[mid] >= target 保留 mid（right=mid），等于 target 时 mid 恰是候选（累计 1 次）

为凑末尾差一去掉了 right-1 补偿：target 在末尾时 lower_bound(target+1) 因右端点取 n-1 停在 n-1，减 1 后差一，于是改成不减 1，导致非末尾用例（target 不在末尾）右边界整体多 1；根因是右端点应取 n（开区间），不是去掉 -1（累计 1 次）

全开区间（红蓝染色）模板返回错哨兵：循环结束返回 left，但 left 是最后一个「不满足」（蓝）的位置、right 才是第一个「满足」（红）的位置；lower bound 的答案应返回 right。返回 left 会得到 -1（target 小于所有元素或首元素即满足）或前一位，导致 nums[-1] 越界或整体结果错位（累计 1 次）
