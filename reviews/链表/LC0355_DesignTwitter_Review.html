    static class Twitter {
        Map<Integer, List<Integer>> tweets;
        Map<Integer, Set<Integer>> followers;
        Map<Integer, Set<Integer>> followees;
        int uniId;
        Map<Integer, Integer> tweetMap;
        public Twitter() {
            tweets = new HashMap<>();
            followers = new HashMap<>();
            followees = new HashMap<>();
            uniId = 0;
            tweetMap = new HashMap<>();
        }
        public void postTweet(int userId, int tweetId) {
            uniId++;
            tweetMap.put(tweetId, uniId);
            tweets.computeIfAbsent(userId, x -> new LinkedList<>()).add(0, tweetId);
        }
        public List<Integer> getNewsFeed(int userId) {
            List<List<Integer>> allNews = new ArrayList<>();
            if (tweets.containsKey(userId)) {
                allNews.add(tweets.get(userId));
            }
            if (followers.containsKey(userId)) {
                for (Integer followeeId : followers.get(userId)) {
                    if (tweets.containsKey(followeeId)) {
                        allNews.add(tweets.get(followeeId));
                    }
                }
            }
            if (allNews.isEmpty()) {
                return new ArrayList<>();
            }
            List<Integer> sortNews = getSortNews(allNews, 0, allNews.size() - 1);
            return new ArrayList<>(sortNews.subList(0, Math.min(10, sortNews.size())));
        }

        private List<Integer> getSortNews(List<List<Integer>> allNews, int l, int r) {
            if (l >= r) {
                return allNews.get(l);
            }
            int mid = l + (r - l) / 2;
            List<Integer> first = getSortNews(allNews, l, mid);
            List<Integer> second = getSortNews(allNews, mid + 1, r);
            return mergeList(first, second);
        }

        private List<Integer> mergeList(List<Integer> first, List<Integer> second) {
            List<Integer> list = new ArrayList<>();
            int i = 0, j = 0;
            while (i < first.size() && j < second.size()) {
                if (list.size() == 10) {
                    break;
                }
                if (tweetMap.get(first.get(i)) > tweetMap.get(second.get(j))) {
                    list.add(first.get(i));
                    i++;
                } else {
                    list.add(second.get(j));
                    j++;
                }
            }
            while (i != first.size() && list.size() < 10) {
                list.add(first.get(i));
                i++;
            }
            while (j != second.size() && list.size() < 10) {
                list.add(second.get(j));
                j++;
            }
            return list;
        }

        public void follow(int followerId, int followeeId) {
            followers.computeIfAbsent(followerId, k -> new HashSet<>()).add(followeeId);
            followees.computeIfAbsent(followeeId, k -> new HashSet<>()).add(followerId);
        }
        public void unfollow(int followerId, int followeeId) {
            if (followers.containsKey(followerId)) {
                followers.get(followerId).remove(followeeId);
            }
            if (followees.containsKey(followeeId)) {
                followees.get(followeeId).remove(followerId);
            }
        }
    }

设计推特：头插推文流+全局时间戳+归并 Top-10，一次 Accepted（22/22），179 题第一遍收官

思路拆解

1. 问题本质与解法选择

本质：设计 Twitter——发推、关注/取关、取「自己 + 关注人」最近 10 条按时间倒序。最多 3×10⁴ 次调用。核心难点在 getNewsFeed 的多路合并 Top-10：每个用户的推文流都是按时间倒序的链表，合并多个有序流取最近 10 条。用二分归并（或优先队列多路归并）逐个取时间戳最大的。

2. 关键设计决策

  • 推文流头插：tweets 用 Map<Integer, List<Integer>>，postTweet 用 add(0, tweetId) 头插，保证每个用户列表「最近在前」——这是归并正确的前提（踩坑：尾插会让单用户列表变成正序，feed 顺序全反）。
  • 全局时间戳：uniId 每次发推自增，tweetMap: tweetId → uniId。题目只保证 tweetId 唯一、不保证递增，所以排序必须用独立时间戳，绝不能拿 tweetId 当时间（踩坑：曾用 tweetId 比较，多关注人合并排错）。
  • 关注表：followers: Map<Integer, Set<Integer>>（userId → 关注的人集合），follow/unfollow O(1)。
  • 二分归并：getSortNews 递归对半拆列表，mergeList 双指针比较时间戳（大者=更近=靠前），每个输出列表截断 10。

3. 边界与细节

  • 空 feed：用户没发过推也没关注人 → 返回空列表。
  • 单用户：只有一个列表时 l >= r 原样返回，靠头插保持倒序。
  • 截断：mergeList 里 list.size()==10 提前停 + 外层 subList(0, min(10, size)) 双重保证。
  • 排序键是时间戳不是 tweetId（本地测试「先发 100、后发 1」验证）。
  • 取关：从 followers 移除后 feed 不再包含该用户推文；辅助结构 followees 有个条件写反的小 bug（未被读取，不影响对外行为）。

5. 复杂度与最优性

  • postTweet / follow / unfollow：O(1)。
  • getNewsFeed：参与合并的列表数 k（自己 + 关注人），二分归并 O(L·log k)（L 为参与推文总数），且每层截断 10 → 实际 O(10·k·log k) 以内；也可用优先队列 O(L·log k)。数据规模 3×10⁴ 次调用下足够。
  • 空间：O(总推文数 + 关注关系)。
  • 下界论证：feed 至少要「看」每个关注人链表头部，O(k)；排序取 Top-10 至少 O(k log k) 量级，本解达到合理最优。
