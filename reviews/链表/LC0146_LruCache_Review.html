146. LRU 缓存 (LRU Cache)

> https://leetcode.cn/problems/lru-cache/

难度：Medium ｜ 分类：链表

标签：设计、哈希表、链表、双向链表

题目描述

请你设计并实现一个满足 LRU (最近最少使用) 缓存 约束的数据结构。

实现 LRUCache 类：

LRUCache(int capacity) 以 正整数 作为容量 capacity 初始化 LRU 缓存

int get(int key) 如果关键字 key 存在于缓存中，则返回关键字的值，否则返回 -1 。

void put(int key, int value) 如果关键字 key 已经存在，则变更其数据值 value ；如果不存在，则向缓存中插入该组 key-value 。如果插入操作导致关键字数量超过 capacity ，则应该 逐出 最久未使用的关键字。

函数 get 和 put 必须以 O(1) 的平均时间复杂度运行。

示例：

输入

["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]

[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]

输出

[null, null, null, 1, null, -1, null, -1, 3, 4]

解释

LRUCache lRUCache = new LRUCache(2);

lRUCache.put(1, 1); // 缓存是 {1=1}

lRUCache.put(2, 2); // 缓存是 {1=1, 2=2}

lRUCache.get(1); // 返回 1

lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3}

lRUCache.get(2); // 返回 -1 (未找到)

lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3}

lRUCache.get(1); // 返回 -1 (未找到)

lRUCache.get(3); // 返回 3

lRUCache.get(4); // 返回 4

    static class LRUCache {
        Map<Integer, Node> map;
        Node head;
        Node tail;
        int capacity;

        public LRUCache(int capacity) {
            this.capacity = capacity;
            map = new HashMap<>();
            head = new Node();
            tail = new Node();
            head.next = tail;
            tail.pre = head;
        }

        public int get(int key) {
            if (!map.containsKey(key)) {
                return -1;
            }
            Node node = map.get(key);
            unLinkNode(node);
            move2Head(node);
            return node.val;
        }

        public void put(int key, int value) {
            Node node;
            if (map.containsKey(key)) {
                node = map.get(key);
                node.val = value;
                unLinkNode(node);
            } else {
                node = new Node(key, value);
                map.put(key, node);
            }
            move2Head(node);
            if (map.size() > capacity) {
                Node last = tail.pre;
                unLinkNode(last);
                map.remove(last.key);
            }
        }

        private void unLinkNode(Node node) {
            node.pre.next = node.next;
            node.next.pre = node.pre;
        }

        private void move2Head(Node node) {
            node.next = head.next;
            node.pre = head;
            head.next.pre = node;
            head.next = node;
        }

        static class Node {
            Node next;
            Node pre;
            int val;
            int key;

            Node() {}

            Node(int key, int val) {
                this.key = key;
                this.val = val;
            }
        }
    }

            unLinkNoe(node);
            move2Head(node);
            return node.val;
        }

        private void move2Head(Node node) {
            head.next.pre = node;
            node.next = head.next;
            node.pre = head;
            head.next = node;
        }

        private void unLinkNoe(Node node) {
            node.pre.next = node.next;
            node.next.pre = node.pre;
        }

        public void put(int key, int value) {
            Node node;
            if (map.containsKey(key)) {
                node = map.get(key);
                node.val = value;
                unLinkNoe(node);

                node = new Node(key, value);
                map.put(key, node);

            }
        }

static class LRUCache {
        Map<Integer, Node> map;
        int capacity;
        Node head;
        Node tail;
        int size;
        public LRUCache(int capacity) {
            this.map = new HashMap<>();
            this.capacity = capacity;
            this.size = 0;
            head = new Node();
            tail = new Node();
            head.next = tail;
            tail.pre = head;
        }
        public int get(int key) {
            if (!map.containsKey(key)) {
                return -1;
            }
            Node node = map.get(key);
            unLinkNode(node);
            move2Head(node);
            return node.val;
        }

        private void move2Head(Node node) {
            node.next = head.next;
            node.pre = head;
            head.next.pre = node;
            head.next = node;
        }

        private void unLinkNode(Node node) {
            node.next.pre = node.pre;
            node.pre.next = node.next;
            node.next = null;
            node.pre = null;
        }

        public void put(int key, int value) {
            Node node;
            if (map.containsKey(key)) {
                node = map.get(key);
                node.val = value;
                unLinkNode(node);
            } else {
                node = new Node(value, key);
                map.put(key, node);
                size++;
            }
            move2Head(node);
            if (size > capacity) {
                Node pre = map.get(tail.pre.key);
                unLinkNode(pre);
                map.remove(pre.key);
                size--;
                pre = null;
            }
        }
    }

    static class Node {
        Node next;
        Node pre;
        int val;
        int key;

        public Node() {
        }

        public Node(int val, int key) {
            this.val = val;
            this.key = key;
        }
    }

思路拆解

问题本质与解法选择

题目要求 get / put 都 O(1)，并且缓存满时要淘汰「最久未使用」的 key。要同时满足两个约束：

  • 查找必须 O(1) → 需要哈希表：Map<Integer, Node>（key → 节点）。
  • 维护「最近使用顺序」且删除/移动任意元素 O(1) → 数组删除要 O(n) 移位、单链表删除拿不到前驱，只有双向链表能做到 O(1) 摘除任意节点。

所以标准结构是 HashMap + 双向链表（带哨兵头尾）：哈希管定位，链表管顺序。链表约定：头部 = 最近使用，尾部 = 最久未使用。访问（get 命中或 put 更新已存在 key）→ 摘下来移到头部；插入新 key → 放头部；容量满 → 摘尾部并同步删 map。

关键设计决策

决策理由
节点里存 key淘汰尾部节点时能直接 map.remove(node.key)，否则无从知道删哪个 key
显式维护 size用 size > capacity 判淘汰；一刷用 map.size() 也行，但显式 size 语义更清楚
哨兵 head / tail空表、单节点、插头、删尾全都不写判空分支，统一走 unLinkNode + move2Head
拆出 unLinkNode / move2Head 两个私有方法get 命中与 put 更新共用同一套「摘 + 移头」逻辑，避免复制粘贴
三个结构同步增删put 新 key：建节点 + map.put + size++ + 挂头部；淘汰：摘尾 + map.remove + size--。漏一个就出现「get 不到新 key」或「永不淘汰」

具体 case 推演（capacity = 2）

题目示例序列：put(1,1), put(2,2), get(1), put(3,3), get(2), put(4,4), get(1), get(3), get(4)。逐操作看 map 与链表状态（链表从左到右 = 头部最近 → 尾部最久）：

操作map（key→value）链表顺序（最近→最久）动作 / 淘汰
put(1,1){1:1}1新 key：建节点 1，挂头部
put(2,2){1:1, 2:2}2 → 1新 key：建节点 2，挂头部
get(1)=1{1:1, 2:2}1 → 2命中：摘 1 移到头部（1 变最近）
put(3,3){1:1, 3:3}，2 被逐3 → 1新 key 且 size=2=capacity：先淘汰尾部 2（map.remove(2)、size--），再插 3 头部
get(2)=-1同上3 → 1map 里已无 2 → 返回 -1
put(4,4){1:1, 3:3, 4:4}？→ 淘汰 14 → 3满：淘汰尾部 1（此刻最久是 1，因为 3 刚插入），插 4
get(1)=-1{3:3, 4:4}4 → 31 已被逐 → -1
get(3)=3{3:3, 4:4}3 → 4命中：3 移到头部
get(4)=4{3:3, 4:4}4 → 3命中：4 移到头部

对照代码里 put 的 else 分支：node = new Node(key,value); map.put(key,node); size++; 三件事缺一不可——漏 map.put 则后续 get 新 key 永远 -1；漏 size++ 则 size > capacity 永不成立、淘汰永不触发。get 命中后先 unLinkNode 再 move2Head，顺序不能反：若先 move2Head，node 仍在原位，自链会把自己 next 搞乱。

边界与细节

  • capacity=1：每插一个新 key 都先淘汰唯一旧 key，链表始终只有一个数据节点。
  • 空缓存 get 任意 key → -1（map 查不到直接返回）。
  • put 已存在的 key = 更新 value + 刷新为最近使用（先摘再移头）。
  • 哨兵节点用身份判断（tail.pre / head.next），不比较 value——value 可能任意，哨兵只是占位。
  • get/put 的容器类名是 LRUCache（设计题），提交区只交类实现，main 负责本地模拟调用序列。

复杂度与下限论证

  • 时间：get / put 均 O(1)（哈希平均 O(1) 查找 + 双向链表常数次指针操作）；put 的淘汰也是 O(1)。
  • 空间：O(capacity)，map 与链表节点数都被容量限制。
  • 为什么是最优：题设把 get/put 的复杂度下限钉死在 O(1)，任何用数组/单链表维护顺序的做法删除或移动都要 O(n)，不满足题意；HashMap + 双向链表正是达成该下界的标准结构，不存在更优档。

套路沉淀

LRU 哈希表+双向链表：两结构必须同步增删，哨兵判身份不判值

map 负责 O(1) 定位节点、链表维护使用顺序，两者必须同步：插入新 key 要 map.put(key,node) 并 size++；淘汰时 cut 掉尾节点后，必须用该节点存的 key 做 map.remove 并 size--；get/更新命中时先 cut 再 moveToHead 刷新顺序。哨兵节点用 cur==head || cur==tail 判身份，不要用 value==null 猜。出处：LC0146 lru-cache。
