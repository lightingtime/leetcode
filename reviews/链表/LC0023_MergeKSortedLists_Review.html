与上一轮对比

  • 主线仍是分治两两合并，但 merge 从「每次 new 节点复制值」改成「直接复用原节点改 next」，辅助空间由 O(N) 降到 O(log k)（只剩递归栈），时间仍是 O(N log k)。
  • 复杂度下限论证：结果链 N 个节点每个至少要读一次；用「每次从 k 个链头挑最小」是 O(N·k)，而分治每层总共只走 N 个节点、共 log k 层，所以 O(N log k) 已是比较模型下的下界，空间靠原地串接压到 O(log k)。

这次想起来的路径

  • 看到「k 条有序链表」直接想到相邻两两合并使链表数减半，没有退化成每次从头扫 k 条链取最小（O(N·k)）。
  • 上次沉淀的微调点（不 new 节点、改 next 复用）这次主动用上，说明该点已内化。

与一刷对比：思路与写法都一致（分治递归两两合并 + mergeTowList 子过程），复杂度也相同。时间 O(N log k) 是本题最优档，但空间未达最优：子过程每接一个节点都 new ListNode() 复制值，额外分配 O(N)；一刷笔记里自己也标了这个微调点。

写对的地方：① 分治的递归出口同时管住了「空区间」（start >= lists.length）与「单链」（start == end）；② 每层只把所有节点各走一遍，共 log k 层，所以是 O(N log k) 而不是 O(N·k)；③ 子过程里某条链走空后把另一条整段接上（两个 if 只会命中一个）。

可优化点：① 交错阶段直接接原节点（挂上后指针后移）即可省掉全部分配，额外空间回到 O(log k)（递归栈）；② mergeTowList 拼写应为 mergeTwoList；③ 末尾两个 if 可合并成 p.next = (p1 != null) ? p1 : p2;。

掌握度依据：一次提交 Accepted、全程无探讨 → 较强（写法未达空间最优，按 optimal=false 记录）。

public ListNode mergeKLists(ListNode[] lists) {
        return mergeHelper(lists, 0, lists.length - 1);
    }

    private ListNode mergeHelper(ListNode[] lists, int l, int r) {
        if (l > r) {
            return null;
        }
        if (l == r) {
            return lists[l];
        }
        int mid = l + (r - l) / 2;
        ListNode first = mergeHelper(lists, l, mid);
        ListNode second = mergeHelper(lists, mid + 1, r);
        return merge(first, second);
    }

    private ListNode merge(ListNode l1, ListNode l2) {
        if (l1 == null) {
            return l2;
        }
        if (l2 == null) {
            return l1;
        }
        ListNode dummy = new ListNode();
        ListNode pre = dummy;
        while (l1 != null && l2 != null) {
            if (l1.val < l2.val) {
                pre.next = l1;
                l1 = l1.next;
            } else {
                pre.next = l2;
                l2 = l2.next;
            }
            pre = pre.next;
        }
        pre.next = l1 == null ? l2 : l1;
        return dummy.next;
    }

public ListNode mergeKLists(ListNode[] lists) {
        return mergeKLists(lists, 0, lists.length - 1);
    }

    private ListNode mergeKLists(ListNode[] lists, int start, int end) {
        if (start >= lists.length) {
           return null;
        }
        if (start == end) {
            return lists[start];
        }
        int mid = start + (end - start) / 2;
        ListNode first = mergeKLists(lists, start, mid);
        ListNode second = mergeKLists(lists, mid + 1, end);
        return mergeTowList(first, second);
    }

    private ListNode mergeTowList(ListNode first, ListNode second) {
        if (first == null) {
            return second;
        }
        if (second == null) {
            return first;
        }
        ListNode dummy = new ListNode();
        ListNode p1 = first, p2 = second, p = dummy;
        while (p1 != null && p2 != null) {
            if (p1.val > p2.val) {
                p.next = p2;
                p2 = p2.next;
            } else {
                p.next = p1;
                p1 = p1.next;
            }
            p = p.next;
        }
        p.next = p1 == null ? p2 : p1;
        return dummy.next;
    }

思路拆解

问题本质：K 个有序链表合成一个。逐个两两合并是 O(k·n)；用分治把复杂度降到 O(n log k)。

关键设计：递归对半切分 lists[start..end]，两半各自合并成有序链，再 merge 两个有序链表（复用归并：dummy + 双指针 + 剩余链续接）。每轮把所有链表合并一轮，共 log k 轮。

边界：lists 为空或长度 0 返回 null；单链表直接返回；链表中含 null 元素时 merge 要处理；链表长度参差不齐不影响分治正确性。

复杂度：O(n log k) 时间（n 为总节点数）、O(log k) 递归栈；与优先队列解法同为时间最优，空间更省。
