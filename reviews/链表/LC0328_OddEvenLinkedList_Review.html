328. 奇偶链表 (Odd Even Linked List)

> https://leetcode.cn/problems/odd-even-linked-list/

难度：Medium ｜ 分类：链表

标签：链表

题目描述

给定单链表的头节点 head ，将所有索引为奇数的节点和索引为偶数的节点分别分组，保持它们原有的相对顺序，然后把偶数索引节点分组连接到奇数索引节点分组之后，返回重新排序的链表。

第一个节点的索引被认为是 奇数 ， 第二个节点的索引为 偶数 ，以此类推。

请注意，偶数组和奇数组内部的相对顺序应该与输入时保持一致。

你必须在 O(1) 的额外空间复杂度和 O(n) 的时间复杂度下解决这个问题。

示例 1:

输入: head = [1,2,3,4,5]

输出: [1,3,5,2,4]

示例 2:

输入: head = [2,1,3,5,6,4,7]

输出: [2,3,6,7,1,5,4]

提示:

n == 链表中的节点数

② 为什么想起来

  • 奇偶分组本质 = 两个互不相交的子序列按位交替，天然是「两个指针各走两步」：odd.next = even.next、odd 前移，even.next = odd.next、even 前移，二者互相借用对方的下一跳，不产生覆盖冲突。
  • 三个关键点一次到位：① 先存 evenHead 否则最后没法拼接；② 循环条件 even != null && even.next != null——奇/偶节点数不同时能安全停在正确位置（奇数个时 even 先到 null，odd 已指向末个奇数节点）；③ 结束后 odd.next = evenHead 必须无条件执行。
  • 一刷「拆链成环」的坑这次没出现：跳 next.next 的写法不依赖被拆节点自己的 next 继续遍历，所以不存在「覆盖原 next 导致无法前进」的问题。

LC0328_OddEvenLinkedList.java · 双哨兵拆链：先保存 p.next 再挂载并断开，奇数位/偶数位各成一链，最后拼接提交区
public ListNode oddEvenList(ListNode head) {
        if (head == null) {
            return head;
        }
        ListNode evenHead = new ListNode();
        ListNode eP = evenHead;
        ListNode oddHead = new ListNode();
        ListNode oP = oddHead;
        int size = 1;
        for (ListNode p = head; p != null;) {
            ListNode next = p.next;
            if ((size & 1) == 1) {
                eP.next = p;
                eP = eP.next;
                eP.next = null;
            } else {
                oP.next = p;
                oP = oP.next;
                oP.next = null;
            }
            size++;
            p = next;
        }
        eP.next = oddHead.next;
        return evenHead.next;
    }

    public ListNode oddEvenList(ListNode head) {
        if (head == null) {
            return null;
        }
        ListNode evenHead = head.next;
        ListNode odd = head, even = evenHead;
        while (even != null && even.next != null) {
            odd.next = even.next;
            odd = odd.next;
            even.next = odd.next;
            even = even.next;
        }
        odd.next = evenHead;
        return head;
    }

思路拆解

① 问题本质与解法选择理由

  • 按索引奇偶分组：第 1、3、5… 个节点（奇数位）在前、第 2、4、6… 个（偶数位）在后，各自保持原相对顺序。
  • 题目硬性要求 O(1) 额外空间 + O(n) 时间 → 必须原地改 next；两种原地写法：哨兵拆链法（直观但步骤多）、odd/even 跳两步的原地交替法（更简洁、不易错）。

写法 1（双哨兵拆链）

  • evenHead/oddHead 两个哨兵分别挂奇数位/偶数位节点；size 从 1 计数，(size&1)==1 判奇偶。
  • 关键：先保存 p.next 再挂载，挂载后断开 p.next——挂载会覆盖原链表边，遍历必须沿保存的 next 前进；被拆节点必须断开，否则尾节点残留原 next 会在拼接处成环。
  • 最后 eP.next = oddHead.next 拼接，返回 evenHead.next。
  • 踩坑记录：初版不断开 → 奇数长度链表成环 OOM；断开但没先保存 next → 只处理第一个节点。

写法 2（原地交替，odd/even 各跳 next.next）

  • odd = head、even = head.next，evenHead = head.next 保存偶数段头。
  • while even != null && even.next != null：odd.next = even.next（奇数指针接下一个奇数位）、odd = odd.next；even.next = odd.next（偶数指针接下一个偶数位）、even = even.next。
  • 结束时 odd.next = evenHead 拼接两段，返回 head。
  • 优点：不需要哨兵、不需要 size、不需要断开操作；跳两步不破坏遍历路径，从根上避免成环问题，代码更短。

③ 边界与细节

  • 空链表返回 null；单节点：even = head.next = null，while 不进，odd.next = evenHead = null，返回 head。
  • 两节点：odd.next = evenHead（即 head.next），返回原链表。
  • 奇数长度：odd 停在最后一个奇数位，odd.next = evenHead 收尾。
  • 偶数长度：even 走到 null 退出，odd 停在最后一个奇数位，接 evenHead。
  • 10000 节点上限：单次遍历 O(n)。

④ 复杂度分析与下限论证

  • 两种写法时间均 O(n)（每节点访问/重连一次）、空间均 O(1)（几个指针）。
  • 最优性：每节点必须被重连一次（否则奇偶顺序无法调整），时间 Ω(n) 达到；不新建链表则空间 Ω(1) 达到——O(n)/O(1) 即题目要求下限，两者等价最优；写法 2 在代码简洁性与出错率上更优。

⑤ 具体 case 推演（写法 2）：[1,2,3,4,5]

  • 初始 odd=1、even=2、evenHead=2。
  • 第 1 轮：odd.next=3（1→3）、odd=3；even.next=odd.next=4（2→4）、even=4。
  • 第 2 轮：odd.next=5（3→5）、odd=5；even.next=odd.next=null（4→null）、even=null，退出。
  • 拼接：odd.next=evenHead → 5→2。
  • 结果：1→3→5→2→4，与示例一致 ✅。
  • 对比写法 1 同输入：哨兵拆链得到相同结果，但需 5 次挂载 + 断开 + 1 次拼接，步骤更多。

套路沉淀

链表拆链/重连：先保存 next 再挂载，或跳 next.next 原地重连

原地拆分链表（奇偶、分区等）时不能边遍历边覆盖原 next：挂载节点的 eP.next=p 会破坏原链表前进路径，且被拆节点未断开会成环。方向① 先保存 p.next 再挂载、挂载后断开 p.next；方向② 用 odd/even 指针各走 next.next 跳两步原地重连，最后拼尾。O(n) 时间 O(1) 空间。
