25. K 个一组翻转链表 (Reverse Nodes in k-Group)

> https://leetcode.cn/problems/reverse-nodes-in-k-group/

难度：Hard ｜ 分类：链表

标签：递归、链表

题目描述

给你链表的头节点 head ，每 k 个节点一组进行翻转，请你返回修改后的链表。

k 是一个正整数，它的值小于或等于链表的长度。如果节点总数不是 k 的整数倍，那么请将最后剩余的节点保持原有顺序。

你不能只是单纯的改变节点内部的值，而是需要实际进行节点交换。

示例 1：

输入：head = [1,2,3,4,5], k = 2

输出：[2,1,4,3,5]

示例 2：

输入：head = [1,2,3,4,5], k = 3

输出：[3,2,1,4,5]

提示：

链表中的节点数目为 n

LC0025_ReverseNodesInKGroup.java · 哨兵 + 逐组探尾 + 区间原地反转提交区
public ListNode reverseKGroup(ListNode head, int k) {
        ListNode dummy = new ListNode(-1, head);
        ListNode pre = dummy;
        while (head != null) {
            ListNode tail = pre;
            for (int i = 0; i < k; i++) {
                tail = tail.next;
                if (tail == null) {
                    return dummy.next;
                }
            }
            ListNode next = tail.next;
            ListNode[] list = reverse(head, tail);
            head = list[0];
            tail = list[1];
            pre.next = head;
            tail.next = next;
            pre = tail;
            head = tail.next;
        }
        return dummy.next;
    }

    private ListNode[] reverse(ListNode head, ListNode tail) {
        ListNode pre = tail.next;
        ListNode cur = head;
        // 循环不变量：groupHead 是区间 [head, tail] 之外的第一个节点；tail.next 会被本循环改写，故先快照再作判据
        ListNode groupHead = tail.next;
        while (cur != groupHead) {
            ListNode next = cur.next;
            cur.next = pre;
            pre = cur;
            cur = next;
        }
        // 返回 {翻转后的新头, 新尾}
        return new ListNode[] {tail, head};
    }

思路拆解

① 问题本质与解法选择

  • 本质是链表的局部结构重排：每连续 k 个节点作为一段翻转，段与段之间、段与剩余尾巴之间的相对顺序不变，且只能改指针不能改值。
  • 拆成三件独立的小事即可解：定位每段的头和尾、把段内指针反接、把段接回主链。用 dummy 哨兵消掉「第一段没有前驱」这个特例。
  • 关键选择是先探尾再反转：tail 从 pre 出发走 k 步，走不到就说明本段不足 k 个，此时链表还完好、可以干净返回；若先翻再判断，链表已被改坏，回不去了。

② 关键设计决策

  • 变量语义：dummy 是假头；pre 是上一段翻转后的尾；tail 每轮从 pre 出发走 k 步定位本段尾；next 是本段之外的后继，必须在动指针之前先存，改完就找不回来；reverse 返回 {新头, 新尾}。
  • 终止条件：探尾时 tail 变成 null，说明剩余不足 k 个，直接返回 dummy.next，剩余部分保持原顺序。
  • 循环不变量：reverse 的判据要和「进循环前快照好的区间外第一个节点」比较。tail.next 会被循环体自己改写（cur 走到 tail 时执行 cur.next = pre，把 tail.next 从后继改成前驱），拿它当判据会漂移，循环停不下来并解引用 null 报 NPE。
  • 接回链的四根指针：pre.next = 新头；原 head（即新尾）的 next = next；新头是原 tail；新尾是原 head。

③ 边界与细节

  • n = k = 1：单节点段内循环一次都不执行，返回 {tail, head}。
  • k = 1：每段 1 个等价于不翻转，顺序原样返回。
  • n 不是 k 的整数倍：探尾时 tail 变 null 走 return 分支，剩余节点原样保留。
  • 值取 0 与 1000 这两个端点、以及全相同值：翻转只改指针，值不参与比较，均不受影响。
  • 规模上限 n = 5000、k = 2：逐段推进，总工作量仍是线性。

④ 复杂度与下限论证

  • 时间 O(n)：tail 探尾指针在整条链上总共前进 O(n) 步，反转部分每个节点一次常数操作。
  • 空间 O(1)：只用常数个指针变量，满足进阶级的原地要求。
  • 下限：要改变某节点在链上的位置，至少得读写一次它的 next，所以任何正确算法时间下限就是 O(n)；空间 O(1) 已到顶。

case 推演 [1,2,3,4,5] k=2：

  • 初始 dummy(-1) -> 1 -> 2 -> 3 -> 4 -> 5，pre = dummy
  • 第 1 组：tail 从 dummy 走 2 步到 2，next = 3。reverse(1,2) 内 pre=3、cur=1：1 不等于 3，1.next=3、pre=1、cur=2；2 不等于 3，2.next=1、pre=2、cur=3；3 等于 3 停，返回 {2,1}。接链后 dummy.next=2、1.next=3，pre=1
  • 第 2 组：tail 从 1 走 2 步到 4，next = 5。reverse(3,4) 同理得 4.next=3、3.next=5，返回 {4,3}。接链后 1.next=4，pre=3
  • 第 3 轮：tail 从 3 走 2 步，第 2 步落到 null，返回 dummy.next
  • 结果 dummy -> 2 -> 1 -> 4 -> 3 -> 5，与期望一致

解题过程

01 · 踩坑已记录

区间反转漏掉闭区间右端点：reverse(head, tail) 的循环写成 while (cur != tail)，只重连了前 k-1 个节点，tail 自身（翻转后成为新头）的 next 从未被改写，仍指向原组外后继 → 新头直接跳过整组，组内其余节点与后续链全部脱链；循环结束判据必须覆盖闭区间 [head, tail] 的全部节点，且「区间右边界」与「滚动前驱 pre」不能共用同一变量

02 · 踩坑已记录

把「会被循环体自身改写」的字段当循环判据：reverse 写成 while (cur != tail.next)。tail 这个引用确实不变，但 tail.next 是每轮判据都要重读的字段，而循环体在 cur==tail 那一轮执行 cur.next = pre，把 tail.next 从后继改成了前驱，哨兵当场漂移 → 循环停不下来，还把区间外的节点一并拖进翻转，最后 cur 走到 null 解引用报 NPE。判据只能用「进循环前快照好的不变量」（或 null 这种字面量），不能用会被本次操作改写的活字段

套路沉淀

区间反转：循环判据必须覆盖闭区间两个端点

出处 LC0025 K 个一组翻转链表。反转链表的一段 [head, tail]（tail 是要翻转的最后一个节点）时，循环的结束判据必须是「区间右后继（tail.next 的旧值）」或 null，而不是 tail 本身。写成 while (cur != tail) 的后果：只重连了前 k-1 个节点，tail 自己的 next 从未被改写——而 tail 恰好是翻转后的新头，它仍指向原区间外的后继，于是新头直接跳过整组、组内其余节点与后续链全部脱链（[1,2,3] k=2 输出 2,3 而不是 2,1,3）。另一个坑是「区间右边界」与「滚动前驱 pre」共用同一变量：pre 初值是 tail.next（边界），第一轮后就被覆盖成前驱，无法再当边界用，于是靠提前停在 tail 来兜底——正好漏掉端点。取舍：要么单独留一个不变的 boundary 变量作判据、pre 只当前驱；要么干脆按「k 个节点」计数循环 k 次。自检：走一遍 [1,2] k=2，问新头（原 tail）的 next 最后指向谁。

循环判据必须是循环不变量：别拿会被循环体改写的字段当哨兵

出处 LC0025。LC206 反转整表能写 while (cur != null)，是因为 null 是字面量、永远不会变；但把同样的写法搬到「反转区间 [head, tail]」时写成 while (cur != tail.next)，tail 这个引用不变，tail.next 却在循环体里被自己改：cur==tail 那一轮执行 cur.next = pre，把 tail.next 从『区间外后继』改成『前驱』，哨兵当场漂移。后果有两层——(1) 停不下来，区间外的节点被继续拖进来一起翻转，链结构被破坏；(2) cur 最终走过表尾变成 null，下一轮判据仍为真，解引用 cur.next 直接 NPE（实测 [1,2,3] k=2 报 NullPointerException）。取舍：判据里只能出现「进循环前就快照好、循环期间不会被改写」的值——要么是字面量（null），要么是提前赋给局部变量的一份引用拷贝。自检口诀：把判据表达式里每个字段都问一遍『本轮循环体会不会写它』。
