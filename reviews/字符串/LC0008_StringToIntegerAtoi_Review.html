8. 字符串转换整数 (atoi) (String to Integer (atoi))

> https://leetcode.cn/problems/string-to-integer-atoi/

难度：Medium ｜ 分类：字符串

标签：字符串

题目描述

请你来实现一个 myAtoi(string s) 函数，使其能将字符串转换成一个 32 位有符号整数。

函数 myAtoi(string s) 的算法如下：

空格：读入字符串并丢弃无用的前导空格（" "）

符号：检查下一个字符（假设还未到字符末尾）为 '-' 还是 '+'。如果两者都不存在，则假定结果为正。

转换：通过跳过前置零来读取该整数，直到遇到非数字字符或到达字符串的结尾。如果没有读取数字，则结果为0。

舍入：如果整数数超过 32 位有符号整数范围 [−231, 231 − 1] ，需要截断这个整数，使其保持在这个范围内。具体来说，小于 −231 的整数应该被舍入为 −231 ，大于 231 − 1 的整数应该被舍入为 231 − 1 。

返回整数作为最终结果。

我的解法

写法 1 · long 绝对值累加 + 累加前预判溢出 + 按符号截断

时间 O(n)空间 O(1)内存 ≈ 41.9 MB用例 1096/1096

src/字符串/LC0008_StringToIntegerAtoi.java提交区
public int myAtoi(String s) {
        int ans = 0;
        int sign = 1;
        int m = s.length();
        int i = 0;
        while (i < m && s.charAt(i) == ' ') {
            i++;
        }
        int start = i;
        for (; i < m; i++) {
            char c = s.charAt(i);
            if (i == start && c == '+') {
                sign = 1;
            } else if (i == start && c == '-') {
                sign = -1;
            } else if (Character.isDigit(c)) {
                int num = c - '0';
                if (ans > Integer.MAX_VALUE / 10 || (ans == Integer.MAX_VALUE / 10 && num > Integer.MAX_VALUE % 10)) {
                    return Integer.MAX_VALUE;
                }

                if (ans < Integer.MIN_VALUE / 10 || (ans == Integer.MIN_VALUE / 10 && -num < Integer.MIN_VALUE % 10)) {
                    return Integer.MIN_VALUE;
                }
                ans = ans * 10 + sign * num;
            } else {
                break;
            }
        }
        return ans;
    }

思路拆解

① 问题本质与解法选择

  • 实现 atoi：跳过前导空格 → 可选 +/- → 读数字直到非数字或结尾 → 结果截断到 [-2^31, 2^31-1]。
  • 难点全在溢出处理：-2^31（-2147483648）的绝对值 2147483648 比 int 上限大 1，int 放不下；且累加 temp*10 + digit 本身可能爆 int。
  • 本版选择：用 long 存绝对值（能容纳 2147483648），累加前用 (limit - digit)/10 预判是否超界，最后按符号统一截断。相比「int + 正数 MAX 对称判断」，long 方案天然避开两个坑：绝对值容器够大、正负方向各自独立截断。

② 关键设计决策

  • 解析状态机：hasNegative/hasPositive（符号只允许在数字前出现一次，重复符号或符号后无数字返回 0）、hasNum（数字已读则后续符号视为停止）。
  • 数字分支：limit = hasNegative ? 2147483648L : Integer.MAX_VALUE（按符号取不同上限，负数方向多 1 格）；temp > (limit - digit)/10 为真 → temp = limit; break（预判溢出截断）；否则 temp = temp*10 + digit。
  • 前导零不需要特判：0 走统一数字分支，temp*10 + 0 无影响。
  • 末尾：负数 temp > 2147483648L → MIN，否则 (int)-temp（-2147483648L 转 int 恰好是 MIN_VALUE，不溢出）；正数 temp > MAX → MAX，否则 (int)temp。

③ 边界与细节

  • -2147483648：绝对值恰为 2147483648，temp（long）存得下，末尾 temp > 2147483648L 为假 → 返回 (int)-2147483648L = MIN_VALUE。合法值不被误截。
  • -2147483649：累加到最后一位时预判 temp > (2147483648-9)/10 → 截断 temp=2147483648L → 返回 MIN_VALUE。真溢出截到下限。
  • 2147483648 → 正数 limit 2147483647，预判截断 → MAX_VALUE。
  • 200 位 "1000...0"：每步预判保证 long 不会越界，最终截断到 MAX。
  • "0-1"：读 0（hasNum=true）后遇 - → 符号分支 hasNum 为真 → break → 0。
  • "+-12" / "-+12"：第二个符号在 hasPositive/hasNegative 已真时 break → 0。
  • 纯空格/纯符号/符号后无数字 → hasNum 始终 false，temp=0。

④ 复杂度与最优性

  • 每个字符处理一次，O(n)；只用几个标量变量，O(1) 额外空间。
  • 最优性：必须读取每个字符（其可能改变结果或触发停止），下界 Ω(n)；本解法达到。

解题过程

01 · 踩坑已记录

atoi 溢出检测漏最后一位加法：temp*=10 后 temp+digit 本身溢出没被拦住（2147483640+8=2147483648 爆 int）；应在累加前检查 temp > (上限-digit)/10。且用 temp==MAX 当溢出标志对负数不对称，-2147483647（绝对值恰为 MAX）被误截成 MIN；负数应按 [-2^31,0] 方向判断

02 · 踩坑已记录

atoi 解析把数字中的 '0' 当终止符：hasNum 后遇 '0' 直接 break，'1000' 返回 1；前导零无需特判（累加 0 无影响），'0' 应走统一数字分支，只有非数字字符才停止读取

03 · 踩坑已记录

负数溢出/边界处理：Integer.MAX_VALUE * -1 == -2147483647 不是最小值，负方向截断下限应为 Integer.MIN_VALUE(-2147483648)，两者差 1；且 -2147483648 的绝对值 2147483648 超出 int 无法按正数累加再取负，累加应沿负数方向或改用 long 容器

套路沉淀

atoi/数字累加防溢出：累加前用 (上限-digit)/10 预判

逐字符累加整数时防溢出：每次累加前检查 temp > (上限 - digit)/10 则截断，避免 temp*10+digit 本身爆 int；溢出标志不能只靠 temp==MAX（对负数不对称，-2147483647 绝对值恰为 MAX 会被误截），负数应按 [-2^31,0] 方向判断；前导零无需特判，'0' 走统一数字分支。
