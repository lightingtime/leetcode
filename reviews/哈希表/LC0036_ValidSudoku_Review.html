public boolean isValidSudoku(char[][] board) {
        int[][] rows = new int[9][9];
        int[][] cols = new int[9][9];
        int[][][] sub = new int[3][3][9];
        for (int i = 0; i < 9; i++) {
            for (int j = 0; j < 9; j++) {
                if (board[i][j] != '.') {
                    Integer num = board[i][j] - '0' - 1;
                    rows[i][num]++;
                    cols[j][num]++;
                    sub[i / 3][j / 3][num]++;
                    if (rows[i][num] > 1 || cols[j][num] > 1 || sub[i / 3][j / 3][num] > 1) {
                        return false;
                    }
                }
            }
        }
        return true;
    }

固定 9x9：rows/cols/sub 三个计数数组一次遍历，数字 ++ 后任一 >1 立即 false；O(81)/O(81) 常数规模，一次 Accepted

思路拆解

问题本质：验证 9×9 棋盘的三组约束——数字 1-9 在每行、每列、每个 3×3 宫内都不能重复；只验证已填入的数字，空白 . 跳过，不要求棋盘可解。

解法选择理由（三个计数数组 + 一次遍历）：

  • 棋盘固定 9×9，最直接的做法是分别检查 9 行、9 列、9 宫，但那样要扫三遍；用三个计数数组可以「一次遍历同时登记三组约束」，代码更短、提前返回更快。
  • 每个数字出现一次就同时在「它所在行、所在列、所在宫」三个计数器里 +1，任一计数器到 2 即冲突。
  • 因为是固定 9×9，时间空间都是常数（81 个格子），不存在更低的复杂度——已是最优。

关键设计决策：

  1. 三个计数器：rows[9][9]（行 → 数字）、cols[9][9]（列 → 数字）、sub[3][3][9]（宫 → 数字）。
  2. 数字转下标：board[i][j] - 0 - 1，把 1-9 映射到 0-8，正好当数组下标。
  3. 宫定位：i/3、j/3 得到 0-2 的宫坐标，sub[i/3][j/3][num] 即该数字在哪个宫的出现次数。
  4. 每个非 . 格子：三个计数器同步 ++，然后立刻检查是否 >1，是则 return false（提前结束，不必扫完）。
  5. . 直接跳过，不参与任何计数。

具体 case 推演：

边界8（左上宫两个 1，期望 false）：棋盘 (0,0)=1、(1,2)=1，其余 .。

格子行计数列计数宫计数结果
(0,0)=1 → 下标0rows[0][0]=1cols[0][0]=1sub[0][0][0]=1继续
(1,2)=1 → 下标0rows[1][0]=1cols[2][0]=1sub[0][0][0]=2>1 → false ✓

两个 1 不同行（0 vs 1）、不同列（0 vs 2），只有宫计数器暴露冲突——这正是「三个计数器缺一不可」的原因。

示例2（左上宫两个 8，期望 false）：(0,0)=8 → sub[0][0][7]=1；(2,2)=8 → sub[0][0][7]=2 → false ✓

边界2（第 0 行两个 1，期望 false）：(0,0)=1 → rows[0][0]=1；(0,8)=1 → rows[0][0]=2 → false ✓

边界1（全空白）：所有格子都是 .，全部跳过，循环结束 return true ✓

边界与细节：

  • . 不计数：只有非 . 才走三个 ++。
  • 数字 1-9 下标化 0-8，不会越界（board 保证是数字或 .）。
  • 固定 9×9：i/3、j/3 恒在 0-2，sub 数组大小正好。
  • 多处冲突时第一个触发点即返回，结果与题目要求一致（只要有一个冲突就无效）。

复杂度分析：

  • 时间 O(81) = O(1)：每个格子常数操作；固定棋盘下这是下限（至少看每个格子一次）。
  • 空间 O(81) = O(1)：三个计数数组总大小 81 + 81 + 81，固定常数。
  • 最优性：固定 9×9 使任何 O(81) 解法都达到下限；三个计数器写法是其中最简单直接的一种。
  • 可微调点：第 24 行 Integer num 装箱可改 int num，减少无谓装箱。
