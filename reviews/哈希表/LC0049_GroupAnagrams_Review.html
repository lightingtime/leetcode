我的解法

思路：计数编码键。统计每个字符串 26 个字母的出现次数，把「字母 + 次数」编码成一个字符串作为分组键； 两个字符串互为字母异位词 ⟺ 它们的计数完全相同 ⟺ 键相同，于是放进同一个 HashMap 桶里。

时间 O(n·L) 空间 O(n·L) L = 字符串平均长度 键包含完整计数

src/LC0049_GroupAnagrams.java提交区（修复后）
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();
    for (String str : strs) {
        String pre = cal(str);
        if (map.containsKey(pre)) {
            map.get(pre).add(str);
        } else {
            List<String> list = new ArrayList<>();
            list.add(str);
            map.put(pre, list);
        }
    }
    return map.values().stream().toList();
}

private String cal(String str) {
    int[] counts = new int[26];
    for (Character c : str.toCharArray()) {
        counts[c - 'a']++;
    }
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < 26; i++) {
        if (counts[i] > 0) {
            sb.append(i + 'a');
            sb.append(counts[i]);
        }
    }
    return sb.toString();
}

键形如「ASCII码+次数」拼接，如 a×1 → 971、aa → 972，能区分不同次数组合。

算法判定：计数编码键，已是最优

  • 时间复杂度 O(n·L)：每个字符至少要读一次，O(n·L) 是本题下限；计数是 O(L)，键拼接是常数 26，都在下界内。
  • 空间复杂度 O(n·L)：分组结果本身就要存下全部字符串，这是必须的开销。
  • 键的正确性：键编码了「每个字母 + 出现次数」，不同次数组合（如 a 与 aa）必然得到不同键，不再误分组。
  • 结论：与题目标准解法一致，无需再优化。

分类提醒 · 哈希表

看到需要 O(n²) 的查找/去重，先想用哈希表把查找降到 O(1)。

本题的关键是「为异位词设计共享键」：键必须编码完整信息——只编码字母集合不够，还要带上每个字母的出现次数； 这类「分组 / 去重 / 计数」题，设计键时先问自己：信息够不够区分两个本应不同的对象。
