217. 存在重复元素 (Contains Duplicate)

难度：Easy ｜ 分类：哈希表

标签：数组、哈希表、排序

题目描述

给你一个整数数组 nums 。如果任一值在数组中出现 至少两次 ，返回 true ；如果数组中每个元素互不相同，返回 false 。

示例 1：

输入：nums = [1,2,3,1]

输出：true

解释：

元素 1 在下标 0 和 3 出现。

示例 2：

输入：nums = [1,2,3,4]

输出：false

解释：

所有元素都不同。

示例 3：

输入：nums = [1,1,1,3,3,4,3,2,4,2]

输出：true

提示：

1 5

-109 9

写法 1 · 单遍哈希表

public boolean containsDuplicate(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int num : nums) {
            if (!set.add(num)) {
                return true;
            }
        }
        return false;
    }

HashSet 单遍扫描：先查后加，遇重复提前返回；O(n)/O(n)，一次 Accepted

思路拆解

问题本质：判断数组中是否存在「任一值出现至少两次」。等价于在线判重：扫描时有没有一个数在它之前已经出现过。不需要计数、不需要下标，只需要记录「已经见过哪些值」。

解法选择理由：

  • 朴素两两比较是 O(n²)，n 最大 10^5 时最坏约 10^10 次比较，不可接受。
  • 哈希表（HashSet）把「某个值之前是否出现过」的查询降到平均 O(1)：每遍历一个数，查一次、必要时插一次，整体 O(n)。
  • 只需要「出现过/没出现过」这个布尔信息，所以用 Set 而不是 Map（Map 的计数/下标在这里是多余信息）。

关键设计决策：

  1. 用 HashSet<Integer> 存已扫描过的值。
  2. 对每个数：先查 set.contains(num)，已存在 → 直接 return true（提前结束，不必扫完）。
  3. 不存在 → set.add(num)，继续。
  4. 循环正常结束 → 所有数互不相同，return false。

具体 case 推演：

nums = [1, 2, 1]（期望 true）：

步骤numset 当前内容contains(num)?动作结果
11{}falseadd 1 → {1}继续
22{1}falseadd 2 → {1,2}继续
31{1,2}true直接返回true ✓

nums = [1, 2, 3]（期望 false）：

步骤numset 当前内容contains(num)?动作结果
11{}falseadd 1继续
22{1}falseadd 2继续
33{1,2}falseadd 3继续
循环结束-{1,2,3}--false ✓

nums = [7]：只有一步，add 7 后循环结束 → false ✓（覆盖 n 下限）。

边界与细节：

  • n=1：只会 add 一次，返回 false。
  • 重复出现在任意位置：第二次遇到就提前返回 true，不必等扫完。
  • 元素范围 -10^9..10^9：int 完全容纳，无溢出/比较陷阱。
  • n=10^5：O(n) 空间可接受。
  • 约束 n>=1 无空数组，不需要特判空输入。

复杂度分析：

  • 时间 O(n)：每个元素一次 contains + 一次 add，平均 O(1)。
  • 空间 O(n)：最坏全部互异时 set 存 n 个元素。
  • 下限论证：判重至少要读每个元素一次（Ω(n)），O(n) 时间已达下限；哈希表是时间最优。若限制 O(1) 空间则需先排序 O(n log n) 再相邻比较，属于时间换空间，不是更优。
