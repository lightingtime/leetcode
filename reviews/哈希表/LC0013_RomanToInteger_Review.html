public int romanToInt(String s) {
        Map<Character, Integer> symbolValues = new HashMap<>();
        symbolValues.put('I', 1);
        symbolValues.put('V', 5);
        symbolValues.put('X', 10);
        symbolValues.put('L', 50);
        symbolValues.put('C', 100);
        symbolValues.put('D', 500);
        symbolValues.put('M', 1000);
        int n = s.length();
        int ans = 0;
        for (int i = 0; i < n; i++) {
            if (i < n - 1 && symbolValues.get(s.charAt(i)) < symbolValues.get(s.charAt(i + 1))) {
                ans -= symbolValues.get(s.charAt(i));
            } else {
                ans += symbolValues.get(s.charAt(i));
            }
        }
        return ans;
    }

哈希表符号映射 + 相邻比较：当前值<右边值则减否则加，一次扫描处理 6 种减法特例；O(n)/O(1)，一次 Accepted

思路拆解

问题本质：把罗马数字按规则转成整数。常规是「左大右小」直接累加，六种减法特例（IV/IX/XL/XC/CD/CM）是「左小右大」时用右边减左边。

解法选择理由（哈希表 + 一次扫描）：

  • 用哈希表把 7 个符号映射成数值，省去 if-else 链。
  • 核心观察：遍历时当前符号的值 < 右边符号的值，说明当前是减法特例的「小数字」，应减去当前值；否则加上当前值。一次扫描即可，不需要特判表。
  • 正确性来自罗马数字合法输入：减法只可能是 I/X/C 放在 V/X、L/C、D/M 左边，而「当前 < 右边」恰好覆盖全部 6 种情况。

关键设计：

  1. values 映射 7 个符号。
  2. for i in 0..n-1：若 i < n-1 且 values(s[i]) < values(s[i+1]) → ans -= values(s[i])；否则 ans += values(s[i])。
  3. 最后一个字符没有右边，必然走加法分支（合法输入中它不可能小于不存在的右边）。

具体 case 推演（s = "MCMXCIV"，期望 1994）：

i字符与右边比较动作ans
0M(1000)1000 > 100+10001000
1C(100)100 < 1000-100900
2M(1000)1000 > 10+10001900
3X(10)10 < 100-101890
4C(100)100 > 1+1001990
5I(1)1 < 5-11989
6V(5)末尾+51994

再推演 s = "IV"：i=0，I(1) < V(5) → -1；i=1，V 末尾 → +5；结果 4 ✓。

边界与细节：

  • 单字符：I/V/X/L/C/D/M 各返回自身值。
  • 6 种减法特例单独输入：IV=4、IX=9、XL=40、XC=90、CD=400、CM=900。
  • 最小值 "I"=1、最大值 "MMMCMXCIX"=3999。
  • 连续相同符号（XX/CCC）逐位累加。
  • 全部用例在题目约束 1..3999 内。

复杂度分析：

  • 时间 O(n)：一次遍历，每次查表 O(1)。
  • 空间 O(1)：固定 7 个映射。
  • 已是最优：每个字符至少要读一次。
