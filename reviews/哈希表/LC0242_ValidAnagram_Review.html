public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) {
            return false;
        }
        Map<Character, Integer> map = new HashMap<>();
        for (int i = 0; i < s.length(); i++) {
            map.merge(s.charAt(i), 1, Integer::sum);
            map.merge(t.charAt(i), -1, Integer::sum);
        }
        for (Map.Entry<Character, Integer> entry : map.entrySet()) {
            if (entry.getValue() != 0) {
                return false;
            }
        }
        return true;
    }

HashMap 双向计数：s 每个字符 +1、t 每个字符 -1，最后 value 全 0 即异位词；长度不等先剪枝；O(n)/O(k)（k≤26），一次 Accepted

思路拆解

问题本质：判断 t 是否是 s 的字母异位词，即两个字符串的「字符多重集」是否相等——每个字符在 s 和 t 中出现次数必须完全一致，顺序无关。

解法选择理由：

  • 排序后逐位比较是 O(n log n)，能解但不是最优。
  • 哈希表计数把「两个串字符次数是否相同」化成「同一个计数器上 +1 / -1 能否互相抵消」：s 贡献 +1、t 贡献 -1，全部抵消说明次数相同。每步平均 O(1)，整体 O(n)。
  • 用户的思路用单个 map 双向计数，比「两个 map 分别统计再比较」少一半空间与一次遍历。

关键设计决策：

  1. 长度不等直接 return false：异位词的必要条件是长度相同，先剪枝省事。
  2. 单 map 双向计数：一个循环里同时对 s 的字符 merge +1、对 t 的字符 merge -1，利用 map.merge 处理「键不存在时按 0 起步」。
  3. 最后遍历 map 的 values()，只要有非 0 就 false；全部为 0 才 true。
  4. 可选的提前返回：减到负数时 t 中该字符已比 s 多，可立即 false（用户没做，不影响正确性，只是少遍历）。

具体 case 推演：

s = "aab", t = "aba"（期望 true，长度 3 相等）：

步骤 is.charAt(i)动作t.charAt(i)动作map
0a+1a-1{a:0}
1a+1b-1{a:1, b:-1}
2b+1a-1{a:0, b:0}

最终 values 全 0 → true ✓

s = "rat", t = "car"（期望 false）：

步骤 is 字符/动作t 字符/动作map
0r +1c -1{r:1, c:-1}
1a +1a -1{r:1, c:-1, a:0}
2t +1r -1{r:0, c:-1, a:0, t:1}

最终 c=-1、t=1 非 0 → false ✓

s = "aaab", t = "aab"（期望 false）：长度 4 != 3，直接 false ✓

边界与细节：

  • 单字符：相同返回 true，不同 map 非 0 返回 false。
  • 长度不同：即使字符集合相同（如 "ab" vs "a"）也先剪枝。
  • 次数不同：a 多一个时 map 中 a 的计数非 0，不会被「只比字符集合」的写法误判。
  • 5*10^4 上限：merge 平均 O(1)，无性能问题。
  • 进阶 Unicode：Java 的 char 是 UTF-16 code unit，补充平面字符（如 emoji）会拆成代理对；真要支持 Unicode 应按码点（codePoints）计数。本题约束仅小写字母，char 计数正确。

复杂度分析：

  • 时间 O(n)：n = s.length + t.length，每个字符一次 merge（平均 O(1)），最后遍历 map 一次。
  • 空间 O(k)：k 为出现的不同字符数；本题仅小写字母，k ≤ 26，可视为 O(1)。
  • 下限论证：判异位词至少要读完两个串的每个字符（Ω(n)），O(n) 已达时间下限；字符集固定时空间也是常数。唯一可精简的是用 int[26] 数组代替 HashMap（省去装箱与哈希开销），属于实现层面的小优化，不是复杂度提升。
