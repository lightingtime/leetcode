    public List<List<Integer>> subsets(int[] nums) {
        ans = new ArrayList<>();
        dfs(nums, 0, new ArrayList<>());
        return ans;
    }

    private void dfs(int[] nums, int index, List<Integer> list) {
        if (index >= nums.length) {
            ans.add(new ArrayList<>(list));
            return;
        }

            list.add(nums[index]);
            dfs(nums, index + 1, list);

            list.remove(list.size() - 1);
            dfs(nums, index + 1, list);
    }

List<List<Integer>> ans;
    public List<List<Integer>> subsets(int[] nums) {
        ans = new ArrayList<>();
        dfs(nums, 0, new ArrayList<>());
        return ans;
    }

    private void dfs(int[] nums, int start, List<Integer> list) {
        ans.add(new ArrayList<>(list));
        for (int i = start; i < nums.length; i++) {
            list.add(nums[i]);
            dfs(nums, i + 1, list);
            list.remove(list.size() - 1);
        }
    }

回溯起点推进框架，每个节点都是唯一子集

思路拆解

问题本质：n 个互异元素的所有子集共 2^n 个，每个元素只有「选/不选」两个决定。枚举全部子集，回溯/DFS 是天然选择。本题有两种等价写法，一次只选一种框架。

写法 1 · 选/不选（已提交）：

  • 递归参数 index 表示下一个待决策的元素；每层两个分支：加入 nums[index] 递归 index+1，或不加入直接递归 index+1；
  • 答案只在叶子收集：index == nums.length 时所有元素决策完毕，把 list 副本加入答案；
  • 必须显式终止，否则 index 越界访问；空集由根节点一路「不选」产生。

写法 2 · 起点推进（已提交）：

  • 递归参数 start 表示下一个可选的起点；for 循环枚举「下一个加入子集的元素」，选 nums[i] 后递归 i+1 并撤销；
  • 「不选」由循环 i++ 隐含表达，不需要第二个递归分支；
  • 答案在每个节点入口收集：该框架下每个节点形成的列表互不相同，不会重复；循环自然结束，无需显式终止。

两种写法对比：

  • 复杂度相同：时间 O(n·2^n)（2^n 个子集，每个复制 O(n)），空间 O(n)（递归栈 + 当前列表，不含输出）；
  • 差别只在「答案收集时机」：选/不选框架内部节点会与叶子重复，只能叶子加；起点推进框架每个节点唯一，入口加即可；
  • 都无需排序（元素互异）；含重复元素时两种框架都要排序 + 跳过相邻相同值。

为什么是最优：输出规模本身就是 2^n 个最多 n 长的子集，任何算法都必须生成 O(n·2^n) 的数据；两种写法每个子集恰好生成一次、无重复枚举，已达下限。

补充：写法 2 的「不选」到底在哪里（具体 case 推演）——

  • 起点推进的循环不是在问「要不要选 nums[i]」，而是在决定「下一个加入子集的元素是哪个」；
  • 具体 case：nums=[1,2,3]，dfs(0, []) 的三条分支：i=0 选 1 → 生成包含 1 的全部子集；i=1 选 2 → list 从未加入过 1，「循环从 0 推进到 1」这个动作本身就是不选 1；i=2 选 3 → 同时跳过 1 和 2，即不选 1、不选 2；
  • 结论：选/不选框架把「不选」写成显式分支；起点推进框架把「不选」编码在循环推进里——i 每前进一位就放弃前面那位；若在循环里再写显式「不选」递归，等于把同一动作做两遍（写法 1 调试时的重复问题）。

套路沉淀

回溯枚举子集：两种框架不可混用，递归起点必须前进

子集/组合类枚举有两种等价回溯框架，只能选一种：

  • 框架 A（每个下标选/不选）：递归参数传下一个下标，分支是「加入」与「不加入」，不需要 for 循环；
  • 框架 B（起点推进）：for i 从 start 起，只走「加入」分支并递归 (i+1)，「不加入」由循环自然推进，循环体内只有一个递归调用；
  • 共性：下一层起点必须基于当前选择前进（i+1），传旧 index 会让同一元素重复入选、子集重复、递归树超过 2^n 爆炸；
  • 每次进入递归就把当前列表副本加入答案，空集由根节点自然产生。

补充：不选的位置——起点推进里 i 从 start 推进到 start+1 就是放弃 start：nums=[1,2,3] 时 i=1 分支的 list 从未包含 1，跳过 1 的动作就是循环推进本身；禁止用「隐含」带过，必须给这样的 case。

递归枚举必须显式终止：决策下标越界即返回，不能访问越界元素

出处：LC0078 子集

选/不选框架没有 for 循环，终止条件必须显式：

  • 递归参数是下一个待决策下标，当 index == 数组长度时，没有元素可决策，先返回；
  • 子集题每个节点都是答案，越界前那层加入即可，但访问 nums[index] 前必须保证在界内；
  • 从「起点推进」改成「选/不选」时，for 循环隐式的越界保护会消失，必须补上显式 base case，否则 AIOOBE。

要点：换框架时检查边界出口是否仍然存在；递归访问数组下标前，先保证下标在界内。

答案收集时机绑定框架：选/不选只在叶子加答案，起点推进每节点加

出处：LC0078 子集

答案收集时机绑定回溯框架：

  • 起点推进框架：每个节点形成的列表互不相同，进入 dfs 即可加答案；
  • 选/不选框架：每个子集唯一对应一棵「叶子」，内部节点的列表与某个叶子重复，只能在叶子（所有元素决策完）加答案；
  • 判断标准：同一个列表是否会被多条路径重复到达。

要点：换框架后，除了递归参数和终止条件，答案收集时机也要一起检查。
