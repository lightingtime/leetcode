List<List<Integer>> ans;
    public List<List<Integer>> subsets(int[] nums) {
        ans = new ArrayList<>();
        dfs(nums, 0, new ArrayList<>());
        return ans;
    }

    private void dfs(int[] nums, int index, List<Integer> list) {
        if (index >= nums.length) {
            ans.add(new ArrayList<>(list));
            return;
        }

            list.add(nums[index]);
            dfs(nums, index + 1, list);

            list.remove(list.size() - 1);
            dfs(nums, index + 1, list);
    }

回溯选/不选框架，答案只在叶子收集

思路拆解

问题本质：n 个互异元素的所有子集共 2^n 个，每个元素只有「选/不选」两个决定。枚举全部子集，回溯/DFS 是天然选择。

为什么用选/不选框架：

- 子集与排列不同，没有顺序概念，不需要 used 去重；每个元素只有「加入」与「不加入」两个分支；

- 递归参数 index 表示「下一个待决策的元素」，从 0 走到 n，决策完所有元素时当前列表就是一个完整子集。

关键设计：

1. 递归状态：当前已决定的列表 list + 下一个待决策下标 index；

2. 终止条件：index == nums.length 时所有元素决策完毕，把 list 的副本加入答案（必须 new 副本，否则后续撤销会改坏已存结果）；

3. 两个分支对称：加入 nums[index] → 递归 index+1 → 撤销移除；不加入 → 直接递归 index+1；

4. 空集自动产生：根节点一路「不选」走到叶子即 []。

边界与细节：

- n=1 只有 [[], [0]]；n=10 共 1024 个子集，测试已覆盖；

- 元素互异，不需要排序或去重；含重复元素（子集 II）才需要排序 + 跳过相邻相同值；

- 框架一致性是本题的最大坑：选/不选框架里答案只能在叶子加，在入口加会把同一子集重复记录；递归必须显式终止，否则越界访问。

复杂度分析：

- 时间 O(n·2^n)：2^n 个子集，每个复制 O(n)；

- 空间 O(n)：递归栈 + 当前列表（不含输出；计入输出为 O(n·2^n)）。

为什么是最优：输出规模本身就是 2^n 个最多 n 长的子集，任何算法都必须生成 O(n·2^n) 的数据；回溯每个子集恰好生成一次、无重复枚举，O(n·2^n) / O(n) 已达下限。

套路沉淀

回溯枚举子集：两种框架不可混用，递归起点必须前进

子集/组合类枚举有两种等价回溯框架，只能选一种：
- 框架 A（每个下标选/不选）：递归参数传下一个下标，分支是「加入」与「不加入」，不需要 for 循环；
- 框架 B（起点推进）：for i 从 start 起，只走「加入」分支并递归 (i+1)，「不加入」由循环自然推进，循环体内只有一个递归调用；
- 共性：下一层起点必须基于当前选择前进（i+1），传旧 index 会让同一元素重复入选、子集重复、递归树超过 2^n 爆炸；
- 每次进入递归就把当前列表副本加入答案，空集由根节点自然产生。

递归枚举必须显式终止：决策下标越界即返回，不能访问越界元素

出处：LC0078 子集
选/不选框架没有 for 循环，终止条件必须显式：
- 递归参数是下一个待决策下标，当 index == 数组长度时，没有元素可决策，先返回；
- 子集题每个节点都是答案，越界前那层加入即可，但访问 nums[index] 前必须保证在界内；
- 从「起点推进」改成「选/不选」时，for 循环隐式的越界保护会消失，必须补上显式 base case，否则 AIOOBE。
要点：换框架时检查边界出口是否仍然存在；递归访问数组下标前，先保证下标在界内。

答案收集时机绑定框架：选/不选只在叶子加答案，起点推进每节点加

出处：LC0078 子集
答案收集时机绑定回溯框架：
- 起点推进框架：每个节点形成的列表互不相同，进入 dfs 即可加答案；
- 选/不选框架：每个子集唯一对应一棵「叶子」，内部节点的列表与某个叶子重复，只能在叶子（所有元素决策完）加答案；
- 判断标准：同一个列表是否会被多条路径重复到达。
要点：换框架后，除了递归参数和终止条件，答案收集时机也要一起检查。
