写法 1 · 环形贪心（变负即排除，起点=前缀和最低点之后）

时间 O(n)空间 O(1)内存 ≈ 114.2 MB用例 40/40

src/贪心与区间/LC0134_GasStation.java提交区
public int canCompleteCircuit(int[] gas, int[] cost) {
        int total = 0;
        int start = 0;
        int cur = 0;
        for (int i = 0; i < gas.length; i++) {
            total += gas[i] - cost[i];
            cur += gas[i] - cost[i];
            if (cur < 0) {
                start = i + 1;
                cur = 0;
            }
        }
        return total < 0 ? -1 : start;
    }

两个变量分工：total 全程累加只判有无解，cur 是候选段油箱负时清零换起点

思路拆解

问题本质与解法选择理由

目标是找唯一的可行起点；最直观是每个起点模拟一整圈，O(n²)，但 n≤10^5 会超时，必须降到 O(n)。

两个结构性质支撑贪心：

  • 若 total = Σ(gas) - Σ(cost) < 0，绕一圈净消耗为正，任何起点都无解；
  • 题目保证解存在时唯一，所以「排除法」只要排除掉不可行的起点，剩下的就是答案。

关键设计决策：两个变量分工

变量语义重置时机
total全程净油 Σ(gas[i]-cost[i])，回答「整体有没有解」从不重置
cur当前候选段 start..i 的累积油箱，回答「这段起点能不能撑下去」cur < 0 时清零
  • 变负即排除：cur 走到 i 变负，说明从 start 出发到 i 就油尽；此时 [start..i] 内任何一站作为起点，到 i 时的油箱都 ≤ 从 start 出发的值（前面那段要么净亏、要么净赚但已经被 cur<0 覆盖），所以必然也 <0——整段全部排除，start = i+1 安全。
  • 起点选在前缀和最低点之后：total ≥ 0 保证最终 start 之后的累计恒 ≥0；绕回 start 之前那段时，靠全程盈余补足，不需要再走一遍验证。

边界与细节

  • n=1：油够则 cur 恒 ≥0，start=0 返回 0；油不够则 total<0 返回 -1，两条路径都正确。
  • total=0（总油=总耗）同样有唯一解：gas=[2,1,1]/cost=[1,1,2] → 答案 0。
  • i+1 可能在最后一站越出数组：此时 total 必 <0（否则最后一段不会净亏到清零），会返回 -1，start 不会被读到，无越界风险。

具体 case 逐层推演

gas=[0,5,0]，cost=[1,1,1]，diff=[-1,4,-1]，total 总和 2，答案应为 1：

  • i=0：cur=-1，total=-1 → cur<0，start=1，cur=0（站 0 被排除）
  • i=1：cur=4，total=3
  • i=2：cur=3，total=2
  • 循环结束 total=2≥0 → 返回 start=1。从 1 出发 cur 恒非负，绕回站 0 时盈余 3 足够。

gas=[2,1,1]，cost=[1,1,2]，diff=[1,0,-1]，total 总和 0，答案应为 0：

  • i=0：cur=1，total=1
  • i=1：cur=1，total=1
  • i=2：cur=0，total=0
  • cur 从未变负，start 保持 0，返回 0。

gas=[2,3,4]，cost=[3,4,3]，diff=[-1,-1,1]，total 总和 -1，答案应为 -1：

  • i=0：cur=-1，total=-1 → start=1，cur=0
  • i=1：cur=-1，total=-2 → start=2，cur=0
  • i=2：cur=1，total=-1
  • total=-1<0 → 返回 -1。

复杂度与下限论证

  • 时间 O(n)：单趟遍历，每站只做 O(1) 加法和比较。每个元素至少要访问一次才能算出净油，所以 Ω(n)，O(n) 即下限。
  • 空间 O(1)：只用了 total、cur、start 三个整型，无任何随输入增长的存储，已是最低。
