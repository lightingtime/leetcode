public String largestNumber(int[] nums) {
        String[] array = Arrays.stream(nums).mapToObj(String::valueOf).toArray(String[]::new);
        Arrays.sort(array, (a, b) -> (b + a).compareTo(a + b));
        StringBuilder sb = new StringBuilder();
        if (array[0].equals("0")) {
            return "0";
        }
        for (String s : array) {
            sb.append(s);
        }
        return sb.toString();
    }

比较器按拼接结果而非数值排序，(b+a).compareTo(a+b)；全零输出单个 0

思路拆解

问题本质与解法选择理由

目标是把 n 个数重排成字典序下最大的拼接串。若按数值从大到小排序（如 [9, 30] 会排成 [30, 9] 拼出 309，但 930 才更大），所以比较两数谁在前，依据不是数值大小，而是两种拼接串的字典序大小：a 应在 b 前 ⟺ a+b > b+a。这决定序关系是否自洽：若 a+b > b+a 且 b+c > c+b，可证 a+c > c+a（传递性成立），因此可直接用于排序。

关键设计决策

决策写法理由
转字符串数组Arrays.stream(nums).mapToObj(String::valueOf)拼接比较必须在字符串上进行，数值会溢出
自定义比较器(b + a).compareTo(a + b)b+a > a+b 时返回正数，b 排前，保证拼出最大串
全零去重追加时若 s=="0" 且当前结果已是 "0" 则跳过[0,0] 应输出 "0" 而非 "00"

边界与细节

  • 全零输入：[0,0,0] → 只保留一个 "0"。注意去重条件看的是「结果串恰好是单个 0」而非「元素是 0」，这样 [1,0,0] 拼出 "100" 不会误去重。
  • 前缀相同长度不同：[30,3]，比较 "303" vs "330"，"330" 更大 → 3 排 30 前，输出 "330" 而非 "303"。
  • 循环前缀陷阱：[121,12]，逐位比较会以为相等，但 "12121"（12+121）vs "12112"（121+12），前者更大 → 12 排前，输出 "12121"。只有拼接比较能区分这种 case。
  • 重复相等元素：[9,9]，比较器返回 0，任意顺序都拼出 "99"，无影响。

具体 case 逐层推演

nums=[3,30,34,5,9]，期望 "9534330"：

两两拼接比较得到顺序：

  • 9 vs 5："95" > "59" → 9 在 5 前
  • 5 vs 34："534" vs "345" → 5 在 34 前
  • 34 vs 3："343" vs "334" → 34 在 3 前
  • 3 vs 30："330" vs "303" → 3 在 30 前

排序后数组：["9","5","34","3","30"]，拼接 = "9534330" ✓

nums=[0,0,0]：

  • 排序后全 0，第一个追加成 "0"，后两个因 sb 已是 "0" 被跳过 → 返回 "0" ✓

nums=[121,12]：

  • "12121" vs "12112" → 12 在前，拼接 "12121" ✓

复杂度与下限论证

  • 时间 O(n·k·log n)：排序 n 个元素，每次比较构造两个长度 ≤2k 的串（k 为最大数字位数，本题 k≤10），字典序比较 O(k)；排序为 O(n·k·log n)。要决定全序必然经过排序，此复杂度为这类问题的标准最优。
  • 空间 O(n)：存 n 个字符串副本 + 结果串，无法低于 O(n)（输出本身就要存所有位）。
