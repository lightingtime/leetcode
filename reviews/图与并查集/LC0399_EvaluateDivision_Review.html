399. 除法求值 (Evaluate Division)

> https://leetcode.cn/problems/evaluate-division/

难度：Medium ｜ 分类：图与并查集

标签：深度优先搜索、广度优先搜索、并查集、图、数组、字符串、最短路、Floyd 算法、Bellman–Ford 算法

题目描述

给你一个变量对数组 equations 和一个实数值数组 values 作为已知条件，其中 equations[i] = [Ai, Bi] 和 values[i] 共同表示等式 Ai / Bi = values[i] 。每个 Ai 或 Bi 是一个表示单个变量的字符串。

另有一些以数组 queries 表示的问题，其中 queries[j] = [Cj, Dj] 表示第 j 个问题，请你根据已知条件找出 Cj / Dj = ? 的结果作为答案。

返回 所有问题的答案 。如果存在某个无法确定的答案，则用 -1.0 替代这个答案。如果问题中出现了给定的已知条件中没有出现的字符串，也需要用 -1.0 替代这个答案。

注意：输入总是有效的。你可以假设除法运算中不会出现除数为 0 的情况，且不存在任何矛盾的结果。

注意：未在等式列表中出现的变量是未定义的，因此无法确定它们的答案。

示例 1：

输入：equations = [["a","b"],["b","c"]], values = [2.0,3.0], queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]

输出：[6.00000,0.50000,-1.00000,1.00000,-1.00000]

解释：

条件：a / b = 2.0, b / c = 3.0

问题：a / c = ?, b / a = ?, a / e = ?, a / a = ?, x / x = ?

结果：[6.0, 0.5, -1.0, 1.0, -1.0 ]

注意：x 是未定义的 => -1.0

示例 2：

输出：[3.75000,0.40000,5.00000,0.20000]

示例 3：

写法 1 · 带权图 DFS

时间 O(Q·(V+E))空间 O(V+E)内存 ≈ 45.3 MB用例 29/29

src/图与并查集/LC0399_EvaluateDivision.java提交区
public double[] calcEquation(List<List<String>> equations, double[] values, List<List<String>> queries) {
        Map<String, Map<String, Double>> graph = new HashMap<>();
        for (int i = 0; i < equations.size(); i++) {
            String a = equations.get(i).get(0);
            String b = equations.get(i).get(1);
            double value = values[i];

            graph.computeIfAbsent(a, k -> new HashMap<>()).merge(b, value, (oldVal, newVal) -> newVal);
            graph.computeIfAbsent(b, k -> new HashMap<>()).merge(a, 1 / value, (oldVal, newVal) -> newVal);
        }
        double[] ans = new double[queries.size()];
        int index = 0;
        for (List<String> query : queries) {
            String a = query.get(0);
            String b = query.get(1);
            if (graph.containsKey(a)) {
                if (a.equals(b)) {
                    ans[index] = 1.0;
                } else {
                    ans[index] = findAns(a, b, 1.0, graph, new HashSet<String>());
                }
            } else {
                ans[index] = -1.0;
            }
            index++;
        }
        return ans;
    }

    private double findAns(String a, String b, double cur, Map<String, Map<String, Double>> graph, HashSet<String> visited) {
        if (a.equals(b)) {
            return cur;
        }
        visited.add(a);
        for (Map.Entry<String, Double> entry : graph.get(a).entrySet()) {
            String next = entry.getKey();
            if (visited.contains(next)) {
                continue;
            }
            double r = findAns(next, b, cur * entry.getValue(), graph, visited);
            if (r != -1.0) return r;
        }
        return -1.0;
    }

等式建模为带权图（A→B=value，B→A=1/value），每个查询从起点 DFS 连乘边权找终点，visited 防环，-1.0 哨兵（值恒正不会误判）；29/29 一次 Accepted

思路拆解

问题本质

已知若干形如 A / B = value 的等式，求任意 C / D 的比值。每个等式是图上的一条带权有向边：变量当节点，A → B 边权 value 表示 A = value × B，反向边 B → A 边权 1/value。于是 C / D 就是从 C 走到 D 的路径上所有边权连乘；走不到（不同连通分量或变量未定义）就是 -1.0。

为什么用 建图 + DFS

  • 关系可链式推导（a/b × b/c = a/c），正是图上的路径乘积，天然用图建模。
  • 每次查询就是在图上找一条可行路径，DFS 遍历邻居连乘即可，代码直观；题目规模（变量 ≤ 40、查询 ≤ 20）下每个查询 O(V+E) 完全够。
  • 也可用 Floyd 预计算所有对（O(V³)）或带权并查集，但本题 DFS 最简且满足复杂度要求。

关键设计决策

  • 数据结构：邻接表 Map<String, Map<String, Double>>；建图时每条等式加双向边：A→B = value、B→A = 1/value。
  • DFS 签名：(当前节点, 目标, 累计乘积 cur, 已访问集合)；cur 初始传 1.0（乘法单位元），每深入一层乘上边权。
  • 终止条件：当前节点 == 目标 → 返回 cur；遍历完所有邻居仍没找到 → 返回 -1.0。
  • 防环：visited 集合，进节点先标记；边可能成环（如 a→b→a），不标记会死循环。
  • 哨兵安全：所有 value > 0，路径乘积恒正，-1.0 永不可能是合法答案，放心当「未找到」信号。
  • 主函数先处理两个特例：变量未定义（不在图里）→ -1.0（即使 C==D，如 x/x）；C==D 且存在 → 1.0。

小 case 推演

equations=[["a","b"],["b","c"]], values=[2,3]，查询 a/c：

  1. 建图：a→b=2，b→a=0.5；b→c=3，c→b=1/3
  2. findAns(a, c, 1.0, visited={})
  3. 访问 a：标记；邻居 b 未访问 → findAns(b, c, 1.0×2=2.0)
  4. 访问 b：标记；邻居 a 已访问跳过，邻居 c 未访问 → findAns(c, c, 2.0×3=6.0)
  5. 当前 c == 目标 c → 返回 6.0 ✅

反向 b/a：findAns(b, a, 1.0) → b→a 边权 0.5 → findAns(a, a, 0.5) → 返回 0.5 ✅

边界与细节

  • 空等式：graph 为空，任何查询都 -1.0（含 a/a）。
  • 已定义但不连通：a/b 与 c/d 两个分量，跨分量 DFS 走不到 → -1.0。
  • 长链：a/e = 2×3×4×5 = 120，验证连乘累计正确。
  • 未定义变量：x/x 也 -1.0（x 不在图里，先判 containsKey）。
  • 变量名含数字：字符串比较，无影响。

复杂度与下限论证

  • 时间：建图 O(E)；每个查询 DFS 最坏遍历所在连通分量 O(V+E)，总 O(Q·(V+E))。V ≤ 40、E ≤ 20，规模极小，可接受。
  • 空间：邻接表 O(V+E)，每次查询 visited 集合 O(V)，递归栈 O(V)。
  • 下限论证：必须至少读一遍所有等式与查询（Ω(E+Q)）；若要求每次查询 O(1)，可用 Floyd 预计算（O(V³)，本题 V 小）或带权并查集，但 DFS 在本题约束下已是简洁且满足要求的选择。
