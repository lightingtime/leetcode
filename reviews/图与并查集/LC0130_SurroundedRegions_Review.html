LC0130_SurroundedRegions.java · 边缘O反向DFS标记安全区，再全棋盘翻转提交区
    public void solve(char[][] board) {
        int m = board.length;
        if (m == 0) {
            return;
        }
        int n = board[0].length;
        for (int i = 0; i < m; i++) {
            dfs(board, i, 0);
            dfs(board, i, n - 1);
        }

        for (int j = 0; j < n; j++) {
            dfs(board, 0, j);
            dfs(board, m - 1, j);
        }

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (board[i][j] == 'A') {
                    board[i][j] = 'O';
                } else if (board[i][j] == 'O') {
                    board[i][j] = 'X';
                }
            }
        }
    }

    private void dfs(char[][] board, int i, int j) {
        if (i < 0 || i >= board.length || j < 0 || j >= board[0].length || board[i][j] != 'O') {
            return;
        }
        board[i][j] = 'A';
        dfs(board, i - 1, j);
        dfs(board, i + 1, j);
        dfs(board, i, j - 1);
        dfs(board, i, j + 1);
    }

思路拆解

问题本质：判断每个 O 区域是否「被 X 完全包围」（即不接触棋盘边缘），被包围的改成 X。难点是「被围」的判断——直接找被围区域要检查四周，很绕。

解法选择理由（反向思维）：与其找「被包围的 O」，不如找「不会被包围的 O」——从棋盘边缘的 O 出发，能连到的所有 O 都接触边缘，一定安全。用 DFS/BFS 把这些安全 O 标记出来，剩下的 O 就是要改成 X 的。复杂度 O(m·n)，达到下界（每个格子至少要看一次）。

关键设计决策：

  1. 反向标记：从四条边的 O 出发 DFS，把连通的 O 标成临时字符 'A'（安全区），同时天然防重复访问（'A' 不再是 'O'，不会再被递归）。
  2. 临时标记用 'A' 而不是直接保留：因为后面要区分「安全 O（保留）」和「被围 O（改 X）」，分两轮处理。
  3. 翻转扫描必须覆盖整个棋盘（含边缘）：'A'→'O'、'O'→'X'。边缘的 'A' 同样是安全区，必须还原（这是本题最容易漏的坑）。

具体 case 推演（3×3，中心被围）：

```

X X X X X X

X O X → X X X 中心 O 到不了边缘 → 捕获

X X X X X X

```

边缘全是 X，DFS 无起点；翻转时中心 'O' → 'X' ✓

反向案例（连通到边缘不捕获）：

```

X X X X X X

X O X → X O X (2,0) 是边缘 O，DFS 标 'A' 把 (2,1) 也标 'A'

O O X O O X → 全棋盘扫描：A→O，保持不变 ✓

```

边界与细节：

  • 边缘 O 一定安全（示例1 的 (3,1)）。
  • 单行/单列：整行/整列都是边缘，所有 O 都安全。
  • 全 X：无 O，不变；全 O：全在边缘/连通边缘，不变。
  • 大输入 200×200：DFS 最坏递归深度 O(m·n)（蛇形连通区），本解在力扣 59 用例通过；但极端全 O 棋盘在栈较小的环境可能栈溢出，更稳的是迭代 DFS/BFS 或并查集（已记入错误习惯）。

复杂度与下限论证：每个格子最多访问常数次 → O(m·n) 时间；递归栈最坏 O(m·n) 空间。下界 Ω(m·n)（每个格子至少判断一次），此解达到最优量级。

踩坑记录：① 翻转循环只扫内部 [1,m-2]×[1,n-2] 导致边缘 'A' 未还原（已修复）；② 递归 DFS 在 200×200 全 O 时 StackOverflowError（本地边界已改为深度有界的大输入用例）。
