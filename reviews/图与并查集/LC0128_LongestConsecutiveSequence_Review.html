题目描述

给定一个未排序的整数数组 nums ，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 O(n) 的算法解决此问题。

示例 1：

输入：nums = [100,4,200,1,3,2]

输出：4

解释：最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。

示例 2：

输入：nums = [0,3,7,2,5,8,4,6,0,1]

输出：9

示例 3：

输入：nums = [1,0,1,2]

输出：3

写法 1 · HashSet + 从段起点向上延展

时间 O(n)空间 O(n)内存 ≈ 91.5 MB用例 —

LC0128_LongestConsecutiveSequence.java · HashSet + 从段起点向上延展提交区
public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for(int num : nums) set.add(num);
        int max = 0;
        for (int num : set) {
            int x = num;
            if (set.contains(x - 1)) {
                continue;
            }
            while (set.contains(x + 1)) {
                x++;
            }
            max = Math.max(max, x - num + 1);
        }
        return max;
    }

思路拆解

问题本质与解法选择

找数组里最长「连续数值段」的长度（数字可乱序、可重复，重复不影响连续段）。朴素思路：排序后扫一遍找最长连续上升 → O(n log n)，但题目明确要求 O(n)。

要 O(n) 就得用哈希做 O(1) 的「存在性查询」：把全部数放进 HashSet 去重，然后对每个数尝试向 +1 方向延展计数。真正的难点是避免 O(n²)：如果对每个元素都向后延展，[1..n] 这种长段会被从每个位置重复数一遍 → TLE。剪枝办法：只从「段起点」开始数（x-1 不在集合里的 x 才是起点），这样每个连续段只被数一次。

关键设计决策

决策理由
Set<Integer> set 去重存在性查询 O(1)；重复值不影响段，天然去重
起点剪枝 if (set.contains(x-1)) continue;非起点跳过 → 每段只从段首数一次，整体 O(n)
while (set.contains(x+1)) x++;从起点向后延展，长度 = x - num + 1
遍历 for (Integer num : set) 而非原数组去重后遍历，避免对重复元素重复发起计数

具体 case 推演（示例1：nums=[100,4,200,1,3,2]）

阶段状态
建 set{1,2,3,4,100,200}
遍历 num=11-1=0 ∉ set → 是起点；延展：2,3,4 都在 → x 到 4，长度 4-1+1=4，max=4
遍历 num=22-1=1 ∈ set → continue（非起点，整段已在 1 处数过）
遍历 num=33-1=2 ∈ set → continue
遍历 num=44-1=3 ∈ set → continue
遍历 num=10099 ∉ set → 起点；100+1=101 ∉ set → 长度 1，max 不变
遍历 num=200同理长度 1
结果4

关键：段 [1,2,3,4] 只被 num=1 数了一次，2/3/4 全部被剪枝跳过——这就是 O(n) 而不是 O(n²) 的原因。

边界与细节

  • 空输入 []：max 初值 0，直接返回 0。
  • 单元素 / 全相同（去重后剩一个）：长度 1。
  • 重复值如 [1,1,2,2,3,3]：set={1,2,3}，从 1 数到 3 → 3。
  • 负数区间（-3..1）：起点 -3（-4 ∉ set），照常延展，int 加法安全。
  • 极值相邻 [1000000000, 999999999]：x+1 不溢出（最大 10^9 + 1 仍在 int 范围）。
  • TLE 回归：长连续段 + 大量重复起点的用例，防「对每个原数组元素都发起延展」的写法。

复杂度与下限论证

  • 时间 O(n)：建 set O(n)；遍历 set 每个元素要么被 continue 剪枝、要么作为某段起点延展——每段延展总次数 = 段内元素数，所有段加起来 ≤ n，故总 O(n)。
  • 空间 O(n)：HashSet 存全部去重元素。
  • 为什么是最优：必须读完全部 n 个元素才能确定哪些数存在 → Ω(n) 时间下界，已达成；哈希去重是「O(1) 存在查询 + 线性扫描」的唯一途径（排序法 O(n log n) 不满足题设 O(n)）。

套路沉淀

记忆化/哈希表：先定死 map 的 value 语义，value 必须是最终要比较的量

用 map 做记忆化或统计前，先明确 key→value 存什么：最终要比较的（长度/最大值）就必须直接存长度本身。把中间定位值（前驱位置、起点偏移）当长度存进 map 再参与 max 比较，结果是无意义数值；跳链时用存储值当步长还可能振荡死循环。

链式记忆化：存在性判断基于全集，不能基于已处理集合

算 f(x)=1+f(x-1) 时，x-1『在不在』必须问全集（所有输入先去重放入），不能问『处理到当前为止见过没有』——否则输入乱序时前驱后到，x 被过早判定为孤立点，缓存值过期。做法：先全部放入（标记未算），再按需递归/循环算；或 HashSet 存全集 + map 只做记忆化。
