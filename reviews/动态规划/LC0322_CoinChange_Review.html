322. 零钱兑换 (Coin Change)

难度：Medium ｜ 分类：动态规划

题目描述

给你一个整数数组 coins ，表示不同面额的硬币；以及一个整数 amount ，表示总金额。

计算并返回可以凑成总金额所需的 最少的硬币个数 。如果没有任何一种硬币组合能组成总金额，返回 -1 。

你可以认为每种硬币的数量是无限的。

示例 1：

输入：coins = [1, 2, 5], amount = 11

输出：3

解释：11 = 5 + 5 + 1

示例 2：

输入：coins = [2], amount = 3

输出：-1

示例 3：

输入：coins = [1], amount = 0

输出：0

我的解法

写法 1 · 一维DP（完全背包）

时间 O(amount · coins)空间 O(amount)内存 ≈ 44.3 MB用例 189/189

LC0322_CoinChange.java · 一维DP（完全背包）提交区
public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, 100001);
        dp[0] = 0;
        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (i - coin >= 0) {
                    dp[i] = Math.min(dp[i - coin] + 1, dp[i]);
                }
            }
        }
        return dp[amount] == 100001 ? -1 : dp[amount];
    }

public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);
        dp[0] = 0;
        for (int i = 1; i <= amount; i++) {
            for (int c : coins) {
                if (c <= i) {
                    dp[i] = Math.min(dp[i], dp[i - c] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }

思路拆解

问题本质与解法选择

凑出 amount 的最少硬币数，硬币无限使用——本质是完全背包/最短路：金额 i 的最优解 = 某枚硬币 coin + 金额 i−coin 的最优解，子问题更小且同构，满足最优子结构。贪心不可行：coins=[1,3,4]、amount=6 时贪心取 4 得 4+1+1=3 个，最优是 3+3=2 个，所以必须枚举全部候选取 min，用一维 DP 自底向上。

关键设计决策（按用户实际写法）

  1. 状态：dp[i] = 凑出金额 i 的最少硬币数；dp[0]=0；其余填 INF=100001（大于 amount 上界 10⁴，表示不可达）。
  2. 转移：外层金额 i=1..amount，内层遍历每枚硬币，coin ≤ i 时 dp[i] = min(dp[i], dp[i−coin]+1)。
  3. 无限使用：外层金额、内层硬币的循环顺序天然允许同一面额重复取。
  4. 答案：dp[amount]，仍为 INF 则返回 -1。

边界与细节

  • amount=0：直接返回 dp[0]=0。
  • 硬币面额大于当前金额：跳过（i−coin≥0 守卫），如 coins=[7]、amount=3 → dp[3] 保持 INF → -1。
  • 无 1 面额：coins=[2,5]、amount=6 → 2+2+2=3，金额递增的自底向上能组合出来。
  • 贪心反例：coins=[1,3,4]、amount=6 → dp[6]=min(dp[5]+1=3, dp[3]+1=2, dp[2]+1=3)=2。
  • INF 选择：100001 大于任何可达硬币数（最多 amount 个面额 1 的硬币），且 dp[i−coin]+1 不会溢出 int。
  • 推演 case：coins=[1,2,5]、amount=11：dp[0]=0→dp[1]=1→dp[2]=1→dp[3]=2→dp[4]=2→dp[5]=1→dp[6]=2→dp[7]=2→dp[8]=3→dp[9]=3→dp[10]=2→dp[11]=min(dp[10]+1=3, dp[9]+1=4, dp[6]+1=3)=3 ✓（5+5+1）。

复杂度与下限论证

  • 时间 O(amount×coins)：两层循环，amount≤10⁴、coins≤12 → 约 12 万次操作。
  • 空间 O(amount)：dp 数组。
  • 下限：每个金额至少要比较所有可用面额才能保证最少（贪心会漏最优），O(amount×coins) 是「枚举最后一块」DP 的自然复杂度，也是本题可接受的最优档（BFS 版本同复杂度）。

套路沉淀

一维完全背包（容量从小到大、物品在内层）

识别信号：物品可无限次选取 + 求最优值（最少个数/最大价值）。与 0/1 背包的唯一分水岭是容量维枚举方向——完全背包容量从小到大，使得 dp[i-c] 是「本轮已更新」的状态，同一物品可复用；0/1 背包必须从大到小，避免同一件物品被重复计入。本题把「求装满的最小代价」直接建模成 min 转移，无需额外记录选取方案。
