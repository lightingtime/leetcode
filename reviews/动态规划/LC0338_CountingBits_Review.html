src/LC0338_CountingBits.java提交区
public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }

最低位+右移递推：偶数 dp[i]=dp[i>>1]，奇数再加 1，合并为 dp[i]=dp[i>>1]+(i&1)，一趟 O(n) 填表；15/15 一次 Accepted

思路拆解

问题本质

对 0..n 每个数统计二进制中 1 的个数。暴力做法是每个数单独数位（逐位与 1 判断）→ O(n log n)；进阶要求一趟 O(n) 扫描推出全部。

为什么用 DP（由小推大）

  • dp[i]（i 的 1 位数）可以只依赖比 i 小的数推出：看二进制最低位和右移一位。
  • 偶数最低位是 0：右移丢掉的是 0，1 的个数不变 → dp[i] = dp[i>>1]。
  • 奇数最低位是 1：右移丢掉的就是这个 1，所以比右移结果多 1 → dp[i] = dp[i>>1] + 1。
  • 两条合并：dp[i] = dp[i>>1] + (i & 1)，且 i>>1 < i，从 0 到 n 顺序填表即可，一趟 O(n)。

关键设计决策

  • 状态定义：dp[i] = 整数 i 的二进制中 1 的个数；返回数组本身当 dp 用（ans）。
  • 转移：ans[i] = ans[i >> 1] + (i & 1)；ans[0] = 0 自动满足（数组默认值）。
  • 填表顺序：i 从 1 到 n 递增，保证 i>>1 已被算过。
  • 不用任何内置 popcount，纯位运算递推。

小 case 推演

n=5：

  1. i=1：ans[0]+(1&1)=0+1=1（1）
  2. i=2：ans[1]+(2&1)=1+0=1（10）
  3. i=3：ans[1]+(3&1)=1+1=2（11）
  4. i=4：ans[2]+(4&1)=1+0=1（100）
  5. i=5：ans[2]+(5&1)=1+1=2（101）

结果 [0,1,1,2,1,2]，与示例一致 ✅。

边界与细节

  • n=0：数组 [0]，循环不执行，返回 [0]。
  • 大数：n ≤ 10⁵（< 2¹⁷），1 位数最多 17，int 数组足够，不会溢出。
  • 最低位判断用 i & 1，奇偶分支无需显式 if。

复杂度与下限论证

  • 时间 O(n)：每个 i 恰好一次 O(1) 转移；输出本身就有 n+1 项，任何解法都必须生成全部 → O(n) 是下界，本题已达最优。
  • 空间 O(1) 额外（返回数组是题目要求的输出，不计入辅助空间）。
  • 结论：一趟扫描 + O(1) 转移，满足进阶要求，是本题最优解。
