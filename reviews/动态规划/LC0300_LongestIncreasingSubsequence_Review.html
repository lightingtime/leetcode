300. 最长递增子序列 (Longest Increasing Subsequence)

难度：Medium ｜ 分类：动态规划

标签：数组、二分查找、动态规划、最长上升子序列

题目描述

给你一个整数数组 nums ，找到其中最长严格递增子序列的长度。

子序列 是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，[3,6,2,7] 是数组 [0,3,1,6,2,2,7] 的子序列。

示例 1：

输入：nums = [10,9,2,5,3,7,101,18]

输出：4

解释：最长递增子序列是 [2,3,7,101]，因此长度为 4 。

示例 2：

输入：nums = [0,1,0,3,2,3]

输出：4

示例 3：

输入：nums = [7,7,7,7,7,7,7]

输出：1

LC0300_LongestIncreasingSubsequence.java · 贪心+二分（tails数组）提交区
public int lengthOfLIS(int[] nums) {
        int[] ans = new int[nums.length];
        Arrays.fill(ans, Integer.MAX_VALUE);
        int k = 0;
        for (int i = 0; i < nums.length; i++) {
            // ans 未使用槽位为 MAX_VALUE，find 的二分会把它当作上界哨兵
            int index = find(ans, k, nums[i]);
            if (index >= k) {
                ans[k] = nums[i];
                k++;
            } else {
                ans[index] = nums[i];
            }
        }
        return k;
    }

    private int find(int[] ans, int tail, int target) {
        int l = -1, r = tail + 1;
        while (l + 1 < r) {
            int mid = l + (r - l) / 2;
            if (ans[mid] < target) {
                l = mid;
            } else {
                r = mid;
            }
        }
        return r;
    }

public int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length];
        int tail = 0;
        for (int i = 0; i < nums.length; i++) {
            int index = findNumIndex(tails, tail, nums[i]);
            if (index < tail) {
                tails[index] = nums[i];
            } else {
                tails[tail] = nums[i];
                tail++;
            }
        }
        return tail;
    }

    private int findNumIndex(int[] tails, int end, int num) {
        int l = -1, r = end + 1;
        while (l + 1 < r) {
            int mid = l + (r - l) / 2;
            if (tails[mid] < num) {
                l = mid;
            } else {
                r = mid;
            }
        }
        return r;
    }

思路拆解

问题本质与解法选择

求最长严格递增子序列长度。朴素 O(n²) DP（dp[i]=以 i 结尾的最长长度，枚举 j<i 且 nums[j]<nums[i]）可行，但题目进阶要求 O(n log n)。核心观察：长度相同的递增子序列，尾值越小越有延展潜力，所以只需保留「每个长度下的最小尾值」——即 patience sorting 的 tails 数组，配合二分把单个元素处理降到 O(log n)。

关键设计决策（按用户实际写法）

  1. tails[k] = 长度为 k+1 的递增子序列的最小尾值，严格递增；tail 变量记录有效长度，只读写 tails[0..tail-1]。
  2. 对每个 nums[i]，二分找第一个 ≥ nums[i] 的下标 index（lower_bound）：index < tail 则替换 tails[index]（长度不变、尾值改小）；否则追加 tails[tail]=nums[i]、tail++（长度 +1）。
  3. 双开区间二分：l=-1、r=end+1，循环 l+1<r；tails[mid] < num → l=mid（mid 及左边都 < num，成为左排除边界），否则 r=mid（mid 及右边都 ≥ num）。返回 r 即 lower_bound。
  4. 哨兵细节：r 初始 end+1 可能让 mid 读到 tails[end]（从未写入、恒为 0 的位置）；只有「全部真实尾巴 < num」时才会访问它——num>0 得 r=end+1、num≤0 得 r=end，主调用都走 append 分支，等价于追加。
  5. 答案：tail。

边界与细节

  • 单元素：直接追加，tail=1。
  • 严格递减/全相等：每元素都替换到前部（lower_bound 很小），tail 保持 1；相等元素因替换条件是 ≥ 而不能续长，[7,7,7] → 1。
  • 负数：二分只比大小，与符号无关；穷举（长度 1-9、值 -2..2）与 O(n²) 参考实现全部一致。
  • 推演 case：nums=[1,3,4,2,5,6,7]。
  1. 1 → tails[0]=1，tail=1。
  2. 3 → 追加 [1,3]，tail=2。
  3. 4 → 追加 [1,3,4]，tail=3。
  4. 2 → lower_bound=1（tails[1]=3≥2）→ 替换 [1,2,4]，tail 仍 3——长度信息不丢，这是与「弹光更大元素」写法的关键区别。
  5. 5 → 追加 [1,2,4,5]，tail=4；6 → 5；7 → 6。
  6. 答案 6 ✓（真实 LIS 为 1,3,4,5,6,7）。

复杂度与下限论证

  • 时间 O(n log n)：外层 n 次 × 每次二分 O(log n)，满足进阶要求。
  • 空间 O(n)：tails 数组。
  • 下限：LIS 在比较模型下需要 Ω(n log n)，本解已达最优；O(n²) DP 是正确但非最优的对照。
