416. 分割等和子集 (Partition Equal Subset Sum)

> https://leetcode.cn/problems/partition-equal-subset-sum/

难度：Medium ｜ 分类：动态规划

标签：数组、动态规划、背包问题、0-1 背包

题目描述

给你一个 只包含正整数 的 非空 数组 nums 。请你判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

示例 1：

输入：nums = [1,5,11,5]

输出：true

解释：数组可以分割成 [1, 5, 5] 和 [11] 。

示例 2：

输入：nums = [1,2,3,5]

输出：false

解释：数组不能分割成两个元素和相等的子集。

public boolean canPartition(int[] nums) {
        int sum =0;
        for (int num : nums) {
            sum += num;
        }
        if ((sum & 1) == 1) {
            return false;
        }
        sum /= 2;
        HashSet<Integer> set = new HashSet<>();
        set.add(0);
        for (int num : nums) {
            HashSet<Integer> copy = new HashSet<>(set);
            for (Integer i : copy) {
                if (i + num <= sum) {
                    set.add(i + num);
                }
                if (set.contains(sum)) {
                    return true;
                }
            }
        }
        return false;
    }

一次 AC；可达和集合（0-1 背包判定）：sum 奇数剪枝 + 快照遍历防元素复用；O(n·target)/O(target)

思路拆解

问题本质与解法选择理由

  • 本质：正整数数组能否分成两个和相等的子集 ⟺ 能否选出一个子集和为 sum/2（target），另一组自动是补集。这是 0-1 背包的判定版：每个元素只能选一次，能否恰好装满容量 target。
  • 为什么不用暴力枚举：2^n 子集不可行；「可达和集合」逐元素扩张，每个元素 O(可达和个数)，总 O(n·target) 伪多项式，是本题约束（n≤200、target≤10000）下的标准最优。

关键设计决策

  • 奇数剪枝：sum 为奇数直接 false（一半不是整数，必不可能）。
  • 状态：可达和集合 set，初始 {0}（空子集和，是「单元素可达」的地基：num 本身 = 0+num）。
  • 扩张规则：处理 num 时，基于上一轮的快照遍历，把每个可达和 i 的 i+num 加入原 set——快照保证每个元素只用一次（不会连锁复用，如 5 不能连用两次凑 10），也避免遍历时修改集合的异常。
  • 提前返回：set 一出现 target 即 true；最终 return set.contains(target)（实现里用循环内提前 return + 末尾 false 等价）。

具体 case 推演：[1,5,11,5]（target=11，期望 true）

  • 初始 set={0}
  • num=1：快照{0} → 加 1 → {0,1}
  • num=5：快照{0,1} → 加 5,6 → {0,1,5,6}
  • num=11：快照{0,1,5,6} → 加 11,12,16,17 → 11 出现 → true ✓

具体 case 推演：[1,2,5]（sum=8，target=4，期望 false）

  • {0} → 1：{0,1}
  • 2：快照{0,1} 加 2,3 → {0,1,2,3}
  • 5：快照{0,1,2,3} 加 5,6,7,8 → {0,1,2,3,5,6,7,8}，始终没有 4 → false ✓

边界与细节

  • 单元素 [2]：target=1 凑不出 → false；[1] 奇数 → false。
  • 全 1 偶数个：target=n/2 可凑 → true；奇数个 sum 奇数 → false。
  • 大数组 200×100：target=10000，set 去重后规模 ≤ target+1，容量足够且不超时。
  • 可优化点（不影响正确性）：i+num > target 的入集合没有意义，可剪枝省时间；也可换 boolean[] dp 倒序遍历，常数更小。

复杂度与下限论证

  • 时间 O(n·target)：每元素遍历当前可达和（去重后 ≤ target+1）。子集和是 NP 完全问题，不存在多项式时间算法；O(n·target) 是标准伪多项式 DP，对本约束即预期最优。
  • 空间 O(target)：set 至多存 target+1 个不同和。
