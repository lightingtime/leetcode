55. 跳跃游戏 (Jump Game)

> https://leetcode.cn/problems/jump-game/

难度：Medium ｜ 分类：动态规划

标签：贪心、数组、动态规划

题目描述

给你一个非负整数数组 nums ，你最初位于数组的 第一个下标 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标，如果可以，返回 true ；否则，返回 false 。

示例 1：

输入：nums = [2,3,1,1,4]

输出：true

解释：可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。

示例 2：

输入：nums = [3,2,1,0,4]

输出：false

解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。

public boolean canJump(int[] nums) {
    int maxReach = 0;
    for (int i = 0; i < nums.length; i++) {
        if (maxReach < i) {
            return false;
        }
        maxReach = Math.max(maxReach, i + nums[i]);
    }
    return maxReach >= nums.length - 1;
}

public boolean canJump(int[] nums) {
        int farthest = 0;
        for (int i = 0; i < nums.length; i++) {
            if (farthest >= nums.length - 1) {
                return true;
            }
            if (i > farthest) {
                return false;
            }
            farthest = Math.max(farthest, i + nums[i]);
        }
        return false;
    }

思路拆解

问题本质：判断能否从下标 0 到达最后一个下标。每个位置能跳的最大长度是 nums[i]，只需要关心「当前已经能覆盖到的最远位置」，不需要具体路径——贪心天然适配。

为什么用贪心：

  • farthest 表示已扫描区间内能到达的最远下标，单调不减；
  • 只要位置 i 被覆盖（i <= farthest），它的跳跃就能把 farthest 继续往右推；若 i > farthest，说明前面所有跳跃都够不着这里，后面更够不着，直接判负；
  • 一旦 farthest >= n-1 即成功，不需要回溯或枚举路径。

关键设计（顺序决定正确性）：

  1. 遍历每个位置 i：先检查 farthest >= n-1 提前返回 true；
  2. 再检查 i > farthest 直接返回 false（可达性守卫，防止不可达位置的大跳跃污染 farthest）；
  3. 最后更新 farthest = max(farthest, i + nums[i])。

具体 case 推演：

  • [2,3,1,1,4]：i=0 → f=2；i=1 → f=4 >= 4 → true；
  • [3,2,1,0,4]：i=0 → f=3；i=1、2、3 都保持 f=3；i=4 时 4 > 3 → false；
  • [1,1,1,0,5,0]（本轮的坑）：真实可达只到下标 3；若缺少 i > farthest 守卫，i=4 会把 f 更新成 9，下一轮误判 true——正确结果是 false。

边界与细节：

  • 单元素数组：farthest=0 >= 0，直接 true（已经站在终点）；
  • 开头为 0 且 n>1：[0,1] 在 i=1 被守卫拦下；
  • 大跳跃（[10,0,0,0]）一步到终点；10000 长度数组一趟通过（O(n) 而非 O(n²)）。

复杂度分析：

  • 时间 O(n)：一趟扫描；
  • 空间 O(1)：一个变量。

为什么是最优：每个位置至少要读一次，O(n) 是下限；只维护一个最远下标，O(1) 空间也是下限。

套路沉淀

贪心最远可达：先判当前位置可达再更新，不可达立即返回

出处：LC0055 跳跃游戏

  • 维护 farthest = 当前能到的最远下标，遍历每个位置 i：
  • 先判 i > farthest：当前位置都够不着，后面更够不着，直接返回 false；
  • 再更新 farthest = max(farthest, i + nums[i])；
  • 一旦 farthest >= n-1 返回 true。
  • 顺序不能反：先可达性检查再更新；只检查不判可达，会让不可达位置的大跳跃把 farthest 推过终点，下一轮误判为 true。
  • 具体 case：[1,1,1,0,5,0] 实际最远只到下标 3，位置 4 的 5 不可达，答案应为 false。

要点：贪心维护「最远可达」时，每个位置在更新前必须先确认自己可达；边界顺序（检查→更新→提前返回）决定正确性。
