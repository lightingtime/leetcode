140. 单词拆分 II (Word Break II)

> https://leetcode.cn/problems/word-break-ii/

难度：Hard ｜ 分类：动态规划

标签：字典树、记忆化、数组、哈希表、字符串、动态规划、回溯

题目描述

给定一个字符串 s 和一个字符串字典 wordDict ，在字符串 s 中增加空格来构建一个句子，使得句子中所有的单词都在词典中。以任意顺序 返回所有这些可能的句子。

注意：词典中的同一个单词可能在分段中被重复使用多次。

示例 1：

输入:s = "catsanddog", wordDict = ["cat","cats","and","sand","dog"]

输出:["cats and dog","cat sand dog"]

示例 2：

输入:s = "pineapplepenapple", wordDict = ["apple","pen","applepen","pine","pineapple"]

输出:["pine apple pen apple","pineapple pen apple","pine applepen apple"]

解释: 注意你可以重复使用字典中的单词。

示例 3：

输入:s = "catsandog", wordDict = ["cats","dog","sand","and","cat"]

输出:[]

LC0140_WordBreakIi.java · 后缀可拆预判+回溯提交区
List<String> ans;
    boolean[] canReach;
    public List<String> wordBreak(String s, List<String> wordDict) {
        ans = new ArrayList<>();
        canReach = new boolean[s.length() + 1];
        canReach[s.length()] = true;
        Set<String> set = new HashSet<>(wordDict);
        for (int i = s.length(); i >= 0; i--) {
            for (String word : set) {
                if (i + word.length() <= s.length() && canReach[i + word.length()] && s.startsWith(word, i)) {
                    canReach[i] = true;
                    break;
                }
            }
        }
        dfs(s, 0, set, new ArrayList<String>());
        return ans;
    }

    private void dfs(String s, int i, Set<String> set, ArrayList<String> path) {
        if (i == s.length()) {
            ans.add(String.join(" ", path));
            return;
        }

        if (!canReach[i]) {
            return;
        }

        for (String word : set) {
            if (i + word.length() > s.length()) {
                continue;
            }
            if (s.startsWith(word, i)) {
                path.add(word);
                dfs(s, i + word.length(), set, path);
                path.remove(path.size() - 1);
            }
        }
    }

boolean[] suffixOK;
    Set<String> set;
    List<String> ans;
    public List<String> wordBreak(String s, List<String> wordDict) {
        set = new HashSet<>(wordDict);
        ans = new ArrayList<>();
        int n = s.length();

        // 后缀可拆预判：suffixOK[i] = s[i..n) 能否由字典词拼完（从右往左算）
        suffixOK = new boolean[n + 1];
        suffixOK[n] = true;
        for (int i = n - 1; i >= 0; i--) {
            for (String word : set) {
                int next = i + word.length();
                if (next <= n && suffixOK[next] && s.startsWith(word, i)) {
                    suffixOK[i] = true;
                    break;
                }
            }
        }
        // DFS 从哪里出发，DP 就最好描述“从哪里能不能到终点”。
        dfs(s, 0, new ArrayList<>());
        return ans;
    }

    private void dfs(String s, int start, List<String> path) {
        if (start == s.length()) {
            ans.add(String.join(" ", path));
            return;
        }
        // 从start直接看后面能不能满足，不满足说明从start出发无论怎么拆都没有结果，直接剪枝
        if (!suffixOK[start]) {
            return;
        }
        for (int i = start; i <= s.length(); i++) {
            String temp = s.substring(start, i);
            if (set.contains(temp)) {           // 当前段是字典词
                path.add(temp);
                dfs(s, i, path);
                path.remove(path.size() - 1);
            }
        }
    }

思路拆解

① 问题本质与解法选择

  • 本质：枚举所有能把 s 拆成字典词的句子，词可重复使用。两层结构：回溯负责枚举，预判负责剪枝。
  • 解法选择：后缀可拆预判 suffixOK（右往左的线性 DP）+ 回溯。set.contains 保证每段是合法词；suffixOK 在 DFS 入口剪掉「从 start 到不了终点」的整棵子树。

② 关键设计决策

设计点决策理由
预判数组suffixOK[i] = s[i..n) 能否拼完，suffixOK[n]=true，从右往左算剪枝要问「未来」能否到终点，不是「过去」前缀
剪枝位置DFS 入口 if (!suffixOK[start]) return到不了终点直接整棵剪，不试词
段合法性set.contains(temp)与 dp 无关，前缀本来就一路真拆出来的
句子拼接List path + 出口 String.join(" ", path)回溯只需 add/remove，避开 StringBuilder 下标手抖
前缀 dp完全不需要前缀可拆在 DFS 里恒 true（被真拆过），冗余

③ 具体 case 推演

示例3 catsandog / [cat,cats,and,sand,dog] 的 suffixOK（期望 []）：

位置剩余判定
10空true（基）
7og无词匹配 → false
3sandogsand→suffixOK[7]=false；and→s[3..6)=san 不匹配 → false
0catsandogcat→suffixOK[3]=false；cats→suffixOK[4] 也 false → false

dfs(0) 入口 !suffixOK[0] → 一步不进直接返回 []，省掉整棵死树的遍历。

示例1 catsanddog 的 DFS 两条路径（suffixOK[3]、[7] 均为 true）：

starttemppath出口

④ 边界与细节

  • 单字符命中 / 完全无法拆分 / 整词+细分并存 / 词重复使用（aaa={a,aa} 三种）/ 剩余不可拼（abcd 只有 ab cd）
  • 长度 20 上限：20 个 a 用 {a,aa} 拼 → 方案数 F(21)=10946，验证枚举不漏不重
  • StringBuilder 出口删空格不恢复是乱码根因 → 用 List path + join 根治

⑤ 复杂度与下限论证

  • 预判 O(n·|dict|)；枚举阶段总开销 = 输出方案数 × 每句拼接 O(n)
  • 空间 O(n)（suffixOK+path）+ 输出结果
  • 枚举类题目下限就是 Ω(方案数)，不可再低；suffixOK 让不可达分支 O(1) 跳过，是可实现的剪枝上限

解题过程

01 · 踩坑已记录

回溯共享状态不对称：子调用修改 StringBuilder（删末尾空格）后未恢复原状就 return，父层按未修改时的下标做 delete 导致状态错乱；且 dp 剪枝用错方向——前缀可拆 dp[i] 不能当后缀可达用，差一个字符的边界 >0/>=0 也导致 dp 欠算砍掉正确路径

02 · 踩坑已记录

DP 可达表基例位置与递推语义不匹配（同一根因第 2 次，一刷也犯过）：canReach[i] 语义是「s[i..n) 能否走到终点」（后缀），而递推检查的落点是 i+word.length()，会取到下标 n，因此基例必须放在末端 canReach[n]=true；写成 canReach[0]=true 后，除下标 0（初始化值）外整张表永远填不出 true，剪枝把「整串恰好是一个词」以外的所有正确路径全砍掉（s="abc"、dict={abc,a,bc} 只剩 abc，丢了 a bc）

套路沉淀

后缀可拆预判+回溯剪枝

枚举拆分句子类：suffixOK[i] 从右往左算 s[i..n) 能否拼完，DFS 入口 !suffixOK[start] 剪掉到不了终点的子树；段合法性用 set.contains；句子用 List path + String.join，别用 StringBuilder 手抖

两段式：DP 判可行性 + 回溯枚举方案

答案数量本身可能指数级（如 s="aaaa"、dict={"a","aa"} 有 5 条），枚举代价躲不掉；能砍的是「注定产不出答案」的子树——先用一遍 DP 预判可行性，再让回溯只在可行分支上展开。预判表方向必须与问题一致：问「从 i 能不能走到终点」就要从右往左填 canReach，canReach[n]=true 为基例，转移 = 存在词 w 使 s.startsWith(w,i) && canReach[i+w.len()]；拿前缀可拆表（0→i 能拆）当后缀可达用就是方向反了。剪枝放在「到达终点收答案」判断之后、循环之前。

错误习惯复盘
