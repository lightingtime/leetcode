91. 解码方法 (Decode Ways)

> https://leetcode.cn/problems/decode-ways/

难度：Medium ｜ 分类：动态规划

标签：字符串、动态规划

题目描述

一条包含字母 A-Z 的消息通过以下映射进行了 编码 ：

"1" -> 'A'

"2" -> 'B'

...

"25" -> 'Y'

"26" -> 'Z'

然而，在 解码 已编码的消息时，你意识到有许多不同的方式来解码，因为有些编码被包含在其它编码当中（"2" 和 "5" 与 "25"）。

例如，"11106" 可以映射为：

"AAJF" ，将消息分组为 (1, 1, 10, 6)

"KJF" ，将消息分组为 (11, 10, 6)

消息不能分组为 (1, 11, 06) ，因为 "06" 不是一个合法编码（只有 "6" 是合法的）。

注意，可能存在无法解码的字符串。

给你一个只含数字的 非空 字符串 s ，请计算并返回 解码 方法的 总数 。如果没有合法的方式解码整个字符串，返回 0。

题目数据保证答案肯定是一个 32 位 的整数。

示例 1：

输入：s = "12"

输出：2

解释：它可以解码为 "AB"（1 2）或者 "L"（12）。

示例 2：

输入：s = "226"

输出：3

解释：它可以解码为 "BZ" (2 26), "VF" (22 6), 或者 "BBF" (2 2 6) 。

示例 3：

输入：s = "06"

输出：0

解释："06" 无法映射到 "F" ，因为存在前导零（"6" 和 "06" 并不等价）。

我的解法

写法 1 · 线性DP·空串基准(n+1)

时间 O(n)空间 O(n)内存 ≈ 41.4 MB用例 269/269

LC0091_DecodeWays.java · 线性DP·空串基准(n+1)提交区
public int numDecodings(String s) {
    int[] dp = new int[s.length() + 1];
    dp[0] = 1;
    dp[1] = s.charAt(0) == '0' ? 0 : 1;
    for (int i = 2; i <= s.length(); i++) {
        int num = s.charAt(i - 2) - '0';
        num = num * 10 + (s.charAt(i - 1) - '0');
        boolean curValid = s.charAt(i - 1) != '0';
        boolean numValid = s.charAt(i - 2) != '0' && num <= 26 && num >= 10;
        dp[i] = (curValid ? dp[i - 1] : 0) + (numValid ? dp[i - 2] : 0);
    }
    return dp[s.length()];
}

写法 2 · 线性DP·以i结尾(n位)

时间 O(n)空间 O(n)内存 ≈ 41.6 MB用例 269/269

LC0091_DecodeWays.java · 线性DP·以i结尾(n位)提交区
public int numDecodings(String s) {
    if (s.charAt(0) == '0') {
        return 0;
    }
    int[] dp = new int[s.length()];
    dp[0] = 1;
    for (int i = 1; i < s.length(); i++) {
        if (s.charAt(i) != '0') {
            dp[i] = dp[i - 1];
        }
        int num = Integer.parseInt(s.substring(i - 1, i + 1));
        if (num >= 10 && num <= 26) {
            dp[i] += (i > 1 ? dp[i - 2] : 1);
        }
    }
    return dp[s.length() - 1];
}

思路拆解

① 问题本质与解法选择

  • 本质：数字串按 1~2 位切成合法编码（1~26；\0\ 不能单独成码）的分组方案计数。每个位置两种来源：当前字符单独解码、或与前一位组成两位数——典型的斐波那契式计数 DP。
  • 解法选择：线性 DP 从左到右扫一遍。两种下标写法数学上完全等价，差别只在「空串基准」放在哪：写法1 开 n+1 数组让 dp[i-2] 在 i=2 时天然存在；写法2 开 n 数组、用一处边界常数 1 代替空串。

② 关键设计决策（两写法对照）

设计点写法1 空串基准写法2 以 i 结尾
dp[i] 含义前 i 个字符的方案数到字符 i（含）为止的方案数
初值dp[0]=1 空串；dp[1]=s[0]!=\0\?1:0dp[0]=s[0]!=\0\?1:0；首字符为 0 提前返回
两位组合贡献dp[i-2] 始终可用i==1 时用常数 1 充当空串
返回dp[n]dp[n-1]

转移只依赖两个独立合法性开关相加：A=当前字符≠\0\ → 贡献 dp[i-1]；B=前一位≠\0\ 且组合值∈[10,26]（两位数天然≥10，只查≤26 与十位非 0）→ 贡献 dp[i-2]。

④ 边界与细节

  • 首字符 \0\：写法1 靠 dp[1]=0 自然传递；写法2 提前 return 0
  • 中间 \0\：只可能配 10/20（A 关 B 开，"10"）；"30" 和 "01" 双双非法 → dp 归零
  • "111"：1,2,3 斐波那契叠加验证
  • 长度 100 上限全 \9\：无任何两位组合 → 恒为 1，检验上界
  • 溢出：题目保证答案在 32 位 int 内

⑤ 复杂度与下限论证

  • 时间 O(n)：每位置 O(1) 转移（Integer.parseInt 处理固定两位子串也是 O(1)）
  • 空间 O(n)（两写法都是数组；滚动变量可降至 O(1)）
  • 下限：必须读完全串 O(n)，每个字符至少一次转移，O(n) 时间为硬下限；空间可进一步优化但非必须。
