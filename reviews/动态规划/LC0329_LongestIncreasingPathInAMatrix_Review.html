329. 矩阵中的最长递增路径 (Longest Increasing Path in a Matrix)

> https://leetcode.cn/problems/longest-increasing-path-in-a-matrix/

难度：Hard ｜ 分类：动态规划

标签：深度优先搜索、广度优先搜索、图、拓扑排序、记忆化、数组、动态规划、有向无环图、矩阵

题目描述

给定一个 m x n 整数矩阵 matrix ，找出其中 最长递增路径 的长度。

对于每个单元格，你可以往上，下，左，右四个方向移动。 你 不能 在 对角线 方向上移动或移动到 边界外（即不允许环绕）。

示例 1：

输入：matrix = [[9,9,4],[6,6,8],[2,1,1]]

输出：4

解释：最长递增路径为 [1, 2, 6, 9]。

示例 2：

输入：matrix = [[3,4,5],[3,2,6],[2,2,1]]

输出：4

解释：最长递增路径是 [3, 4, 5, 6]。注意不允许在对角线方向上移动。

示例 3：

输入：matrix = [[1]]

输出：1

② 关键设计点：带 pre 参数的 DFS 为什么仍然能查 memo

一般原则是「memo[i][j] 只在返回值不依赖调用方参数时成立」，本轮的写法满足这个条件：

  • 守卫 matrix[i][j] <= preValue 的分支先返回 0，且不写 memo（0 也不是合法答案，天然当「未计算」哨兵）；
  • 只有守卫通过后才计算并与 memo 打交道，而通过守卫后的返回值就是无条件的「从 (i,j) 出发的最长递增路径长度」，与 pre 具体是多少无关。

小例子 [[1,2],[4,3]]：算 dfs(0,0,pre=-1) 时会依次算出 dfs(0,1,-1)=3、dfs(1,1,-1)=2、dfs(1,0,-1)=1 并写入 memo；外层循环再问 dfs(0,1,-1) 时直接命中缓存返回 3，不再重走 2→3→4 那一段。若把 memo 写在守卫之前（把 0 也缓存），就会把「因前驱太大而被切断」的错误答案固化下来。

int ans;
    int[][] memo;

    public int longestIncreasingPath(int[][] matrix) {
        ans = 0;
        int m = matrix.length;
        int n = matrix[0].length;
        memo = new int[m][n];
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                ans = Math.max(ans, dfs(matrix, i, j, -1));
            }
        }
        return ans;
    }

    private int dfs(int[][] matrix, int i, int j, int preValue) {
        if (i < 0 || j < 0 || i >= matrix.length || j >= matrix[0].length || matrix[i][j] <= preValue) {
            return 0;
        }
        if (memo[i][j] != 0) {
            return memo[i][j];
        }
        int count = 0;
        count = Math.max(count, dfs(matrix, i + 1, j, matrix[i][j]));
        count = Math.max(count, dfs(matrix, i - 1, j, matrix[i][j]));
        count = Math.max(count, dfs(matrix, i, j - 1, matrix[i][j]));
        count = Math.max(count, dfs(matrix, i, j + 1, matrix[i][j]));
        memo[i][j] = count + 1;
        return memo[i][j];
    }

int max;

    public int longestIncreasingPath(int[][] matrix) {
        max = 0;
        memo = new int[matrix.length][matrix[0].length];
        for (int i = 0; i < matrix.length; i++) {
            for (int j = 0; j < matrix[0].length; j++) {
                memo[i][j] = dfs(matrix, i, j, -1);
                max = Math.max(max, memo[i][j]);
            }
        }
        return max;
    }

    private int dfs(int[][] matrix, int i, int j, int pre) {
        if (i < 0 || i >= matrix.length || j < 0 || j >= matrix[0].length || matrix[i][j] <= pre) {
            return 0;
        }
        if (memo[i][j] != 0) {
            return memo[i][j];
        }

        count = Math.max(count, dfs(matrix, i - 1, j, matrix[i][j]));

        count = Math.max(count, dfs(matrix, i, j + 1, matrix[i][j]));

        return count + 1;

思路拆解

① 问题本质与解法选择

  • 本质：网格 DAG 上的最长路径。严格递增（B>A）让移动方向天然无环——每个格子是节点，四向边指向值更大的邻居。
  • 解法选择：记忆化 DFS。dfs(i,j) 返回从该格出发的最长递增路径长度，每格只算一次，O(m·n)。
  • 为什么不能朴素 DFS：无记忆化时不同起点反复展开同一段后缀路径，200x200 网格路径数指数爆炸（实测直接卡死超时）。

② 关键设计决策

设计点决策理由
memo[i][j]从 (i,j) 出发的最长路径长度，0 表示未算记忆化核心，每格算一次
dfs 转移1 + max(四方向中值更大的邻居的 dfs)，无更大邻居为 1DAG 最长路径标准形态
守卫matrix[i][j] <= pre 拦下严格递增要求 B>A；用 < 会放行等值格，相邻等值互走成 2-环 → StackOverflowError
无环保证严格递增 → DAG → 不需要 visited值只增不回头，memo 足够
答案主循环遍历每格取 memo 最大值最长路径可从任意格出发

③ 具体 case 推演

示例1 [[9,9,4],[6,6,8],[2,1,1]] → 4，最长路径 1(2,1)→2(2,0)→6(1,0)→9(0,0)。

格子更大邻居dfs 计算memo
(0,0)=9无11
(1,0)=6(0,0)=91+dfs(0,0)=22
(2,0)=2(1,0)=61+dfs(1,0)=33
(2,1)=1(1,1)=6、(2,0)=21+max(dfs(1,1)=2, dfs(2,0)=3)=44
(1,1)=6(0,1)=9、(0,0)=9、(1,2)=81+1=22

max=4 ✓。等值格（两个 9、两个 6）在守卫 matrix[i][j]<=pre 下互不可走，不会成环。

④ 边界与细节

  • 单行/单列：只能单向移动，答案 = n 或 m
  • 全相同矩阵：等值不可走 → 每格 1，答案 1
  • 2x2 螺旋递增 → 4（验证跨两行路径）
  • 200x200 上限 matrix[i][j]=i+j → 单调右/下路径长 m+n-1=399（验证 O(m·n) 不超时）
  • 取值上限 2^31-1：全程只比较不运算，无溢出
  • 教训沉淀：记忆化入口必查 memo（只存不查等于白存）；严格递增守卫 < 与 <= 一个符号之差决定是否成环

⑤ 复杂度与下限论证

  • 时间 O(m·n)：每格恰好计算一次，每次看 4 个邻居
  • 空间 O(m·n)：memo 表 + 递归栈最坏 O(m·n)（最长递增路径可贯穿全图）
  • 下限：每个格子至少要被考察一次（可能成为路径成员），O(m·n) 时间即为下限；记忆化让每格只算一次、不重复

套路沉淀

网格DAG最长路径：记忆化DFS

严格递增的网格路径=DAG 最长路径：dfs(i,j)=1+max(更大邻居的 dfs)，入口必查 memo（只存不查=白存），守卫用 <= pre 拦等值否则相邻等值互走成环 SOE

带 pre 参数的 DFS 何时还能记忆化：看返回值是否与 pre 无关

memo 可用的判据只有一条：同一状态在不同调用下返回值是否恒定。写成 dfs(i,j,pre) 时，只要「pre 只用于提前拦截」——拦截分支 return 0 且不写 memo，通过拦截后算出的就是与 pre 无关的无条件值——(i,j) 仍是完整状态，memo 依然成立（本题等值被 <= pre 拦下，既保证严格递增又保证无环）。危险写法是把 memo 写在守卫之前，把「被前驱切断」的 0 固化进缓存。外层入口用 -1 当无约束初始值需先确认值域下界（本题 matrix>=0）。
