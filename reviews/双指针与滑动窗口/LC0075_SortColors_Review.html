我的解法

思路：标准荷兰国旗三指针。start 是 0 的边界（左边全是 0），end 是 2 的边界（右边全是 2）， mid 是扫描指针。遇到 0 与 start 交换后 start++、mid++； 遇到 2 与 end 交换后 end--、mid 停住回看；遇到 1 直接 mid++。 扫描指针从不重置，严格一趟。

时间 O(n) 一趟 空间 O(1) 原地修改

src/LC0075_SortColors.java提交区
public void sortColors(int[] nums) {
    int start = 0, end = nums.length - 1;
    int mid = start;
    while (mid <= end) {
        if (nums[mid] == 0) {
            int temp = nums[start];
            nums[start] = nums[mid];
            nums[mid] = temp;
            start++;
            mid++;
        } else if (nums[mid] == 2) {
            int temp = nums[end];
            nums[end] = nums[mid];
            nums[mid] = temp;
            end--;
        } else {
            mid++;
        }
    }
}

边界语义：mid 指向的元素未处理、正在检查；end 指向的元素未处理（闭区间 [mid, end]，所以用 mid <= end）；start 指向的元素未处理。 0 交换后 mid 前进是安全的（从 0 边界换进来的是 1）；2 交换后 mid 必须停住回看（换进来的可能是 0）。

解题过程

01 · 初版：左右双指针 + 中间扫描死循环超时 ▸

两端各用 start/end 比较，中间用 mid 扫描。当 nums[start] 和 nums[end] 都是 1、 中间也没有 0/2 可换时，没有任何指针移动，外层 while (start < end) 永不退出， 本地测试 20 秒超时。

教训：终止条件怎么写都行，但每一轮迭代必须保证有指针在推进。

02 · 改三指针，但推进逻辑有跳跃WA [0,2,1] ▸

改成 0/2 边界 + 扫描指针，但 0 分支 mid = start 重置 + 循环底部无条件 mid++， 叠加后 mid 直接跳过了未处理位置；2 分支交换后也没有停住回看换入值。 判题 WA：[0,2,1] 中下标 1 的 2 从未被检查，输出仍是 [0,2,1]。

03 · 修复推进逻辑，本地全过已解决 ▸

2 分支交换后不再无条件推进（由外层循环回看换入值），1 分支显式前进； 0 分支仍保留 mid = start 重置。回归用例 [0,2,1] 已补进本地测试， 本地全过并第二次提交 Accepted（89/89）；但 mid = start 的重置使最坏时间仍是 O(n²)。

04 · 第二次提交 Accepted，但最坏 O(n²)未达最优 ▸

第二次提交 Accepted（89/89），但 0 分支 mid = start 会把扫描指针 拉回边界重扫，最坏 O(n²)，不满足进阶「一趟扫描」。

05 · 重写为标准荷兰国旗，第三次提交 Accepted达成最优 ▸

去掉外层边界检查和 mid = start 重置：0 交换后 mid++、2 交换后 mid 停住回看、 1 直接前进。扫描指针从不后退，本地全过（含回归用例），第三次提交 Accepted（89/89）， 严格 O(n)/O(1)，达成进阶最优。

算法判定：标准荷兰国旗，已达最优

  • 时间复杂度 O(n)：扫描指针 mid 从不重置，每轮要么前进、要么交换后回看，严格一趟扫描。
  • 空间复杂度 O(1)：只用 start、end、mid 三个常量指针，满足常数空间。
  • 推进规则正确：0 交换后 mid++（从 0 边界换进来的是 1，安全前进）；2 交换后 mid 停住回看（换进来的可能是 0）；1 直接前进。
  • 边界覆盖：空、单元素、全相同、逆序、两种颜色、WA 回归用例 [0,2,1] 全部通过。
  • 结论：与标准解法一致，满足进阶「一趟扫描 + 常数空间」。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

三值原地分区这类题，双指针的职责要分清：边界指针只负责「放值」，扫描指针负责「遍历」，遍历的推进规则决定复杂度。

套路沉淀

本轮沉淀 1 条套路（lc-analyze/references/patterns.md）：

三路原地分区：0 与 2 各用一个边界指针，扫描指针负责遍历——遇到 0 交换后前进、遇到 2 交换后停住回看、遇到 1 前进；扫描指针每轮必进或回看，保证一趟 O(n) 且不死循环。

错误习惯复盘

  • 分区双指针死循环：没有覆盖无可交换的终态（两端都是 1 且中间全 1 时无进展）。
  • 分区交换后未回看换入值：扫描指针交换后直接前进，换入的 0/2 可能被困在中间。
  • 扫描指针推进逻辑有跳跃：mid = start 重置 + 底部无条件 mid++ 跳过未处理位置。
