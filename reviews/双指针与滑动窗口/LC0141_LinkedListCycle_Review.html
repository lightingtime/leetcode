141. 环形链表 (Linked List Cycle)

> https://leetcode.cn/problems/linked-list-cycle/

难度：Easy ｜ 分类：双指针与滑动窗口

标签：哈希表、链表、双指针

题目描述

给你一个链表的头节点 head ，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：pos 不作为参数进行传递 。仅仅是为了标识链表的实际情况。

如果链表中存在环 ，则返回 true 。 否则，返回 false 。

示例 1：

输入：head = [3,2,0,-4], pos = 1

输出：true

解释：链表中有一个环，其尾部连接到第二个节点。

示例 2：

输入：head = [1,2], pos = 0

输出：true

解释：链表中有一个环，其尾部连接到第一个节点。

示例 3：

输入：head = [1], pos = -1

输出：false

解释：链表中没有环。

提示：

链表中节点的数目范围是 [0, 104]

-105 5

pos 为 -1 或者链表中的一个 有效索引 。

① 与上一轮对比

  • 写法同为 Floyd 快慢指针判圈（时间 O(n)、额外空间 O(1)），但循环骨架重写了：
  • 一刷：先排除 head == null || head.next == null，再 while (fast.next != null && fast.next.next != null) 两跳推进，相遇就直接 return true。
  • 本轮：while (fast != null) 内先让 slow 走 1 步、fast 走 1~2 步并分别判空，相遇只 break，最后 return fast != null 统一出口。
  • 两种骨架都正确，但本轮多了一个隐含分支：fast 与 slow 同时为 null 时 fast == slow 也成立会 break（单节点无环 [7] 就是这种情况），靠最后 return fast != null 把它兜成 false。本次 7 个边界用例里的「单节点无环」正好压在这条线上，通过。

② 这次为什么能一次写对

  • 一刷一次 AC、无沉淀错误习惯，本轮凭记忆直接给出「快走 2、慢走 1、相等即有环」的核心，并且每一跳前都做了判空，没有出现 fast.next.next 的空指针。

③ 掌握度判定

  • 一次提交即 Accepted（29/29），全程无提示、无探讨 → 较强。

④ 下一步提醒

  • 回看时可把条件收进循环（while (fast != null && fast.next != null)）：这样「相遇」一定意味着真有环，不需要依赖 null == null 也成立的巧合，读代码的人不必自己推一遍边界。
  • 判圈只是第一步，142 环形链表 II 要求返回入环点，同一套快慢指针再加一段「从头出发的等速指针」即可。

LC0141_LinkedListCycle.java · 快慢指针提交区
    public boolean hasCycle(ListNode head) {
        ListNode fast = head, slow = head;
        while (fast != null && fast.next != null) {
            fast = fast.next.next;
            slow = slow.next;
            if (fast == slow) {
                return true;
            }
        }

        return false;
    }

LC0141_LinkedListCycle.java · 快慢指针 · 上一版提交区
public boolean hasCycle(ListNode head) {
        ListNode fast = head, slow = head;
        while (fast != null) {
            slow = slow.next;
            fast = fast.next;
            if (fast != null) {
                fast = fast.next;
            }
            if (fast == slow) {
                break;
            }
        }
        return fast != null;
    }

思路拆解

问题本质：判断链表是否有环。哈希表记录访问过的节点可行但 O(n) 空间；快慢指针让 fast 每次走 2 步、slow 走 1 步，只花 O(1) 空间。

关键设计：若有环，fast 相对 slow 每轮靠近 1 步，必在环内相遇；无环则 fast 先走到 null。判断相遇要在移动之后立刻比较（代码在 fast 前进后检查 fast==slow）。

边界：空链表或单节点直接返回 false；循环条件 fast.next!=null && fast.next.next!=null 保证 fast 前进前已有两个后继，不会空指针；自环节点也能正确检测（fast 先入环，slow 随后在环内被追上）。

复杂度：O(n) 时间（无环走 n/2 步；有环不超过 n+环长）、O(1) 空间，最优。
