239. 滑动窗口最大值 (Sliding Window Maximum)

> https://leetcode.cn/problems/sliding-window-maximum/

难度：Hard ｜ 分类：双指针与滑动窗口

标签：队列、数组、滑动窗口、单调队列、堆（优先队列）、区间最值查询

题目描述

给你一个整数数组 nums，有一个大小为 k 的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 k 个数字。滑动窗口每次只向右移动一位。

返回 滑动窗口中的最大值 。

示例 1：

输入：nums = [1,3,-1,-3,5,3,6,7], k = 3

输出：[3,3,5,5,6,7]

解释：

滑动窗口的位置 最大值

--------------- -----

[1 3 -1] -3 5 3 6 7 3

1 [3 -1 -3] 5 3 6 7 3

1 3 [-1 -3 5] 3 6 7 5

1 3 -1 [-3 5 3] 6 7 5

1 3 -1 -3 [5 3 6] 7 6

1 3 -1 -3 5 [3 6 7] 7

示例 2：

输入：nums = [1], k = 1

输出：[1]

时间 O(n)空间 O(k)内存 ≈ 137.5 MB用例 —

LC0239_SlidingWindowMaximum.java · 单调队列提交区
public int[] maxSlidingWindow(int[] nums, int k) {
        LinkedList<Integer> queue = new LinkedList<>();
        int[] ans = new int[nums.length - k + 1];
        int start = 0;
        int i = 0;
        while (i < nums.length) {
            // 入队前弹掉队尾比新元素小的：新元素更大且更晚，被弹者永远当不了最大值
            while (!queue.isEmpty() && nums[queue.peekLast()] < nums[i]) {
                queue.pollLast();
            }
            queue.offerLast(i);
            // 弹出过期队头：窗口是闭区间 [i-k+1, i]，队头下标 <= i-k 说明已滑出窗口
            while (!queue.isEmpty() && queue.peekFirst() <= i - k) {
                queue.pollFirst();
            }
            if (i - start + 1 == k) {
                ans[start] = nums[queue.peekFirst()];
                start++;
            }
            i++;
        }
        return ans;
    }

思路拆解

问题本质：每个固定长度 k 窗口的最大值。暴力 O(nk)；单调队列把每个窗口取最大值摊到 O(1)。

关键设计：双端队列存下标，从队头到队尾保持数值单调递减。新元素入队前弹掉队尾所有比它小的——那些元素比新元素更小且更早过期，永远不可能再成为最大值；入队后弹掉队头中已滑出窗口的下标（≤ i-k）；此时队头就是当前窗口最大值。窗口形成后（i≥k-1）每次记录。

边界：k=1 时每个窗口即单元素；k=n 只有一个窗口；形成窗口前的阶段只入队不记录；过期判断基于闭区间 [i-k+1, i]。

复杂度：O(n) 时间（每个下标至多入队出队一次）、O(k) 空间，最优。

二刷补强（2026-09-17）：入队前弹队尾必须是 while 连续弹，写成 if 只弹一次会留下比新元素更小、却排在新元素前面的残留下标，它挡在队头把真正的最大值顶掉。

  • 最小复现 [2,1,3]、k=3：i=0 入队 [0]；i=1（值 1）比队尾 2 小，入队得 [0,1]；i=2（值 3）需要连续弹掉下标 1 和 0 两个（值 1、2 都 < 3），只弹一个则队列变 [0,2]，队头下标 0 的值 2 被当成窗口最大值，输出 2（正确 3）。
  • 示例1 的 i=4 轮同理：队列已积压 [1,2,3]（值 3、-1、-3），新值 5 只弹掉下标 3 就入队，队头残留下标 1（值 3），第三个窗口输出 -1（应 5）。
  • 递增数组用例压不出这个 bug（每轮队列里只有一个元素，弹一次恰好够），必须构造「队内先积压 ≥2 个候选、之后才来更大值」的输入。

空间上二刷用 List 收集答案（一刷预开 int[n-k+1] 数组），两者同为 O(k)；时间仍是每个下标至多进出队一次 O(n)，已是本题下限（每个元素至少要读一次）。

解题过程

01 · 踩坑已记录

单调队列缺少过期队头淘汰：只弹队尾小值，未弹出已滑出窗口的队头下标，递减数组/全负数用例中旧最大值一直占着队头导致答案不变；读取答案前需先弹出 peekFirst() 小于窗口左边界的下标

02 · 踩坑已记录

过期淘汰边界差一：窗口左边界是 i-k+1（闭区间 [i-k+1, i]），队头下标 < i-k+1（等价 ≤ i-k）才算过期；写成 < i-k 会漏掉恰好滑出窗口的那一格，递减/全负数用例仍错

03 · 踩坑已记录

单调队列弹队尾用了 if 只弹一次：队列可能积压多个比新元素更小的候选，它们值更小又更早过期，必须用 while 连续弹到队尾不小于新元素；漏弹会让残留小值挡住真正的最大值——示例1 第三窗口输出 -1（应 5），最小回归 [2,1,3] k=3 输出 2（应 3）

套路沉淀

滑动窗口最值：单调队列（双端队列存下标）

队列值从队头到队尾单调递减、队头即最大；入队前弹掉队尾比新元素小的（更大且更晚，永无出头之日），读取答案前必须弹出 peekFirst() 小于窗口左边界的过期下标——弹队尾是比大小淘汰，弹队头是下标过期淘汰，两者缺一不可，一趟 O(n)
