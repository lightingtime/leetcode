我的解法

思路：单调队列（双端队列存下标）。队列值从队头到队尾单调递减，队头即当前窗口最大值。 入队前弹掉队尾比新元素小的（更大且更晚，永无出头之日）；读取答案前弹出滑出窗口的过期队头。 两个方向的弹出各管一件事，缺一不可。

时间 O(n) 空间 O(k)（队列最长 k） 每个元素入队出队各一次

src/LC0239_SlidingWindowMaximum.java提交区
public int[] maxSlidingWindow(int[] nums, int k) {
    LinkedList<Integer> queue = new LinkedList<>();
    int[] ans = new int[nums.length - k + 1];
    int start = 0;
    int i = 0;
    while (i < nums.length) {
        // 入队前弹掉队尾比新元素小的：新元素更大且更晚，被弹者永远当不了最大值
        while (!queue.isEmpty() && nums[queue.peekLast()] < nums[i]) {
            queue.pollLast();
        }
        queue.offerLast(i);
        // 弹出过期队头：窗口是闭区间 [i-k+1, i]，队头下标 <= i-k 说明已滑出窗口
        while (!queue.isEmpty() && queue.peekFirst() <= i - k) {
            queue.pollFirst();
        }
        if (i - start + 1 == k) {
            ans[start] = nums[queue.peekFirst()];
            start++;
        }
        i++;
    }
    return ans;
}

边界语义：当前窗口是闭区间 [i-k+1, i]，左边界 left = i - k + 1； 队头下标 < left（等价 <= i - k）说明已滑出窗口、已过期，读取答案前必须弹出。

解题过程

01 · 独立实现：单调队列主体思路正确 ▸

双端队列存下标、值单调递减、队头即最大；入队前弹队尾小值——主体一次搭对。

02 · 踩坑①：缺少过期队头淘汰答案不变 ▸

只弹队尾小值，没弹出滑出窗口的队头。递减数组 [4,3,2,1]（k=2）中下标 0 一直占着队头， 输出变成 [4,4,4]（应为 [4,3,2]）；全负数同理输出全 -1。

03 · 踩坑②：过期边界差一仍错一格 ▸

加上淘汰后写成 peekFirst() < i - k，漏掉下标恰好等于 i - k 的元素—— 它刚滑出窗口（窗口左边界是 i - k + 1）。递减数组变成 [4,4,3]，还是差一格。

04 · 修正：`<= i - k`，本地全过已解决 ▸

闭区间 [i-k+1, i] 的过期条件改为 peekFirst() <= i - k（等价 < i - k + 1）。 2 示例 + 7 边界（k=1、k=全长、全相同、递增/递减、全负数、大数）全部通过。

05 · 提交：一次 Accepted，单调队列最优完成 ▸

提交结果：Accepted，53/53 用例通过，第一次提交即成功。 O(n)/O(k)，每个元素入队出队各一次，达到最优。

算法判定：单调队列，已是最优

  • 时间复杂度 O(n)：每个元素最多入队一次、出队一次，均摊 O(1)。
  • 空间复杂度 O(k)：队列最多同时存 k 个候选下标。
  • 正确性：弹队尾管「比大小淘汰」，弹队头管「下标过期淘汰」，两者配合不重不漏。
  • 边界覆盖：k=1、k=全长、全相同、递增/递减、全负数、大数全部通过。
  • 结论：与标准解法一致，无需再优化。

套路沉淀

本轮沉淀 1 条套路（lc-analyze/references/patterns.md）：

滑动窗口最值：双端队列存下标、值单调递减；入队前弹队尾小值（比大小淘汰），读答案前弹队头过期下标（peekFirst() < i-k+1，等价 <= i-k），两者缺一不可，一趟 O(n)。

错误习惯复盘

  • 单调队列缺少过期队头淘汰：只弹队尾小值，旧最大值一直占着队头。
  • 过期淘汰边界差一：窗口左边界是 i-k+1，写成 < i-k 漏掉恰好滑出的一格。
