我的解法

思路：排序 + 固定第一个数 + 双指针夹逼。先排序，固定 nums[i] 为三元组最小值， 用 k（左）和 j（右）两个指针在剩余区间夹逼：三数和等于 0 就记录并前进 k； 小于 0 说明需要更大的数，k++；大于 0 说明需要更小的数，j--。 重复值用「保留第一次出现、跳过后续重复」的方式去重。

时间 O(n²) 空间 O(1) 排序后夹逼，去重不重不漏

src/LC0015_3sum.java提交区
public List<List<Integer>> threeSum(int[] nums) {
    List<List<Integer>> ans = new ArrayList<>();
    int i = 0, j = nums.length - 1;
    Arrays.sort(nums);
    while (i < j) {
        if (i > 0 && nums[i] == nums[i - 1]) {
            i++;
            continue;
        }
        int k = i + 1;
        j = nums.length - 1;
        while (k < j) {
            if (k > i + 1 && nums[k] == nums[k - 1]) {
                k++;
                continue;
            }
            if (nums[i] + nums[k] + nums[j] == 0) {
                List<Integer> list = new ArrayList<>();
                list.add(nums[i]);
                list.add(nums[k]);
                list.add(nums[j]);
                ans.add(list);
                k++;
            } else if (nums[i] + nums[k] + nums[j] < 0) {
                k++;
            } else {
                j--;
            }
        }
        i++;
    }
    return ans;
}

去重时机：固定点 i 在进入内层前跳过后续重复；夹逼点 k 在前进时跳过后续重复—— 都保留第一次出现的值，因此 [-1,-1,2] 这类需要两个相同值的组合不会被误杀，同一组合也不会重复输出。

解题过程

01 · 初版：固定两端 + 中间逐个扫本地失败 ▸

排序后固定两端 i、j，中间用 k 逐个扫描找零和； 扫完一轮再用 nums[i]+nums[k]+nums[j] 的符号决定移动 i 还是 j。

本地测试 2 个失败：

示例1 失败 ✗ 期望=[[-1, -1, 2], [-1, 0, 1]] 实际=[[-1, 0, 1]]
边界6 失败 ✗ 期望=[[-2, 0, 2]] 实际=[[-2, 0, 2], [-2, 0, 2], [-2, 0, 2]]

一个丢解，一个重复输出——两个症状，同一类根因。

02 · 根因①：去重方向写反逻辑错误 ▸

初版用 nums[i] == nums[i + 1] 跳过去重，跳掉的是重复组里靠前的那个值； 而正确去重应该跳过已经用过一遍的后续重复。方向反了的后果：

  • 示例 1 里 [-1,-1,2] 需要两个 -1 分别作固定点和夹逼点，第一个 -1 被跳过后就再也凑不出来；
  • 边界 6 里同一组合在不同 j 位置被重复加入三次。
03 · 根因②：移动决策引用了已失效的 k逻辑错误 ▸

内层 while (k < j) 结束后 k 一定等于 j， 此时 nums[i] + nums[k] + nums[j] 等于把 nums[j] 算了两次， 这个符号和任何三元组的和都无关——i/j 的移动完全脱离了三元组的和。

教训：双指针的移动依据必须来自两个指针当前指向的值；中间逐个扫完之后，偏大/偏小的信息已经丢失。

04 · 修正为排序 + 双指针夹逼，本地全过已解决 ▸

改为固定 nums[i]，剩下两个数用 k、j 从两端夹逼， 每步按三数和与 0 的大小只移动一侧；去重改为保留第一次出现（nums[i]==nums[i-1]、 nums[k]==nums[k-1] 时跳过）。3 个示例 + 7 个边界（空、不足三个、全相同、无解、大数、重复去重、多零）全部通过。

算法判定：排序 + 双指针夹逼，已是最优

  • 时间复杂度 O(n²)：排序 O(n log n)，固定 i 后双指针一趟 O(n)，合计 O(n²)； 本题可能输出的三元组数量本身可达 O(n²)，所以 O(n²) 已是下限。
  • 空间复杂度 O(1)：排序原地，双指针只占常数空间（不含答案本身）。
  • 去重正确：固定点与夹逼点都「保留第一次出现、跳过后续重复」， 既不丢 [-1,-1,2] 这类含相同值的合法组合，也不重复输出。
  • 边界覆盖：空数组、不足三个元素、全相同、无解、大数、多零等边界本地均已覆盖。
  • 结论：与本题标准解法一致，无需再优化。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

以后遇到同类题（三数之和变体、区间问题、回文验证等），第一步先想「排序后能否用双指针夹逼」，移动依据必须是两个指针当前的值。

套路沉淀

本轮沉淀 1 条套路（lc-analyze/references/patterns.md）：

排序后去重：保留重复值第一次出现，跳过后续重复——去重方向是跳过已经用过的值（nums[i]==nums[i-1] 时跳过）， 而不是跳过重复组里靠前的第一个；三数之和允许两个位置取相同值，所以第一次出现必须保留，双指针夹逼找到答案后还需跳过两端重复值。

错误习惯复盘

  • 去重方向写反：跳过重复值中靠前的第一个，而不是跳过后续重复，导致需要两个相同值的合法组合被丢弃，或同一组合重复输出。
  • 指针移动决策引用了已跑到边界的变量：内层扫描结束后 k==j，仍用 nums[i]+nums[k]+nums[j] 判断移动，同一元素被用了两次。
