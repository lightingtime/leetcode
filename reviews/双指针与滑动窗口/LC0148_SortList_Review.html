我的解法

思路：自顶向下归并排序。用快慢指针找到链表中点，把链表切成两半；递归排序两半后， 用 merge 把两个有序链表合并。区间用哨兵 tail 表示开区间 [head, tail)，head.next == tail 说明只剩一个节点，直接断开返回。

时间 O(n log n) 空间 O(log n)（递归栈） 比较排序下限即 O(n log n)

public ListNode sortList(ListNode head) {
    return sortList(head, null);
}

private ListNode sortList(ListNode head, ListNode tail) {
    if (head == null) {
        return head;
    }
    if (head.next == tail) {
        head.next = null;
        return head;
    }
    ListNode fast = head, slow = head;
    while (fast != tail) {
        slow = slow.next;
        fast = fast.next;
        if (fast != tail) {
            fast = fast.next;
        }
    }
    ListNode mid = slow;
    ListNode p1 = sortList(head, mid);
    ListNode p2 = sortList(mid, tail);
    return merge(p1, p2);
}

private ListNode merge(ListNode p1, ListNode p2) {
    ListNode head = new ListNode(0);
    ListNode dummy = head;
    while (p1 != null && p2 != null) {
        if (p1.val <= p2.val) {
            dummy.next = p1;
            p1 = p1.next;
        } else {
            dummy.next = p2;
            p2 = p2.next;
        }
        dummy = dummy.next;
    }
    if (p1 == null) {
        dummy.next = p2;
    } else if (p2 == null) {
        dummy.next = p1;
    }
    return head.next;
}

边界语义：tail 是哨兵边界，排序区间为开区间 [head, tail)， tail 指向的元素不属于本段；fast 探路到 tail（null 或边界节点）即停，slow 停在中间。 探路必须「先检查再前进」，避免 fast 变 null 后被解引用。

解题过程

01 · 独立实现：快慢指针找中点 + 递归归并分治 ▸

sortList(head, tail) 按哨兵区间切分：空段直接返回，单节点断开返回，否则快慢指针找中点、 递归两半、合并。链表 O(n log n) 排序的标准方向。

02 · 踩坑：探路先前进后判空NPE ▸

初版探路循环写成 fast = fast.next 后立刻访问 fast.next。 当 fast 原本在最后一个节点时，前进一步后 fast 变成 null，再访问 fast.next 就空指针崩溃： 本地测试全部用例报 Cannot read field "next" because "<local3>" is null。

03 · 修正：探路先检查再前进，本地全过已解决 ▸

把第二步前进的判空条件改成 if (fast != tail)：fast 前进后先确认不是 null 再走第二步， 循环条件在下一轮再检查是否结束。3 示例 + 6 边界（单元素、两元素、已排序、全相同、奇数长度、大数）全部通过。

04 · 提交：一次 Accepted，时间最优完成 ▸

提交结果：Accepted，30/30 用例通过，第一次提交即成功。 时间 O(n log n) 达到比较排序下限；但递归归并的空间是 O(log n)，未达到进阶要求的常数空间。

算法判定：时间已最优，空间未达进阶

  • 时间复杂度 O(n log n)：比较排序的下限就是 O(n log n)，链表归并排序达到该下限。
  • 正确性：哨兵开区间 [head, tail) 切分无重叠无遗漏；merge 用 dummy 统一头结点处理。
  • 边界覆盖：空链表、单节点、两元素、已排序、全相同、奇数长度、大数混合全部通过。
  • 空间 O(log n)：自顶向下递归的调用栈深度随链表长度增长，进阶要求常数空间，未完全达标。
宽泛最优思路（可自行重写后再次提交）

要达到常数空间，换成迭代式自底向上归并：不递归，而是从长度为 1 的子链表开始， 每轮把相邻的两段已排序子链表两两合并，子链表长度倍增（1 → 2 → 4 → …），直到整条链表有序。 空间只用于几个指针和 dummy，严格 O(1)。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

链表里的双指针是快慢指针：找中点、判环、删倒数第 N 个都靠它；探路的共同铁律是「先检查再前进」。

套路沉淀

本轮复用已收录套路（lc-analyze/references/patterns.md 第 1 条），并补了哨兵 tail 变体：

链表指针判空取舍：快慢指针跳 2 步防越界用 while (fast.next != null && fast.next.next != null)； 按哨兵 tail 截断找中点用 while (fast != tail && fast.next != tail)——探路必须先检查再前进，fast 变 null 后不可解引用。

错误习惯复盘
