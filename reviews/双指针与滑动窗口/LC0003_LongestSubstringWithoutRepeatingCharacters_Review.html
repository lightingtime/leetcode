我的解法

思路：滑动窗口 + 哈希表记位置，延迟结算。按实际代码结构： map 记录每个字符最后出现的位置，start 是窗口左边界。 你的设计里 max 只在两个点结算，if 分支不结算：

  • if 分支（字符不在当前窗口内）：只把位置写进 map，窗口继续扩展，不更新 max。
  • else 分支（遇到窗口内重复）：此时 i 是重复字符，结算被截断的窗口 [start, i-1]，长度 i - start；随后 start 跳到上次出现位置 +1，并更新 map。
  • 循环结束后：补结算最后一个窗口 [start, 串尾]，长度 s.length() - start。

时间 O(n) 空间 O(1)（字符集有限） 延迟结算结构 start 跳到重复位置+1

src/LC0003_LongestSubstringWithoutRepeatingCharacters.java提交区
public int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> map = new HashMap<>();
    int max = 0;
    int start = 0;
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (!map.containsKey(c) || map.get(c) < start) {
            map.put(c, i);
        } else {
            max = Math.max(max, i - start);
            start = map.get(c) + 1;
            map.put(c, i);
        }
    }
    max = Math.max(max, s.length() - start);
    return max;
}

关键点：else 结算的是不含 i 的窗口 [start, i-1]（长度 i - start）；结尾补 [start, 串尾]。两个结算点覆盖所有窗口。

算法判定：标准滑动窗口，已是最优

  • 时间复杂度 O(n)：每个字符至多进出窗口一次，右指针只前进；O(n) 是下限（每个字符都要看）。
  • 空间复杂度 O(1)：HashMap 存字符最后位置，字符集有限（字母/数字/符号/空格），不随 n 增长。
  • 正确性：延迟结算的两个结算点覆盖所有窗口；start 跳到重复位置 +1，窗口始终合法。
  • 结论：与题目标准解法一致，无需再优化。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

子串/子数组「无重复/满足条件」类问题首选滑动窗口：右指针扩展、左指针在条件被破坏时收缩。 哈希表在这里的作用是把「判断字符在不在窗口内」从 O(窗口长度) 降到 O(1)。

套路沉淀

闭区间计数：元素个数 = 间隔数 + 1——窗口/子数组长度计算通用，防 off-by-one。
滑动窗口结算时机与公式绑定：每步结算（先跳 start 再 i-start+1）或延迟结算（else 算 i-start，结尾补 n-start）；公式必须匹配结算时窗口的合法性。

错误习惯复盘

本轮记录 2 条错误习惯（已写入 progress.json，后续选题会提醒）：

滑动窗口长度更新时机与公式：max 只在遇到重复时更新，漏掉延伸到末尾的无重复窗口；长度公式取决于窗口是否合法——窗口 [start,i] 无重复时为 i-start+1，else 里 i 是重复字符时应按 [start,i-1] 算 i-start。
窗口长度公式先确认窗口合法性：else 分支里 i 是刚发现的重复字符，此刻 [start,i] 含重复、不是合法窗口，长度应为 i-start；只有把 start 跳到重复位置+1 之后，才能用 i-start+1。
