    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        ListNode p1 = headA, p2 = headB;
        while (p1 != p2) {
            p1 = p1 != null ? p1.next : headB;
            p2 = p2 != null ? p2.next : headA;
        }
        return p1;
    }

public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        if (headA == null || headB == null) {
            return null;
        }
        ListNode p1 = headA, p2 = headB;
        while (p1 != p2) {
            if (p1 != null) {
                p1 = p1.next;
            } else {
                p1 = headB;
            }
            if (p2 != null) {
                p2 = p2.next;
            } else {
                p2 = headA;
            }
        }
        return p1;
    }

思路拆解

问题本质：找两个链表的第一个相交节点。朴素做法先求长度差再对齐；更简洁的是双指针换链：p1 走完 A 后从 B 头继续，p2 走完 B 后从 A 头继续，两指针总路程相等（A+B 与 B+A），必然同时到达交点或同时走到 null。

关键设计：换链时机是「指针本身走到 null」时，而不是 next 为 null 时——只有指针为 null 才说明把整条链走完了。这样两指针在第二段路径上从相同剩余长度出发，交点处必然对齐。

边界：无交点时两指针同时为 null，返回 null（A+B 与 B+A 等长）；任一链表为空直接返回 null；有交点时第一次相遇处就是交点，直接返回。

复杂度：O(m+n) 时间、O(1) 空间，最优。本题历史踩坑就在换链时机上：在 next==null 时切换会导致无交点时死循环、有交点时错位。

套路沉淀

链表指针判空取舍：p != null vs p.next != null

p != null 允许指针走出链表（完整遍历/换链对齐，如 160 相交链表换链必须在指针为 null 时）；p.next != null 让指针停在最后一个节点或提前看一步（找尾追加、快慢指针跳两步防越界、删除节点找前驱）。取舍标准：这一步之后指针是否应该越界。

错误习惯复盘

守卫条件写反/冗余：空值处理后又用 (a != null || b != null) 提前 return，该条件恒真，导致所有非空输入直接返回 null（累计 1 次）

双指针换链时机：在 next==null（链表尾）时切到另一条链，而不是指针本身走到 null 时切换；无交点时指针永远到不了 null 而死循环，有交点时两指针对齐错位（累计 1 次）

双指针换链死代码：null 判断写在恒真位置（else 内 while 刚保证非空），且循环条件 while(p1!=null) 不允许指针为 null，换链永不执行，p1 走完即返回 null（累计 1 次）

双指针换链三要素在复习轮再次写错：① 先解引用 p.next 再判空 → 空链表直接 NPE；② 换链写在「比较之后」，两指针相位错乱，长度差极大时以 null==null 相遇返回 null；③ 循环先走一步才比较，漏掉第 0 步——两链从头共享或某链头即交点时，返回交点后面的节点。正确次序：每轮开头先判 p1==p2，再按「指针自己是否为 null」决定落到另一条链的头还是自己的 next。（同类问题第 2 次：一刷已记「在 next==null 时换链」）（累计 1 次）

复习提醒

★ 换链的两条次序是本写法的全部要害：每轮开头先 `p1 == p2`，推进时先问「自己是不是 null」——顺序反了不会编译报错，只会让空链 NPE、或让两指针以 `null == null` 收尾。
