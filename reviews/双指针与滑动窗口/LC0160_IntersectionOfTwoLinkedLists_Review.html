我的解法

思路：双指针换链消除长度差。p1 从 headA 出发、p2 从 headB 出发， 各自每次走 1 步，走到 null 时切到另一条链的头部继续走。有交点时，两指针走完相同总步数后在交点相遇； 无交点时，两指针各走完 m+n 步，最终同时停在 null，循环以 p1 == p2 结束。

时间 O(m+n) 空间 O(1) 指针为 null 时才换链 相遇或同为 null 结束

src/LC0160_IntersectionOfTwoLinkedLists.java提交区（格式化后）
public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
    if (headA == null || headB == null) {
        return null;
    }
    ListNode p1 = headA, p2 = headB;
    while (p1 != p2) {
        if (p1 != null) {
            p1 = p1.next;
        } else {
            p1 = headB;
        }
        if (p2 != null) {
            p2 = p2.next;
        } else {
            p2 = headA;
        }
    }
    return p1;
}

关键点：换链发生在「指针本身为 null」的那一步，循环条件用 p1 != p2 而不是 p1 != null。

算法判定：标准双指针换链，已是最优

  • 时间复杂度 O(m+n)：每个指针最多走 m+n 步；有交点时在交点相遇，无交点时同时走到 null。这是下限，因为至少要看清两条链的节点。
  • 空间复杂度 O(1)：只使用两个指针，优于哈希表记节点的 O(m+n) 空间方案。
  • 正确性：任一链表为空直接返回 null；换链时机、循环终止条件（p1 == p2，含同为 null）配套一致。
  • 结论：与题目标准解法一致，无需再优化。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

链表场景下的双指针有三个经典变体：快慢指针（判环/找中点）、首尾相向（回文）、以及本题的「换链对齐」—— 通过让两个指针走相同总步数来消除长度差。以后遇到两条链表找交点、找倒数第 k 个节点，先想双指针，别急着用哈希表。

套路沉淀 · 链表指针判空取舍

本轮踩坑凝练出的可复用套路（已收录进 lc-analyze/references/patterns.md）：

目的判断
完整遍历所有节点 / 让指针走出链表while (p != null)
找链表尾（追加节点、接另一条链）while (p.next != null) p = p.next;
双指针换链对齐（走完一条链再切）指针本身走到 null 时切换
快慢指针跳 2 步（判环/找中点）防越界while (fast.next != null && fast.next.next != null)
删除节点（需要前驱）停在目标前一个：while (cur.next != null && cur.next.val != target)
判断当前是否为最后一个节点p.next == null
取舍标准：这一步之后指针要不要越界。p != null 允许指针走出链表（遍历/换链对齐）； p.next != null 让指针停在链内或提前看一步（找尾、快慢指针防踏空、删除节点找前驱）。

错误习惯复盘

本轮记录 3 条错误习惯（已写入 progress.json，后续选题会提醒）：

守卫条件写反/冗余：空值处理后又用 (a != null || b != null) 提前 return，该条件恒真，导致所有非空输入直接返回 null。
双指针换链时机：在 next==null（链表尾）时切到另一条链，而不是指针本身走到 null 时切换；无交点时指针永远到不了 null 而死循环，有交点时两指针对齐错位。
双指针换链死代码：null 判断写在恒真位置（else 内 while 刚保证非空），且循环条件 while(p1!=null) 不允许指针为 null，换链永不执行，p1 走完即返回 null。
