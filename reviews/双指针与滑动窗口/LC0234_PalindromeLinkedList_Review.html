我的解法

思路：快慢指针找中点 + 栈比较后半段。快指针每次走 2 步、慢指针走 1 步， 走完后 slow 停在链表中点附近；后半段节点值依次入栈，再从头节点开始与栈顶逐一对齐比较。 用 fast 是否停在最后一个节点区分链表长度奇偶，奇数时先跳过中点再入栈。

时间 O(n) 空间 O(n)（栈存后半段） 快慢指针防越界 fast 位置判奇偶

public boolean isPalindrome(ListNode head) {
    if (head == null) {
        return false;
    }
    ListNode fast = head, slow = head;
    while (fast != null && fast.next != null) {
        fast = fast.next.next;
        slow = slow.next;
    }
    ListNode p1 = slow;
    Stack<Integer> stack = new Stack<>();
    if (fast != null) {
        slow = slow.next;
    }
    while (slow != null) {
        stack.push(slow.val);
        slow = slow.next;
    }
    fast = head;
    while (fast != p1 && !stack.isEmpty()) {
        if (fast.val != stack.peek()) {
            return false;
        }
        stack.pop();
        fast = fast.next;
    }
    return stack.isEmpty();
}

关键点：快慢指针走完后，fast == null 是偶数长度、fast 停在最后节点是奇数长度（要先跳过中点）。

算法判定：思路正确，时间最优，空间未达进阶要求

  • 时间复杂度 O(n)：每个节点至多访问常数次，O(n) 是下限，已最优。
  • 空间复杂度 O(n)：栈最多存后半段（约 n/2）个节点值；进阶要求 O(1)。
  • 正确性：奇偶长度分别处理；奇数时跳过中点，比较范围正确。
  • 宽泛最优思路：快慢指针找中点后，把后半段「原地反转」再与前半段比较，可以省掉栈、把空间降到 O(1)。想挑战的话可以自己重写后再次提交。

分类提醒 · 双指针与滑动窗口

看到有序数组/子数组/子串问题，先想排序后双指针或滑动窗口，把 O(n²) 降到 O(n)。

链表双指针的经典组合是「快慢指针 + 反转/栈」：快慢指针负责找中点/判环，反转或栈负责「从尾部往回看」。 这题用栈是 O(n) 空间的简单版，进阶版把「往回看」交给原地反转，空间就省下来了。

套路沉淀

本轮涉及两条已入库套路（lc-analyze/references/patterns.md）：

链表指针判空取舍：p != null 允许指针走出链表；p.next != null 停在链内/提前看一步。快慢指针跳 2 步用 fast.next != null && fast.next.next != null 防越界。
快慢指针找中点后的奇偶判定：fast 为 null → 偶数，slow 即后半段开头；fast 停在最后节点 → 奇数，先跳过中点再比较。
