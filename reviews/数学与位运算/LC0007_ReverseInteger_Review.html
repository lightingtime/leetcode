7. 整数反转 (Reverse Integer)

题目描述

给你一个 32 位的有符号整数 x ，返回将 x 中的数字部分反转后的结果。

如果反转后整数超过 32 位的有符号整数的范围 [−231,  231 − 1] ，就返回 0。

假设环境不允许存储 64 位整数（有符号或无符号）。

示例 1：

输入：x = 123

输出：321

示例 2：

输入：x = -123

输出：-321

示例 3：

输入：x = 120

输出：21

示例 4：

输入：x = 0

输出：0

写法 1 · 逐位弹出 + 溢出预判

LC0007_ReverseInteger.java · 逐位弹出 + 溢出预判提交区
    public int reverse(int x) {
        int ans = 0;
        while (x != 0) {
            if (ans > Integer.MAX_VALUE / 10 || (ans == Integer.MAX_VALUE / 10 && x % 10 > Integer.MAX_VALUE % 10)) {
                return 0;
            } else if (ans < Integer.MIN_VALUE / 10 || (ans == Integer.MIN_VALUE / 10 && x % 10 < Integer.MIN_VALUE % 10)) {
                return 0;
            }
            ans = ans * 10 + x % 10;
            x /= 10;
        }
        return ans;
    }

思路拆解

1. 问题本质与解法选择

反转十进制整数 = 反复「弹出最低位 → 拼到结果尾部」。难点不在反转本身而在溢出：题目限定 32 位有符号整数，且环境不允许 64 位整数，所以不能用 long 兜底再比较，必须在拼装前用数学关系预判越界。逐位弹出是数位处理的标准套路，正负统一处理：Java 中 x % 10 对负数返回非正余数、x / 10 向零取整，恰好配合。

2. 关键设计决策

  • 状态：ans 保存已反转部分；每轮 digit = x % 10 取最低位，x /= 10 去掉最低位。
  • 溢出预判（在拼装 ans*10 + digit 之前做，拼装后检查就已溢出成错误值）：
  • 正方向：ans > MAX/10 必溢出；ans == MAX/10 时再看 digit > MAX % 10（即 > 7）。
  • 负方向：ans < MIN/10 必溢出；ans == MIN/10 时再看 digit < MIN % 10（即 < -8）。
  • 理由：ans*10 + digit 越界 ⇔ 合法 int 内无法表示，等价于上面两条判断。
  • 终止条件：x == 0，所有位弹出完毕。

3. 边界与细节

  • x = Integer.MIN_VALUE：最低位是 -8（负数 % 得非正余数），反转后远超下限 → 返回 0。
  • 末尾 0：120 → 21，ans 从 0 开始拼，反转天然丢弃前导 0。
  • x = 0 与单数字：循环一次/直接结束，返回自身。
  • 等号分支最易漏：ans 恰好等于 MAX/10（214748364）或 MIN/10（-214748364）时必须继续比对最后一位，不能直接放行。

5. 复杂度与最优性论证

  • 时间 O(log₁₀|x|)：每个十进制位常数次操作。下界论证：反转必须读取全部数位，任何算法至少 Ω(log₁₀|x|)，此解达到下界，最优。
  • 空间 O(1)：只用一个 int ans。至少需要一个累加器，无法低于常数空间，已达下限。
  • 对比「用 long 拼完再判断」：在「不允许 64 位整数」约束下不成立；本解纯 32 位运算完成，是题意下的正确且最优写法。

套路沉淀

数位弹出 + 拼装前溢出预判

逐位反转/拼接时，若题目禁止 64 位中间量，就用 ans 与 MAX/10（MIN/10）比较：先比大小，相等再比最后一位 digit 与 MAX%10（MIN%10）；预判必须在拼装 ans*10+digit 之前做。适用于 reverse-integer、字符串转整数等数位拼接题。
