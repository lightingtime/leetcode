public int reverseBits(int n) {
        int rev = 0;
        for (int i = 0; i < 32; i++) {
            rev |= (n & 1) << (31 - i);
            n >>>= 1;
        }
        return rev;
    }

思路拆解

问题本质与解法选择理由

把 32 位整数的位模式首尾颠倒：第 i 位（0-based，最低位）换到第 31-i 位。题面写「有符号」但实际约束是无符号范围（0 ≤ n ≤ 2^31-2 且 n 偶），Java 用 int 表示，位操作与符号无关，按位处理即可。

最直观的解法是逐位搬运：循环 32 次，每次从 n 取出最低位，放到结果的对称位置。固定 32 轮，O(1) 时间。

关键设计决策

决策写法理由
取最低位n & 1掩码取当前最低位
放到对称位`rev= (n & 1) << (31 - i)`第 i 轮取出的是原第 i 位，目标位是 31-i
前进到下一高位n >>>= 1无符号右移 1 位，下一轮取原第 i+1 位
循环 32 次for (i = 0; i < 32; i++)必须固定 32 轮：n 变小后前面的 0 也要搬到高位，不能提前退出

为什么必须用 >>> 而不是 >>：Java int 有符号，n >> 1 在最高位为 1 时会用符号位填充高位，导致后续 n & 1 取到的不是原低位。n >>> 1 无符号右移，高位补 0，才能正确逐位取出。题目保证 n 非负时影响有限，但标准写法必须用 >>>。

边界与细节

  • 约束范围 0..2^31-2 且 n 偶：最高位 bit31 实际恒为 0，反转后最低位 bit0 恒为 0——但实现不受影响，仍处理全部 32 位。
  • 0 → 0；2（bit1）→ 0x40000000（bit30）。
  • 全 1 前缀 0x7FFFFFFC → 反转 0x3FFFFFFE（示例2 验证）。
  • reverse 两次必还原：边界6 用 reverse(reverse(2))==2 验证往返性质。

具体 case 逐层推演

n=2（位模式 ...0010，bit1=1）：

  • i=0：n&1=0，rev|=0<<31=0；n>>>1 → 1
  • i=1：n&1=1，rev|=1<<30=0x40000000；n>>>1 → 0
  • i=2..31：n&1 恒 0，rev 不变
  • 返回 0x40000000 ✓（原 bit1 搬到 bit30）

n=0x7FFFFFFC（示例2，2147483644）：

  • bit1..30 全 1，bit0=bit31=0；反转后 bit0..29 全 1，bit30=bit31=0 → 0x3FFFFFFE = 1073741822 ✓

复杂度与下限论证

  • 时间 O(1)：固定 32 轮，与输入无关。32 位宽是常数，任何正确解法至少要处理每一位，O(32) 已是下限；分治掩码（5 轮 O(1)）是常数上的优化，同一复杂度级。
  • 空间 O(1)：仅一个 int 累加器。
