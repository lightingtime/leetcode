public void rotate(int[][] matrix) {
        int n = matrix.length;
        for (int i = 0; i < n / 2; i++) {
            for (int j = 0; j < n; j++) {
                int temp = matrix[i][j];
                matrix[i][j] = matrix[n - i - 1][j];
                matrix[n - i - 1][j] = temp;
            }
        }

        for (int i = 0; i < n; i++) {
            for (int j = 0; j <= i; j++) {
                int temp = matrix[i][j];
                matrix[i][j] = matrix[j][i];
                matrix[j][i] = temp;
            }
        }
    }

思路拆解

### 问题本质与解法选择

  • 顺时针旋转 90° 本质是把矩阵做一次坐标映射，可以拆成两次对称变换的组合：先上下翻转（反转行序），再沿主对角线转置。
  • 选择对称变换组合的原因：对称操作是「成对交换」，天然可以用 O(1) 额外空间实现，满足题目原地约束；比直接按四轮换位写圈层循环更直观、不易错。

### 关键设计决策

  • 上下翻转：i 从 0 到 n/2-1，把第 i 行与第 n-1-i 行逐列交换；奇数 n 的中间行不动。
  • 转置：遍历下三角（j <= i），交换 (i,j) 与 (j,i)；上三角的每对元素会在遍历到对称位置时被交换，因此遍历范围必须只覆盖半边，否则同一对会被交换两遍、恢复原状。对角线自交换无害。
  • 两步都只用一个临时变量完成交换。

### 具体 case 推演

2x2：[[1,2],[3,4]]

  1. 上下翻转：i=0 交换行 0 与行 1 → [[3,4],[1,2]]
  2. 转置下三角：
  • (0,0) 自交换无变化；
  • (1,0) 与 (0,1) 交换 → [[3,1],[4,2]]
  1. 结果 [[3,1],[4,2]] ✓

3x3 示例：[[1,2,3],[4,5,6],[7,8,9]]

  1. 上下翻转：i=0 与 i=2 整行交换，i=1 不动 → [[7,8,9],[4,5,6],[1,2,3]]
  2. 转置下三角：依次交换 (1,0)↔(0,1)、(2,0)↔(0,2)、(2,1)↔(1,2) → [[7,4,1],[8,5,2],[9,6,3]] ✓

若第二步误用左右翻转，得到的是 180°；若转置遍历了全部格子，每对元素交换两遍会回到原矩阵。

### 边界与细节

  • n=1：两个循环的区间都为空，矩阵保持原样，正确。
  • 上下翻转的 i 范围只到 n/2-1：若越界到下半区，会把已换好的行再换回去。
  • 转置只遍历下三角：j 从 0 到 i；若 j 遍历整个行，每对元素被交换两次。
  • 值范围 ±1000 只做交换不做算术，无溢出问题。

### 复杂度分析与最优性论证

  • 时间 O(n^2)：每个元素参与常数次交换；下界为 Ω(n^2)——旋转后每个位置都承载新值，必须读写全部 n^2 个元素，因此 O(n^2) 最优。
  • 空间 O(1)：仅临时变量，满足题目「原地」硬性约束。
