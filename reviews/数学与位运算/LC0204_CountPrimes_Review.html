LC0204_CountPrimes.java · 静态埃氏筛+前缀和查表提交区
    static boolean[] isComposite = new boolean[5000001];
    static int[] pre = new int[5000001];
    static {
        for (int i = 2; i < 5000001; i++) {
            if (isComposite[i]) {
                continue;
            }
            if ((long) i * i < 5000001) {
                for (int j = i * i; j < 5000001; j += i) {
                    isComposite[j] = true;
                }
            }
        }
        for (int i = 2; i < 5000001; i++) {
            pre[i] = pre[i - 1] + (i - 1 >= 2 && !isComposite[i - 1] ? 1 : 0);
        }
    }
    public int countPrimes(int n) {
        return pre[n];
    }

写法 2 · 线性筛（欧拉筛）+前缀和查表

时间 O(n) 预处理 / O(1) 查询空间 O(n)内存 ≈ 64.5 MB用例 385/385

LC0204_CountPrimes.java · 线性筛（欧拉筛）+前缀和查表提交区
    static boolean[] isComposite = new boolean[5000001];
    static int[] primes = new int[348513];
    static int[] pre = new int[5000001];
    static {
        int pc = 0;
        for (int i = 2; i < 5000001; i++) {
            if (!isComposite[i]) {
                primes[pc++] = i;
            }
            for (int j = 0; j < pc && (long) i * primes[j] < 5000001; j++) {
                isComposite[i * primes[j]] = true;
                if (i % primes[j] == 0) {
                    break;
                }
            }
        }
        for (int i = 2; i < 5000001; i++) {
            pre[i] = pre[i - 1] + (!isComposite[i - 1] && i - 1 >= 2 ? 1 : 0);
        }
    }
    public int countPrimes(int n) {
        return pre[n];
    }

计数质数：写法1 静态埃氏筛+前缀和（AC 385/385）；写法2 线性筛欧拉筛 O(n) 预处理，每合数仅被最小质因子筛一次，本地验证 17 个抽样全过

思路拆解

1. 问题本质与解法选择

本质：统计小于 n 的质数个数，n ≤ 5×10⁶。逐个试除是 O(n√n) 必超时；埃氏筛「遇到质数就把它的倍数标成合数」，O(n log log n)。本场景的特殊性：力扣 385 个用例在同一个进程内依次调用 countPrimes，若每次调用都全量筛，总时间 = 385 × 单次筛（实测单次 12ms 但累计超时，两次 TLE 均为此因）——所以要用静态缓存把筛摊平成一次预处理，查询降到 O(1)。

2. 关键设计决策

  • 静态字段 + 静态块：isComposite（合数标记）和 pre（前缀计数）是 static，类加载时初始化一次，函数结束不清空，跨 385 次调用复用。
  • 一次筛满题目上限：数组长度 5000001（覆盖 n 最大 5×10⁶），任何 n 都能直接查表；避免「n 变大就重建」在 n 递增用例下重复筛。
  • 埃氏筛剪枝：内层从 i*i 起跳（2i..(i-1)*i 含更小因子，早被标过）；外层无需专门限制，j=i*i; j<n 在 i*i>=n 时天然空转。
  • 前缀和语义：pre[i] = 小于 i 的质数个数，递推 pre[i] = pre[i-1] + (i-1 是质数 ? 1 : 0)；必须加守卫 i-1 >= 2——1 从未被筛法标记（筛从 2 开始），不排除会全局多算 1。
  • 查询：return pre[n]，n=0 时 pre[0]=0 天然正确，无越界。

3. 边界与细节

  • n ≤ 2：pre[2]=0（小于 2 无质数）。
  • n 本身是质数：pre[n] 不含 n——如 n=4999999（质数）时 pre=348512，不把 4999999 计入。
  • 静态块只在类加载执行一次；本地多个 main 调用共享同一份筛结果。
  • i*i 溢出：n 上限 5e6 时 i ≤ √n ≤ 2236，i*i 远小于 int 上限，安全（写法 A 中的 (long) 防御可省）。

5. 复杂度与最优性

  • 预处理：O(N log log N)（N = 5×10⁶），空间 O(N)；单次查询 O(1)。
  • 最优性：面对多查询场景，把全量筛摊平成一次预处理是正确做法——总耗时从「385 × 单次筛」降到「1 次筛 + 384 次查表」，达到该场景下最优；单次查询下界就是 O(1)（查表）。

---

写法 2（线性筛 / 欧拉筛，O(n) 预处理）：每个合数只被它的最小质因子筛一次

1. 问题本质与解法选择

埃氏筛的冗余：合数 12 会被质数 2 和 3 各标一次，标记总数 = Σ_{p≤√n} n/p ≈ n log log n，不是线性。线性筛保证每个合数恰好被它的最小质因子标记一次，标记总数 = 合数个数 = O(n)，是筛法的渐进最优。

2. 关键设计决策

  • 结构：primes[] 存已发现质数；遍历 i 时未标记则入表；内层用质数表标记 i × primes[j]。
  • 灵魂 break：i % primes[j] == 0 立即 break——此时 primes[j] 已是 i 的最小质因子，i × 更大的质数 的最小质因子仍是 primes[j]，会由更合适的 i' 筛掉，现在标就是重复标记。正是这条保证线性。
  • 边界守卫：(long) i * primes[j] < 5000001 防 i×p 溢出 int。
  • primes 数组容量：π(5×10⁶) = 348513，恰好够存。
  • 前缀和与查询：同写法 1，pre[i] = 小于 i 的质数个数，查询 O(1)。

3. 边界与细节

  • 静态块初始化一次，跨 385 个用例复用（同写法 1 的多查询场景优化）。
  • i 从 2 扫到 5000000；i=2 时内层 2×2=4 标记后 2%2==0 break。
  • 质数本身：!isComposite[i] 入表，与标记互不干扰。
  • 前缀和守卫 i-1 >= 2 排除 1（1 未被筛但非质数）——同写法 1 的坑。

4. 具体 case 推演

5. 复杂度与最优性

  • 预处理 O(n)：每个合数恰好标记一次；空间 O(n)（isComposite + primes + pre）。
  • 查询 O(1)。
  • 最优性：标记次数 = 合数个数是下界（每个合数至少要标一次），线性筛达到该下界，是筛法的渐进最优；相比埃氏筛 O(n log log n)，渐进更优、常数略大，本题两者都能过。
