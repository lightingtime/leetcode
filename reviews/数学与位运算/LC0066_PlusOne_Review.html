66. 加一 (Plus One)

> https://leetcode.cn/problems/plus-one/

难度：Easy ｜ 分类：数学与位运算

标签：数组、数学

题目描述

给定一个表示 大整数 的整数数组 digits，其中 digits[i] 是整数的第 i 位数字。这些数字按从左到右，从最高位到最低位排列。这个大整数不包含任何前导 0。

将大整数加 1，并返回结果的数字数组。

示例 1：

输入：digits = [1,2,3]

输出：[1,2,4]

解释：输入数组表示数字 123。

加 1 后得到 123 + 1 = 124。

因此，结果应该是 [1,2,4]。

示例 2：

输入：digits = [4,3,2,1]

输出：[4,3,2,2]

解释：输入数组表示数字 4321。

加 1 后得到 4321 + 1 = 4322。

因此，结果应该是 [4,3,2,2]。

示例 3：

输入：digits = [9]

输出：[1,0]

解释：输入数组表示数字 9。

加 1 得到了 9 + 1 = 10。

因此，结果应该是 [1,0]。

public int[] plusOne(int[] digits) {
        for (int i = digits.length - 1; i >= 0; i--) {
            if (digits[i] == 9) {
                digits[i] = 0;
            } else {
                digits[i] += 1;
                return digits;
            }
        }
        int[] ans = new int[digits.length + 1];
        ans[0] = 1;
        return ans;
    }

思路拆解

问题本质与解法选择理由

大整数以高位到低位数组表示，加 1 本质是最低位的手算加法 + 进位传播。不能把整个数组转成整数相加（长度可达 100，远超 long 范围），必须逐位模拟进位。从最低位（数组末尾）向前处理，遇 9 会进位（9+1=10 → 本位 0、进 1），遇非 9 加 1 后进位终止，可提前返回。

关键设计决策

决策写法理由
反向遍历for (i = len-1; i >= 0; i--)低位在数组末尾，模拟手算从个位开始
遇 9 置 0 继续digits[i] = 09+1=10，本位归 0 且进位继续向左传播
遇非 9 +1 返回digits[i] += 1; return digits进位链在此终止，剩余高位不变，原地返回
全 9 扩容循环走完未返回 → new int[len+1]，首位 1全部进位后最高位溢出（999→1000）

边界与细节

  • 单元素非 9：[4]→[5]，第一步就返回。
  • 部分 9 进位：[1,9,9] → 末位 9→0，中位 9→0，首位 1→2 返回 [2,0,0]。
  • 全 9 扩容：[9,9,9] 全部置 0，循环走完，扩容 [1,0,0,0]；100 位全 9 扩到 101 位。
  • 含 0 数字：[1,0,0]→[1,0,1]，末位 0 非 9 直接 +1。
  • 无前导 0 约束下，扩容只可能发生在「全 9」，首位必为 1。

具体 case 逐层推演

[1,9,9]：

  • i=2：digits[2]=9 → 置 0，数组 [1,9,0]
  • i=1：digits[1]=9 → 置 0，数组 [1,0,0]
  • i=0：digits[0]=1 非 9 → +1=2，返回 [2,0,0] ✓

[9,9]：

  • i=1：9 → 0，[9,0]
  • i=0：9 → 0，[0,0]
  • 循环结束，扩容 new int[3] 首位 1 → [1,0,0] ✓

复杂度与下限论证

  • 时间 O(n)：最坏全 9 需遍历整个数组（n 次置 0）+ O(n) 扩容；平均提前返回更快。任何解法至少要处理从末尾开始的连续 9 段才能确定结果，Ω(n) 即下限。
  • 空间 O(1)：非全 9 原地修改，无额外存储；仅全 9 时需要新数组（结果本身就要多一位），这是必要开销。
