## 18. 递归反转链表：新头 vs 原后继（head.next.next = head）

出处：LC0206 反转链表（递归写法）

递归版 `reverseList(head.next)` 返回的是「反转后子链表的**新头**」，即原链表的尾节点；
它是最终要返回的答案，不是负责接回头部的那一端。

错误写法：`ListNode newHead = reverseList(head.next); newHead.next = head;` —— 把 head 接到了新头后面，
中间节点全部丢失（例：[1,2,3,4,5] 输出 [5,1]）。

正确接回：让「head 原来的后继」（现在位于反转后子链表的**尾部**）指回 head，即
`head.next.next = head; head.next = null;`，最后返回新头。

要点：分清两个角色——返回值（新头，最终返回）与 `head.next`（原后继，负责指回头部）；
递归层里能访问到原后继的唯一途径就是 `head.next`，因为它在反转后的子链表里已经被移到尾部。

## 19. LRU 哈希表+双向链表：两结构必须同步增删，哨兵判身份不判值

出处：LC0146 LRU 缓存

`map` 负责 O(1) 定位节点，双向链表负责维护使用顺序，两者必须同步更新，漏一步就会整个错位：

| 操作 | map | 链表 | size |
| --- | --- | --- | --- |
| 插入新 key | `map.put(key, node)` | 新节点插到 head 后 | `size++` |
| 命中 get / 更新已有 key | 不变（节点不变） | 先 cut 再 moveToHead | 不变 |
| 容量满时淘汰 | `map.remove(被逐出节点的 key)` | cut 掉 tail 前节点 | `size--` |

要点：

- 节点里必须存自己的 key，否则淘汰时不知道从 map 删谁。
- `size` 必须随插入/淘汰同步增减；只初始化不维护，`size == capacity` 永远不会成立，淘汰逻辑等于不存在。
- 哨兵节点用身份判断（`cur == head || cur == tail`），不要用 `value == null` 之类的值特征猜，值会变、身份不会变。

## 49. BFS 层序遍历：size 划层 + 空子节点不入队

出处：LC0116 填充每个节点的下一个右侧节点指针

树的 BFS 层序遍历（连接同层节点、逐层处理等）：

- 每轮 while 前记录 `size = queue.size()`，只处理 size 个节点——队列里会混着下一层，size 是本层的边界。
- 同层串联用 `pre` 指针：弹出 node 后 `pre.next = node`，层首的 pre 为 null、保持不连。
- **空子节点不入队**：叶子节点的 left/right 是 null，直接 offerLast 会把 null 混进队列，下一轮 size 计数错乱，pollFirst 取出 null 后访问 `node.left` 直接 NPE。
- 对比：非树的普通 BFS（图）节点可能重复入队需要 visited；树的 BFS 天然无环，只需管好「入队内容非空」。

要点：BFS 遍历树时先问「要不要把 null 子节点放进去」，一律不入队最安全；层序处理先问「这一层的边界怎么划」，size 快照最稳。

## 50. 复制带引用结构：一原节点一克隆，先查后建

出处：LC0138 随机链表的复制

复制带 next/random 等引用的结构（深拷贝链表/图）：

- 用 `Map<原节点, 新节点>` 保证一一对应；创建前先 `map.get` 判存在，**已存在则复用、不存在才 new**。
- 反例：先无条件 `new` 再 `put` —— 同一原节点被创建两次（一次作为被 next/random 引用的对象、一次作为主节点），
  `put` 覆盖旧登记，旧节点成孤儿且其 random/next 未设置（示例 `[[1,1],[2,1]]` 中 B 被建两次）。
- 或两遍法：第一遍遍历建全量映射（原→新），第二遍只连 next/random（全部从 map 取），天然唯一。

要点：任何「新结构 = 旧结构的复制」题，先回答「同一旧节点会不会被多次创建」，用 map 判重保证唯一。

## 51. 无前驱删除：后继值覆盖当前节点再跳过后继

出处：LC0237 删除链表中的节点

只给待删节点、拿不到前驱（无 head）时，不能用「前驱.next = 后继」：

- `node.val = node.next.val; node.next = node.next.next;` —— 后继的值顶替当前节点，再跳过后继，等效删除。
- 前提：node 不是末尾节点（必有后继可借）；值唯一时更安全（覆盖不产生歧义）。
- 两步缺一不可：只改值会残留后继节点（长度不减），只改指针会残留当前值。
- 对比：正常删除（有前驱）停在目标前一个；无前驱删除直接改 node 本身。

要点：删除类题先确认「能不能拿到前驱」；拿不到就借后继顶替，O(1) 完成。

## 52. 链表拆链/重连：先保存 next 再挂载，或跳 next.next 原地重连

出处：LC0328 奇偶链表

原地拆分/重连链表（奇偶分组、分区等）时：

- 不能在遍历的同时覆盖原 next：`eP.next = p` 会把原链表「指向 p 的边」改掉，遍历前进仍依赖原 next，
  两套引用打架；被拆出的节点若不断开，奇偶交替处成环（偶数长度碰巧无环、奇数长度遍历 OOM）。
- 方向① 拆链法：遍历时先 `next = p.next` 保存，挂载到哨兵链后再 `p.next = null`（或管理好），沿保存的 next 前进。
- 方向② 原地交替法：`odd.next = odd.next.next; even.next = even.next.next` 各跳两步，不破坏遍历路径，最后拼尾。
- 共性：任何「边遍历边改 next」都要先想清楚**遍历前进的路径是否被自己破坏**。

要点：改链表 next 前先自问「改的是谁指向谁的边，谁还依赖这条边前进」。
