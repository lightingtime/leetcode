## 22. BST 校验：上下界递归时，未收紧的一侧要继承而非重置为 ±∞

出处：LC0098 验证二叉搜索树

递归 helper 带 `(node, upper, lower)`，验证时：

- 左子树：`helper(left, node.val, lower)` —— 只收紧 upper，lower **继承**；
- 右子树：`helper(right, upper, node.val)` —— 只收紧 lower，upper **继承**。

错误写法：把没变化的一侧重置成 `Long.MIN_VALUE` / `Long.MAX_VALUE`，等于丢掉祖先约束
（例：根 10 → 右子树 15 → 15 的左子树 6，若 lower 被重置为 MIN，就漏掉 `6 > 10` 的检查，误判合法）。

要点：递归下降时，只有「靠近根的一侧」边界收窄，另一侧是当前路径上祖先给的约束，必须原样传下去。

## 23. 序列化/反序列化顺序一致性 + 队列栈进出配对

出处：LC0297 二叉树的序列化与反序列化

| 配对 | 语义 |
| --- | --- |
| `offerLast` + `pollFirst` | 队列（FIFO），先入先出，层序 |
| `offerLast` + `pollLast` | 栈（LIFO），后进先出，右子树优先的深搜序 |
| `offerFirst` + `pollLast` | 队列（FIFO），等价层序 |

要点：用 Deque 当队列时，「进」和「出」必须在两端配对；`offerLast` 配 `pollLast` 只是能跑，但顺序变成了栈序。
序列化与反序列化是「编码 / 解码」一对，字符串的顺序约定必须完全一致——层序序列化就按层序重建（先左后右），
否则两端各按各的顺序理解，还原出的树结构错位（例：正确层序 1,2,3 被序列化成右子树先行的 1,3,2，反序列化按左先读就串位）。

验证法：固定一棵树，看 `deserialize(serialize(t))` 是否与原树逐节点一致；失败时先打印 serialize 输出，人工按层序核对第几个 token 应该是谁。

## 39. 计数/收集时机绑定终点：别把判断下放到子递归入口

出处：LC0437 路径总和 III（双重 DFS 计数）

| 场景 | 正确做法 |
| --- | --- |
| 枚举「以 X 为终点的向下路径」并计数 | 判断绑定在「把 X.val 计入路径和」之后，每节点恰好检查一次 |
| 新起点 / 顶层入口的初始状态 | cur=0 不代表任何真实路径，不能拿来和 target 比较 |

要点：

- 把 `cur + X.val == target` 的判断放到**进入左右孩子时**执行，等于对同一条「以 X 为终点」的路径检查两次（左分支一次、右分支一次），计数变成 2 倍（示例 3→6）。
- 入口处 `cur=0` 是「路径还没包含任何节点」的初始状态；target=0 时它会制造虚假命中：空树直接 dfs(null,0) 得 1，每层新起点调用再各加一次，叠加出 17/21 这类数字。
- 判定时机应绑定「当前节点值已计入路径和」这一事件，而不是子递归入口或初始状态。
## 74. 递归传递上下界

出处：LC0098 验证二叉搜索树

树中节点不只受直接父节点约束，而受整条祖先路径共同约束。递归时把 lower/upper 当作不变量向下传递：进入左子树收紧上界，进入右子树收紧下界；遇到相等或越界立即失败。
