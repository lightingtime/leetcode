## 15. 旋转有序数组二分：先判有序半段，再用值域归属 target

出处：LC0033 搜索旋转排序数组（旋转后仍有一半严格有序）

每轮三分步：

1. 中点：`mid = left + (right - left) / 2`（不能写成 `(right - left) / 2`，left > 0 时落在区间外）；
2. 判有序半段：`nums[left] <= nums[mid]` 说明左半段有序（闭区间左端）；
3. 值域归属：左半段有序时，仅当 `nums[left] <= target < nums[mid]` 才搜左，否则搜右；
   右半段有序时，仅当 `nums[mid] < target <= nums[right]` 才搜右，否则搜左。

要点：不能只拿 target 和 nums[mid] 比大小——必须同时检查 target 是否落在有序半段的
值域 `[nums[left], nums[mid])` / `(nums[mid], nums[right]]` 内，否则会把 target 错误丢出区间。

注意：① target 恰好等于 nums[mid] 时必须能命中，循环内要显式判断 `nums[mid] == target` 返回
（或分支条件含等号、边界收到 mid）；② 有序半段判定用 `nums[left] <= nums[mid]` 而不是 `>`——
区间只剩两个元素时 mid == left，`>` 恒 false 会进错分支。

为什么：旋转数组只有一个「山谷」（旋转点处大→小掉落），从任意位置切两半，最多一个半边含山谷，
所以必有一半有序；只有有序段能用值域判断 target 归属。左半段 `[left, mid]` 有序 ⇔ 没跨山谷 ⇔
`nums[left] <= nums[mid]`（`==` 只在 mid == left 的单元素段发生，天然有序）；若 `nums[left] > nums[mid]`，
山谷在左半段内，右半段 `[mid, right]` 才有序，此时仅当 `nums[mid] < target <= nums[right]` 搜右。

## 16. 二分下界（lower bound）的区间端点：right 取 n 还是 n-1

出处：LC0034 在排序数组中查找元素的第一个和最后一个位置（找 `>= target` 的第一个位置）

| 写法 | 循环条件 | 可返回的范围 | 空数组行为 |
| --- | --- | --- | --- |
| `right = nums.length`（右端点开区间） | `while (left < right)` | `[0, n]`，含插入点 n | 循环不执行，返回 0，语义正确 |
| `right = nums.length - 1`（右端点闭区间） | `while (left < right)` | `[0, n-1]`，表达不了 n | `right = -1`，循环不执行返回 0，解引用越界 |

要点：

- 「第一个 >= target 的位置」是 lower bound，target 可能大于数组中所有元素，此时答案是插入点 `n`，**答案在初始区间之外**；只有右端点取开区间 `n` 才能表达它。
- 闭区间 `[0, n-1]` 配 `while (left < right)` 在区间缩到只剩一个元素（`left == right`）时直接退出，**从不验证那个元素是否满足条件**：target 大于所有元素时停在 `n-1`，返回 `n-1` 而非 `n`。
- 该差一在「last = lower_bound(target+1) - 1」的组合里会传导成整体右边界差一：目标值在数组末尾（含单元素、全相同）时，结束位置报成 `n-2`。
- 空数组时 `right = nums.length - 1 = -1`，循环一次不执行直接 `return left`（0），上层再 `nums[left]` 就抛 `ArrayIndexOutOfBoundsException`。

要点口诀：二分前先问「答案会不会在区间之外」——lower bound / upper bound / 插入点这类问题答案可以是 n，右端点就必须是开区间；只有答案保证在数组内的查找（如查 target 是否存在）才允许闭区间端点。

## 17. 第 k 小 / 中位数的排名换算：1 基第 k 小 vs 0 基下标

出处：LC0004 寻找两个正序数组的中位数（两数组找第 k 小，迭代排除 k/2）

辅助函数若以「第 k 小」（1 基）为语义，代码有这些特征：

- 出口用 `nums[p + k - 1]` 直接返回（从起点 p 数起的第 k 个）；
- `k == 1` 返回当前头部较小值（1 表示「第 1 小」）。

调用方如果按 0 基下标算「中间位置」（如 `totLen / 2`）并直接当 k 传入，会整体偏小 1：

| 场景 | 0 基下标写法（错） | 1 基第 k 小（对） |
| --- | --- | --- |
| 奇数总长 totLen | `k = totLen / 2` | `k = totLen / 2 + 1` |
| 偶数总长 totLen | `k = totLen / 2 - 1`、`totLen / 2` | `k = totLen / 2`、`totLen / 2 + 1` |

换算关系：0 基下标 i 对应第 i+1 小。totLen=1 时若传 `totLen/2 = 0`，辅助函数算 `p + k - 1 = -1` 直接越界。

要点：调用前先确认被调函数的 k 是「第几个」（1 基）还是「下标」（0 基）；「第 k 个」的下标永远是 `起点 + k - 1`，反过来「下标 i」的排名永远是 i+1。

## 43. 沿上升方向二分找峰：方向看局部趋势，不看区间远端

出处：LC0162 寻找峰值

无序数组找任一峰值（`nums[-1]=nums[n]=-∞`，相邻不等），要求 O(log n)：

- 二分比较 `nums[mid]` 与 `nums[mid+1]`：
  - 右邻居更大 → 在上坡，峰必在右半（`l = mid+1`）；
  - 右邻居更小 → 在下坡，峰在左半含 mid（`r = mid`）。
- 端点自然处理：`mid == n-1` 时无右邻居，直接是左半的候选（`r=mid` 收拢）；
  外侧 -∞ 保证沿上升方向走一定能到峰。
- 反例（方向依据错）：用 `nums[mid] > nums[r]`（区间远端）决定收缩方向，
  `[1,2,3,1]` 中 mid=1 处右侧在爬坡（2<3），却被 2>nums[3]=1 误导缩到左半 → 返回 0。
- 死循环陷阱：mid 落在端点且非峰时若只 `if` 不收缩，l/r 不变 → while 死循环。

要点：峰值二分的方向 = 「mid 与相邻元素」的比较（趋势），不是「mid 与区间另一端」
的大小；端点特判若不能推进搜索空间，就让端点也走统一方向判断。

## 44. 双状态编码原地模拟（同时更新）

出处：LC0289 生命游戏

矩阵所有格子需按「旧状态」同时更新，且要求原地（不能用被改过的邻居值计数）：

- 用额外编码保存旧新两态：`1->0` 标 `-1`，`0->1` 标 `-2`，原值 1/0 表示未变化。
- 第一轮只标记不改值：计数时 `-1` 按旧状态「活」计（旧值是 1），`-2` 不按活计（旧值是 0）；
  活细胞过少(<2)/过多(>3) 标 -1，死细胞恰好 3 个活邻居标 -2。
- 第二轮统一落地：`-1->0`、`-2->1`。
- 边界：角/边细胞邻居数不同（角 3、边 5、内部 8），计数按实际在面板内的邻居，不能默认 8 个。

要点：凡是「原地 + 所有元素按旧值同时更新」的模拟题，先想「能否用一个格子同时编码旧态与新态」，
第一轮只读旧值做标记、第二轮落地，空间 O(1)、时间 O(mn)。

## 57. 划分二分：下标空间自洽 + 每轮必收缩

出处：LC0004 寻找两个正序数组的中位数

- 只在**一个数组**上二分：先 `if (nums1.length > nums2.length)` 交换，保证短数组做划分，复杂度 O(log(min(m,n)))。
- 「下标空间」与「排名空间」不能混用：`left = -1, right = m` 里 `i` 表示 nums1 左半边的**最后一个元素下标**（可为 -1 表示左半边空），不是「第 k 小」的 1 基排名——混用就是历史上「奇数取前一位、偶数取两位、k=0 越界」的根源。
- 循环 `while (left + 1 < right)` 内**只动一个端点**：合法（`nums1[i] <= nums2[j+1]`）就 `left = i`，否则 `right = i`；把另一个数组的切分点 `j` 赋给 `right` 属于跨数组下标空间混用，某些输入下区间不收缩 → 死循环。
- 收尾用两句话定位答案：左半最大 `maxInMin = max(ai, bj)`、右半最小 `minInMax = min(ai1, bj1)`；总长奇数返回 `maxInMin`，偶数返回两者均值。
- 越界半边用哨兵：`i < 0` 时 `ai = Integer.MIN_VALUE`、`i+1 >= m` 时 `ai1 = Integer.MAX_VALUE`，于是空数组、单元素、两数组悬殊都不必特判。
- 自检：写完后问自己「这一轮区间一定变小了吗？」与「这里的下标属于哪个数组的哪个空间？」两个问题，能同时挡掉死循环与差 1。

要点：划分法的正确性 = 下标空间自洽 + 单调收缩；答案用左半最大/右半最小两句话表达，边界交给哨兵。

## 63. 二分的分支必须互斥且完备：条件都不命中 = 区间不收缩 = 死循环

出处：LC0033 搜索旋转排序数组（二刷踩坑）

旋转数组二分每轮的本质是「丢掉半边、保留含答案的另一半」。只写两个**独立** `if`——① mid 在左段且
target 落在左段值域内 → 保留左半边；② mid 在右段且 target 落在右段值域内 → 保留右半边——时，
**剩下的情形没有归属**：mid 恰好落在下标 0、`target == nums[mid]`、mid 在左段但 target 更大、
mid 在右段但 target 更小，这些都会让两个条件同时为假，于是 `left`、`right` 都不动，`mid` 不变 →
死循环。

症状很好认：**不是 WA，是没有任何输出**（本机跑 main 时 Java 进程被 20s 超时杀掉，连第一行测试
结果都打不出来）。

| 输入 | 第几轮卡死 | 两个条件为何都不成立 |
| --- | --- | --- |
| `{1, 2}`，target = 2 | 第一轮 mid=0 | `nums[0] > nums[0]`、`nums[0] < nums[0]` 全假 |
| `{4,5,6,7,0,1,2}`，target = 0 | 第三轮 mid=0 | 同上（前两轮把 right 收到 1） |
| `{4,5,6,7,0,1,2}`，target = 5 | 第二轮 mid=1，`nums[1]=5` | 左段成立但 `5 > 5` 假；右段条件也不成立 |

对照一刷的闭区间写法：`nums[mid] == target` 命中即 `return`，否则 `left = mid + 1` / `right = mid - 1`，
每轮无条件收缩，所以从结构上不可能死循环。**换模板不会改变「每轮必缩」这个要求**：开区间 lower bound
模板把「丢掉半边」的责任交给了你写的分支，就必须保证 mid 一定被归入某一侧（保留 `[mid, right]` 或
`[left, mid]`），也就是分支互斥且完备。

自检口诀：每轮末尾问「这一轮区间一定变小了吗」；两元素输入（`{1,2}`、`{2,1}` 这类）是死循环的照妖镜。

要点：二分分支写「该往哪边走」永远不够——还要有兜底的那一支负责丢掉另一边，否则条件全落空时区间原地踏步。
## 75. 合并区间：维护覆盖终点

出处：LC0056 合并区间

排序后单遍合并时，当前合并区间的终点表示已经覆盖到的最右位置。处理新区间不能只沿用新区间终点，必须考虑旧区间仍向右延伸的情况；用 [[1,10],[2,3],[4,5]] 可逐层检查终点是否会错误回退。

## 76. 二维有序矩阵从右上角消行消列

出处：LC0240 搜索二维矩阵 II

行列分别单调时，从右上角或左下角出发，每次比较可安全排除一整行或一整列；适用于需要在矩阵中高效查找目标且不能把整体视作一维有序数组的场景。
