## 31. DP 填表顺序满足依赖方向 + 答案更新必须校验状态

出处：LC0005 最长回文子串

- dp[i][j] 依赖 dp[i+1][j-1]（左下方），按 i 正序、j 内层正序填会读到未计算的格子，必须按子串长度从小到大填（或 i 倒序）；
- 记录答案/最优解前必须确认 dp[i][j] 为 true：只看两端字符相等就更新会把非回文（如 abca）当成答案；
- 具体 case：abca 的 dp[0][3]=dp[1][2]=false，但若 ans 更新不看 dp，会错误返回 abca。
- 长度 2 的 base 不能走转移：dp[i][i+1] 已在初始化置位，主循环若再执行 dp[i][j]=dp[i+1][j-1] 会读到无效下三角（dp[i+1][i]=false）把 true 覆盖，所有偶数长度回文断链（aa→a、abba 丢失）；长度 2 应直接判两端相等，或转移前先排除 j==i+1。

要点：写 DP 先画依赖图确定填表顺序；从 dp 取值更新答案时，先校验状态本身成立。

## 32. 贪心最远可达：先判当前位置可达再更新，不可达立即返回

出处：LC0055 跳跃游戏

- 维护 farthest = 当前能到的最远下标，遍历每个位置 i：
  - 先判 i > farthest：当前位置都够不着，后面更够不着，直接返回 false；
  - 再更新 farthest = max(farthest, i + nums[i])；
  - 一旦 farthest >= n-1 返回 true。
- 顺序不能反：只更新不判可达，会让不可达位置的大跳跃把 farthest 推过终点，下一轮误判为 true。
- 具体 case：[1,1,1,0,5,0] 实际最远只到下标 3，位置 4 的 5 不可达，答案应为 false。

要点：贪心维护「最远可达」时，每个位置在更新前必须先确认自己可达；检查 → 更新 → 提前返回的顺序决定正确性。

## 33. 滚动数组：初始化已代表第 0 行，循环起点要偏移到 1

出处：LC0062 不同路径

- Arrays.fill(dp, 1) 已代表第一行（一路向右只有 1 条路径），外层循环应只处理第 2..m 行，即从 i=1 开始共 m-1 次；
- 若循环仍从 i=0 开始，第一行会被额外更新一遍，等于多算一行：m=1,n=10 应得 1 却得 10，3x2 应得 3 却得 4；
- 通用检查：写出初始化语义后，确认循环覆盖的区间与之不重叠；滚动数组常见错误就是「初始化一行 + 再跑 m 行」= m+1 行。

要点：状态初始化与循环起点的行数要对齐：init 占一行，循环只跑剩余 m-1 行。

## 34. 滚动变量原地更新：先存旧快照再整体替换，答案跟踪对象与状态语义一致

出处：LC0152 乘积最大子数组

- 把二维 dp 压成两个滚动变量时，转移公式的输入必须是「上一轮」的两个旧值；先更新 max 再算 min，min 的候选里就混进了本轮新 max（状态污染）；
- 正确做法：每轮先用旧 max/min 算出新值，再整体赋值（先保存快照，或用临时变量）；滚动只改存储方式、不改转移语义；
- 答案变量也要跟对对象：dpMax 的滚动结果才对应「最大」，答案应与其比较；把 ans 与 min 比较会丢掉已出现的最大值；
- 具体 case：nums=[-2,-3,-1]，正确过程 i=1 应得 max=6、min=-3、ans=6；原地更新 + 跟 min 比较会算出 i=1 的 min=-18，最终返回 -2 而非 6。

要点：滚动压缩只改存储、不改语义：两个状态必须在同一旧快照上计算，答案更新对象与状态定义一一对应。

## 35. DP 初始化必须覆盖该下标全部合法决策，不能只取一种

出处：LC0198 打家劫舍

- 递推起点状态要完整：dp[1] 表示前两间的最优，应同时包含「偷第 1 间」与「只偷第 0 间」两种候选（max(nums[0], nums[1])），只存 nums[1] 等于强制第 1 间必偷；
- 具体 case：nums=[2,1,1,2]，正确起点 dp[1]=2，才能在 i=3 得到 dp[1]+2=4；起点只存 1 时 i=3 只能算出 1+2=3，返回错误；
- 修复后一维 dp 单调不减（dp[i]≥dp[i-1]），答案直接取 dp[n-1] 即可，末尾再 max(dp[n-1], dp[n-2]) 是冗余（无害）。

要点：写 DP 时先写出「下标 x 的状态语义」，初始化时逐项核对它应包含哪些候选，别让起点丢情况。

## 36. 字符串匹配 DP：前缀长度语义 + 循环含端点 + 星号分支三要素

出处：LC0010 正则表达式匹配

- dp[i][j] 用前缀长度语义（0..len，共 len+1 个状态），循环必须遍历到 s.length() 与 p.length()（含端点），否则最后一行/列和答案格永不填充；取字符一律 charAt(i-1) / charAt(j-1)；
- 星号分支三要素：零次走 dp[i][j-2]；一次及以上走 dp[i-1][j]，且要求 i>0、s.charAt(i-1) 匹配 x（x 为 '.' 或等于该字符）；两条取或；
- 具体 case：s="aa"、p="a*"，若 j 只循环到 p.length()-1，dp[2][2] 从未填，答案错误返回 false；s="ab"、p=".*"，若星号匹配漏掉 '.' 通配，正确 true 却返回 false；
- 取 s.charAt(i-1) 前必须先保证 i>0，否则 i=0 时直接数组越界。

要点：dp 的每个边界格都要被循环覆盖；分支访问字符串前先确认下标存在。

## 41. 网格正方形 DP：三邻居取 min + 1，答案取全局最大边长

出处：LC0221 最大正方形

以 `(i,j)` 为右下角的最大正方形边长：`dp[i][j] = min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1`（该格为 '1' 时），'0' 格 dp=0。

- 为什么取 min：边长 k 的正方形以 (i,j) 为右下角，内部必须分别包含以「上、左、对角」三格为右下角的三个 k-1 正方形；最矮的邻居决定上限。
- 基础行列：第一行 / 第一列的 '1' 格 dp=1，'0' 格 dp=0（判断别写反）。
- 答案：全程记录最大边长，返回 maxSide²（面积）；最大正方形可能出现在任意位置，不能只返回固定角格（如右下角）。
- 反例：`[[1,1,1],[1,1,1],[0,1,1]]` 中 (2,2) 的三邻居为 2,2,1 → dp=2 而非 3，因为左邻列被 (2,0) 的 0 截断。

## 58. 滚动数组的三来源：左=插入、上=删除、对角=替换/相同

出处：LC0072 编辑距离（一维滚动 DP）

- 二维转移：`dp[i][j] = a[i]==b[j] ? dp[i-1][j-1] : min(左上, 上, 左) + 1`。滚成一维后要认清**算 `dp[j]` 那一刻三个格子分别是谁**：
  - `dp[j-1]`：已在本行被覆盖 → 二维的 `dp[i][j-1]` = **插入**；
  - 覆盖前先存下的 `pre = dp[j]`：二维的 `dp[i-1][j]` = **删除**；
  - `leftTop`：二维的 `dp[i-1][j-1]` = **替换/相同**。
- 字符相等时**必须继承 `leftTop`**，不能取 `dp[j-1]`：相等意味着这一步不需要任何操作，代价应原样来自「两串各少一个字符」的对角格子；取左等于把「插入一个字符」也算进来。
  - 小例子：`word1="ab"`、`word2="b"`。第一行 `dp=[1]`，进入第二行前 `leftTop = i = 1`（把 `"a"` 删光）；`j=0` 时 `a[1]==b[0]`（都是 `b`）→ `dp[0] = leftTop = 1`（答案：删掉 `a`）。若误用左格，`j=0` 连下标都没有，按 0 处理则等于宣称「ab → b 不用操作」。
- 每列末必须 `leftTop = pre`，下一列的「左上」才是上一行同列的值；漏更新会让对角语义断掉（这是本题历史上反复踩的坑）。
- 边界两种写法都行：开 `n+1` 哨兵列（`dp[0] = i` 每行重置），或不加哨兵列但把 `j==0` 的左侧来源手工补成 `i+1`（word1 前缀全删），并把 word2 为空提前返回 `m`；后者少一列但要额外兜基例。
- 正确性自检：挑一个两字符的小例子（如 `"ab"` vs `"b"`）手推 2×1 表，逐格核对「相等走对角、不等取三来源 min+1」。

要点：一维滚动只是把「上/左/左上」三个格子换成了 `pre`/`dp[j-1]`/`leftTop`；相等只认对角，不等才三取一。

## 60. 两段式：DP 判可行性 + 回溯枚举方案

出处：LC0140 单词拆分 II

- 适用信号：要返回**所有**方案（句子、路径、切分方式），而判定「有没有方案」本身是个 DP/可达性问题。
- 先分清两件事：**枚举**的代价躲不掉（答案数本身可能指数级，如 `s="aaaa"`、`dict={"a","aa"}` 有 5 条），能砍的是**注定产不出答案的子树**。
- 第一段（判定）：`canReach[i]` = 「从 i 开始的后缀能不能拆完」。基例 `canReach[n] = true`（空后缀可拆），从右往左填：
  `canReach[i] = ∃w: s.startsWith(w, i) && canReach[i + w.length()]`。
- 第二段（枚举）：DFS 进入时先 `if (!canReach[start]) return;`，只展开能走到终点的分支。
- **方向不能反**：问「从 i 到终点」就必须右→左；拿前缀可拆表（0→i 能拆）来剪枝是历史上踩过的坑。
- 剪枝位置：放在「到达终点 → 收答案」之后、循环之前，到达终点的路径才不会被误剪。
- 效果实测：`s = "a"×60 + "b"`、`dict = {"a","aa","aaa","aaaa","aaaaa"}` —— 带剪枝 ≈0ms 返回空答案；无剪枝超过 2000 万次递归仍未结束。
- 变体：判定表也可以用记忆化递归 `memo[i] = 从 i 出发的所有方案`，代价变成保存/拷贝子答案列表；只判定不枚举的版本（LC139）不需要第二段。

要点：答案枚举 + 可行性预判拆成两段；预判表的方向必须与「问的是谁到谁」一致。

## 61. 带 pre 参数的 DFS 何时还能记忆化：看返回值是否与 pre 无关

出处：LC0329 矩阵中的最长递增路径

- 判据只有一条：**同一状态在不同调用下返回值是否恒定**。恒定才能缓存，参数里有谁不影响结论。
- 反例直觉：`dfs(i, j, pre)` 看起来「状态带了 pre」就不能缓存了。但若 `pre` 只用于**提前拦截**——
  - 拦截分支 `matrix[i][j] <= pre` 直接 `return 0`，**且不写 memo**；
  - 通过拦截后算出的就是「从 (i,j) 出发的最长递增路径」，与 `pre` 具体是几无关；
  那么 `(i, j)` 依旧是完整状态，`memo[i][j]` 成立。
- 关键顺序：**守卫在前、查缓存/写缓存在后**。若把 memo 写在守卫之前，会把「因前驱太大而返回 0」的截断值固化进缓存，后续再用就是错的。
- 哨兵选择：本题答案 ≥ 1，所以 `0` 既能表示「未计算」，又正好是拦截分支的返回值——但这个巧合正是必须靠「不写 memo」来保护的。
- 入口无约束值：外层传 `-1` 之前先确认值域下界（本题 `matrix[i][j] >= 0`），否则应改用 `Integer.MIN_VALUE` 或标记数组。
- 对拍验证：2 万组随机小网格与「无记忆化朴素 DFS」结果零差异，说明 `pre` 与 memo 的组合没有破坏状态语义。

要点：参数里有 pre ≠ 不能缓存；只要 pre 只做拦截、且拦截结果不入缓存，状态就仍然是格子本身。
## 65. 一次遍历维护前缀极值

出处：LC0121 买卖股票的最佳时机

要求一对 i<j 的最优差（最大利润、最大差值）时，固定右端点 j，最优左端点只依赖 [0,j-1] 的极值：滚动维护前缀极值就能把 O(n^2) 枚举压成 O(n)/O(1)。套用前先确认方向性（先买后卖），否则会退化成「全局最大减全局最小」。对照：若问的是「某个位置之后的最优」，要改成预处理后缀极值或倒序扫描。

## 67. Kadane 滚动（以位置结尾的最优）

出处：LC0053 最大子数组和

当题目要求「连续区间最优最大值」时，把状态定为「以 i 结尾的最优值」，转移 = max(接上一段, 从当前重启)，一遍扫描只保留上一位置的状态 → O(n)/O(1)。对照：乘积版（152）不能只留一个状态，因为负负得正，要同时维护以 i 结尾的 max 与 min。

## 68. 线性 DP · 字符串切分可行性

出处：LC0139 单词拆分

切分/拼接可行性题先想「位置就是阶段」：状态定义为某端开头（或结尾）的剩余串能否拼出，转移只写「当前这一段取词典里的哪个词」。
- 正向 vs 倒向只是镜像，选哪个看哪端更好写边界；空串（下标 n 或 0）永远是 true 的终点。
- 可行性只要一个见证，命中即 break，不要写成计数 DP。
- 词典先去重；若词很长很多，再考虑 Trie 把公共前缀的重复比较省掉。

## 69. 完全背包一维压缩（正序枚举）

出处：LC0279 完全平方数

物品可无限次使用时，一维 dp 按容量从小到大正序填表，dp[c] 才能复用本轮刚更新的 dp[c-w]；改成倒序就退化成 0-1 背包。本题 w=j²、每件代价 1，求恰好装满容量 n 的最小代价。

## 70. 一维完全背包（容量从小到大、物品在内层）

出处：LC0322 零钱兑换

识别信号：物品可无限次选取 + 求最优值（最少个数/最大价值）。与 0/1 背包的唯一分水岭是容量维枚举方向——完全背包容量从小到大，使得 dp[i-c] 是「本轮已更新」的状态，同一物品可复用；0/1 背包必须从大到小，避免同一件物品被重复计入。本题把「求装满的最小代价」直接建模成 min 转移，无需额外记录选取方案。

## 73. 多起点 DP/DFS：外层枚举必须把当前下标传进递归，否则退化成单起点

出处：LC0329 矩阵中的最长递增路径

出处 LC0329（复习轮）。双层 for 遍历每个格子当起点，但体内写成 dfs(matrix, 0, 0, -1)，循环变量 i、j 一次都没用到 —— 结果只反映从左上角出发的路径：示例1 [[9,9,4],[6,6,8],[2,1,1]] 实际 1、期望 4。之所以难发现，是因为示例2 [[3,4,5],[3,2,6],[2,2,1]] 的最长路径 3->4->5->6 恰好从 (0,0) 起步，边界用例也大多把 (0,0) 设计成起点，9 组里过了 8 组，只挂 1 组。取舍与自检：多起点结构的入口必须显式传当前坐标；写完后扫一眼「外层循环变量在循环体内出现过吗」——没有被用到就说明循环白转。配套点：这类题的记忆化入口哨兵要对着值域下界选（本题值 >= 0 才敢用 -1），否则会误拦第一个格子。
