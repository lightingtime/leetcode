## 1. 链表指针判空取舍：p != null vs p.next != null

出处：LC0141 环形链表（快慢指针判环）、LC0160 相交链表（双指针换链）

| 目的 | 判断 |
| --- | --- |
| 完整遍历所有节点 / 让指针走出链表 | `while (p != null)` |
| 找链表尾（追加节点、接另一条链） | `while (p.next != null) p = p.next;` |
| 双指针换链对齐（走完一条链再切） | 指针本身走到 null 时切换 |
| 快慢指针跳 2 步（判环/找中点）防越界 | `while (fast.next != null && fast.next.next != null)` |
| 按哨兵 tail 截断找中点（链表归并排序） | `while (fast != tail && fast.next != tail)` |
| 删除节点（需要前驱） | 停在目标前一个：`while (cur.next != null && cur.next.val != target)` |
| 判断当前是否为最后一个节点 | `p.next == null` |

要点：判断没有优劣，选哪个取决于「这一步之后指针要不要越界」。

- `p != null`：允许指针越过最后一个节点（到达 null），用于需要完整走完一条链的场景（遍历、换链对齐）。
- `p.next != null`：让指针停在最后一个节点上或提前看一步，用于必须在链内操作、不能踏空的场景（找尾、快指针跳两步、删除节点找前驱）。
- 换链类双指针必须在指针为 null 时切换：这样两个指针各自完整走完一条链，总步数同步（各 m+n），无交点时同时归零结束、有交点时在交点相遇；在尾巴上切换会错位或死循环。

## 2. 快慢指针找中点后的奇偶判定

出处：LC0234 回文链表（快慢指针找中点 + 栈/反转比较后半段）

快慢指针走完后，`fast` 的位置直接给出链表长度奇偶：

- `fast == null` → 偶数长度：`slow` 正好是后半段开头，直接比较后半段。
- `fast` 停在最后一个节点（非 null）→ 奇数长度：`slow` 停在中点，比较前先跳过中点。

要点：这决定「要不要把 slow 再往后移一步」；配合第 1 条里的快慢指针防越界写法使用。

## 3. 递归不算 O(1) 空间：调用栈计入空间复杂度

出处：LC0234 回文链表（进阶 O(1) 空间讨论）

递归每层调用压一个栈帧，调用栈深度随输入规模增长（如链表递归深度 n），辅助空间为 O(递归深度)，**不算 O(1)**。

- 复杂度分析中调用栈与堆上容器一样计入空间。
- O(1) 空间要求用迭代 + 常数个变量（如快慢指针 + 原地反转链表）。
- 递归深度大时（如 n=10^5）还有栈溢出风险。

## 4. 反转链表三步的顺序与自环陷阱

出处：LC0234 回文链表（O(1) 空间反转后半段）

标准三步：

```java
ListNode next = cur.next;  // 1. 先保存后继
cur.next = pre;            // 2. 用旧 pre 把当前节点指回上一节点
pre = cur;                 // 3. 最后才前移 pre、cur
cur = next;
```

陷阱：若先执行 `pre = cur` 再执行 `cur.next = pre`，pre 与 cur 是同一节点，
`cur.next` 指向自己形成自环，链表结构被破坏，后续遍历/比较全错甚至死循环。
`pre` 的「上一节点」身份必须在第 2 步使用完之后才能覆盖。

## 5. 数组双指针原地分区：快指针扫描 + 慢指针记写入位置

出处：LC0283 移动零（数组原地筛选/分区）

快指针扫描全数组，慢指针记录「下一个目标元素应写入的位置」；遇到满足条件的元素就放到慢指针位置并前移。
一趟 O(n)、空间 O(1)，且保持元素相对顺序。

适用：移动零、删除有序数组重复项、颜色分类等原地筛选/分区题。

## 6. 闭区间计数：元素个数 = 间隔数 + 1

出处：LC0003 无重复字符的最长子串（滑动窗口长度计算）

闭区间 `[l, r]` 的元素个数 = `r - l + 1`（两端下标都算上）。直观理解：
`r - l` 是「间隔数」（栅栏空隙），元素个数 = 间隔数 + 1（栅栏数）。

滑动窗口 / 子数组 / 遍历题的长度计算都适用，最常错在多减 1 或少加 1。

## 7. 滑动窗口结算时机与公式绑定

出处：LC0003 无重复字符的最长子串（延迟结算写法）

两种合法写法：

- 每步结算：先处理重复（必要时跳 start），再 `max = max(max, i - start + 1)`。
- 延迟结算：if 分支只扩展窗口不结算；else（遇到重复）结算被截断的窗口 `[start, i-1]`，长度 `i - start`；循环结束后补最后窗口 `n - start`。

要点：公式必须匹配结算那一刻窗口的合法性——窗口含 i 且无重复才用 `i - start + 1`；
else 里 i 是重复字符，窗口只能算到 `i-1`，用 `i - start`。

## 8. 相向双指针：两端向中间收，移动条件更差的一侧

出处：LC0011 盛最多水的容器（两端夹逼）

左右指针从数组两端出发，每轮计算当前答案后，移动「条件更差」的一侧：
容器题移动较矮的边（高度是短板，移高边只会更差）；回文验证移动不匹配的一侧。
把 O(n²) 降到 O(n)，空间 O(1)。

适用：盛水容器、接雨水（变体）、验证回文串等两端夹逼题。

## 9. 排序后去重：保留重复值第一次出现，跳过后续重复

出处：LC0015 三数之和（固定第一个数 + 双指针夹逼时的去重）

| 写法 | 效果 |
| --- | --- |
| `i > 0 && nums[i] == nums[i-1]` 时跳过 | 保留该值第一次出现、跳过后续重复 → 同一三元组只输出一次 |
| `i < j-2 && nums[i] == nums[i+1]` 时跳过 | 丢掉重复组里靠前的那个，可能丢掉需要两个相同值的合法组合（如 -1,-1,2），且同一组合可能重复输出 |

要点：去重方向是「跳过已经用过的值」，而不是「跳过重复组里靠前的第一个」；三数之和允许两个位置取相同值，
所以第一次出现必须保留。双指针夹逼找到一组答案后，还要把两端的重复值一并跳过，避免同值不同下标的组合重复输出。

## 10. 链表删除倒数第 N 个：哨兵 + 快慢指针拉开 N 步

出处：LC0019 删除链表的倒数第 N 个结点（一趟扫描）

快指针先走 N 步，慢指针与 pre 从 head / dummy 同步前进；快指针走到 null 时，
慢指针正好指向待删节点，pre 是其前驱。dummy 哨兵让「删头结点」与普通删除共用同一段逻辑。

要点：一趟扫描 O(n)/O(1) 即可完成，不需要先数长度再走第二遍；
哨兵节点（dummy）统一处理头结点删除，避免特判「n == 链表长度」。

## 11. 三路原地分区：两个边界指针 + 一个扫描指针

出处：LC0075 颜色分类（0/1/2 原地排序，一趟扫描 + 常数空间）

0 与 2 各用一个边界指针（p0、p2），扫描指针 cur 负责遍历：

- `nums[cur] == 0`：与 p0 交换，p0++、cur++；
- `nums[cur] == 2`：与 p2 交换，p2--，**cur 不前进**（回看换入值）；
- `nums[cur] == 1`：cur++。

要点：扫描指针要么前进、要么停在原地回看交换进来的值，保证每轮必有进展，不会死循环，整趟 O(n)；
「两端都是 1 且中间全为 1」就是终态，靠 cur 越过 p2 结束，而不是靠 start/end 相撞。

## 12. Floyd 判圈找环入口：先移动后比较 + 第二阶段同速

出处：LC0287 寻找重复数（数组当下标链 i→nums[i]，重复数 = 环入口）

两个阶段：

- **相遇阶段**：slow 每次一步、fast 每次两步，直到相遇。两指针从同一起点出发时，
  必须先移动再比较（`do { ... } while (fast != slow)`，或初始化时让 fast 先走两步），
  用 `while (fast != slow)` 会因初始相等一次都不执行。
- **入口阶段**：slow 放回起点，fast 留在相遇点，两者都每次一步，再次相遇的位置就是环入口。

要点：O(n)/O(1)，不修改数组；「先走还是先比」由两指针初始位置决定——起点相同必须 do-while，
起点错开才能 while。

## 13. 滑动窗口覆盖子串：收缩只删多余、记录后整体前移

出处：LC0076 最小覆盖子串（覆盖判定 = 计数 + 未满足数 count）

覆盖类滑动窗口三件事：

- **扩展**：右指针前进，遇到需要字符（`need[c] > 0`）才 `need[c]--` 并 `count--`；
- **收缩**：只能删「多余」字符（`need[left] < 0`）——`need[left] == 0` 表示恰好满足、删了会破坏覆盖；
- **前进**：记录答案后，把左边界关键字符还回（`need[left]++`、`count++`、`left++`），窗口整体继续走。

要点：收缩用 `need[left] <= 0` 会把恰好满足的字符也还回去却不更新 count/left，覆盖状态与 count 脱节
（count 可能变负数），后续窗口全部失真。

注意：扩展时「判断 count 是否减」必须用 `need[c]--` **之前**的值——先减后判（减完再问
`need[c] > 0`）会让首次遇到的必需字符（减后为 0）永不触发 count--，count 恒不变、覆盖永远判不出来；
正确写法是先判（`need[c] > 0` 则 count--）再无条件减，或减后判断 `>= 0`。

## 14. 滑动窗口最值：单调队列（双端队列存下标）

出处：LC0239 滑动窗口最大值（窗口内最值，一趟 O(n)）

双端队列存**下标**，值从队头到队尾单调递减（队头 = 当前窗口最大）。两个方向的弹出各管一件事：

- **弹队尾**（入队前）：`nums[peekLast()] < nums[i]` 的全弹——新元素更大且更晚，被弹者永远当不了最大；
- **弹队头**（读答案前）：`peekFirst() < 窗口左边界` 的弹出——下标已滑出窗口（过期），必须淘汰。

要点：弹队尾是「比大小淘汰」，弹队头是「下标过期淘汰」，两者缺一不可；
队列存下标而不是值，才能判断过期。窗口左边界 = `i - k + 1`（或用独立左指针）。

注意：过期条件必须是 `peekFirst() < i - k + 1`（等价 `<= i - k`）；写成 `< i - k`
会漏掉恰好滑出窗口的那一格（下标 == i-k 已过期），递减/全负数用例仍会错。

## 15. 旋转有序数组二分：先判有序半段，再用值域归属 target

出处：LC0033 搜索旋转排序数组（旋转后仍有一半严格有序）

每轮三分步：

1. 中点：`mid = left + (right - left) / 2`（不能写成 `(right - left) / 2`，left > 0 时落在区间外）；
2. 判有序半段：`nums[left] <= nums[mid]` 说明左半段有序（闭区间左端）；
3. 值域归属：左半段有序时，仅当 `nums[left] <= target < nums[mid]` 才搜左，否则搜右；
   右半段有序时，仅当 `nums[mid] < target <= nums[right]` 才搜右，否则搜左。

要点：不能只拿 target 和 nums[mid] 比大小——必须同时检查 target 是否落在有序半段的
值域 `[nums[left], nums[mid])` / `(nums[mid], nums[right]]` 内，否则会把 target 错误丢出区间。

注意：① target 恰好等于 nums[mid] 时必须能命中，循环内要显式判断 `nums[mid] == target` 返回
（或分支条件含等号、边界收到 mid）；② 有序半段判定用 `nums[left] <= nums[mid]` 而不是 `>`——
区间只剩两个元素时 mid == left，`>` 恒 false 会进错分支。

为什么：旋转数组只有一个「山谷」（旋转点处大→小掉落），从任意位置切两半，最多一个半边含山谷，
所以必有一半有序；只有有序段能用值域判断 target 归属。左半段 `[left, mid]` 有序 ⇔ 没跨山谷 ⇔
`nums[left] <= nums[mid]`（`==` 只在 mid == left 的单元素段发生，天然有序）；若 `nums[left] > nums[mid]`，
山谷在左半段内，右半段 `[mid, right]` 才有序，此时仅当 `nums[mid] < target <= nums[right]` 搜右。

## 16. 二分下界（lower bound）的区间端点：right 取 n 还是 n-1

出处：LC0034 在排序数组中查找元素的第一个和最后一个位置（找 `>= target` 的第一个位置）

| 写法 | 循环条件 | 可返回的范围 | 空数组行为 |
| --- | --- | --- | --- |
| `right = nums.length`（右端点开区间） | `while (left < right)` | `[0, n]`，含插入点 n | 循环不执行，返回 0，语义正确 |
| `right = nums.length - 1`（右端点闭区间） | `while (left < right)` | `[0, n-1]`，表达不了 n | `right = -1`，循环不执行返回 0，解引用越界 |

要点：

- 「第一个 >= target 的位置」是 lower bound，target 可能大于数组中所有元素，此时答案是插入点 `n`，**答案在初始区间之外**；只有右端点取开区间 `n` 才能表达它。
- 闭区间 `[0, n-1]` 配 `while (left < right)` 在区间缩到只剩一个元素（`left == right`）时直接退出，**从不验证那个元素是否满足条件**：target 大于所有元素时停在 `n-1`，返回 `n-1` 而非 `n`。
- 该差一在「last = lower_bound(target+1) - 1」的组合里会传导成整体右边界差一：目标值在数组末尾（含单元素、全相同）时，结束位置报成 `n-2`。
- 空数组时 `right = nums.length - 1 = -1`，循环一次不执行直接 `return left`（0），上层再 `nums[left]` 就抛 `ArrayIndexOutOfBoundsException`。

要点口诀：二分前先问「答案会不会在区间之外」——lower bound / upper bound / 插入点这类问题答案可以是 n，右端点就必须是开区间；只有答案保证在数组内的查找（如查 target 是否存在）才允许闭区间端点。

## 17. 第 k 小 / 中位数的排名换算：1 基第 k 小 vs 0 基下标

出处：LC0004 寻找两个正序数组的中位数（两数组找第 k 小，迭代排除 k/2）

辅助函数若以「第 k 小」（1 基）为语义，代码有这些特征：

- 出口用 `nums[p + k - 1]` 直接返回（从起点 p 数起的第 k 个）；
- `k == 1` 返回当前头部较小值（1 表示「第 1 小」）。

调用方如果按 0 基下标算「中间位置」（如 `totLen / 2`）并直接当 k 传入，会整体偏小 1：

| 场景 | 0 基下标写法（错） | 1 基第 k 小（对） |
| --- | --- | --- |
| 奇数总长 totLen | `k = totLen / 2` | `k = totLen / 2 + 1` |
| 偶数总长 totLen | `k = totLen / 2 - 1`、`totLen / 2` | `k = totLen / 2`、`totLen / 2 + 1` |

换算关系：0 基下标 i 对应第 i+1 小。totLen=1 时若传 `totLen/2 = 0`，辅助函数算 `p + k - 1 = -1` 直接越界。

要点：调用前先确认被调函数的 k 是「第几个」（1 基）还是「下标」（0 基）；「第 k 个」的下标永远是 `起点 + k - 1`，反过来「下标 i」的排名永远是 i+1。
