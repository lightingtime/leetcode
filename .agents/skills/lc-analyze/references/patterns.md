## 1. 链表指针判空取舍：p != null vs p.next != null

出处：LC0141 环形链表（快慢指针判环）、LC0160 相交链表（双指针换链）

| 目的 | 判断 |
| --- | --- |
| 完整遍历所有节点 / 让指针走出链表 | `while (p != null)` |
| 找链表尾（追加节点、接另一条链） | `while (p.next != null) p = p.next;` |
| 双指针换链对齐（走完一条链再切） | 指针本身走到 null 时切换 |
| 快慢指针跳 2 步（判环/找中点）防越界 | `while (fast.next != null && fast.next.next != null)` |
| 按哨兵 tail 截断找中点（链表归并排序） | `while (fast != tail && fast.next != tail)` |
| 删除节点（需要前驱） | 停在目标前一个：`while (cur.next != null && cur.next.val != target)` |
| 判断当前是否为最后一个节点 | `p.next == null` |

要点：判断没有优劣，选哪个取决于「这一步之后指针要不要越界」。

- `p != null`：允许指针越过最后一个节点（到达 null），用于需要完整走完一条链的场景（遍历、换链对齐）。
- `p.next != null`：让指针停在最后一个节点上或提前看一步，用于必须在链内操作、不能踏空的场景（找尾、快指针跳两步、删除节点找前驱）。
- 换链类双指针必须在指针为 null 时切换：这样两个指针各自完整走完一条链，总步数同步（各 m+n），无交点时同时归零结束、有交点时在交点相遇；在尾巴上切换会错位或死循环。

## 2. 快慢指针找中点后的奇偶判定

出处：LC0234 回文链表（快慢指针找中点 + 栈/反转比较后半段）

快慢指针走完后，`fast` 的位置直接给出链表长度奇偶：

- `fast == null` → 偶数长度：`slow` 正好是后半段开头，直接比较后半段。
- `fast` 停在最后一个节点（非 null）→ 奇数长度：`slow` 停在中点，比较前先跳过中点。

要点：这决定「要不要把 slow 再往后移一步」；配合第 1 条里的快慢指针防越界写法使用。

## 3. 递归不算 O(1) 空间：调用栈计入空间复杂度

出处：LC0234 回文链表（进阶 O(1) 空间讨论）

递归每层调用压一个栈帧，调用栈深度随输入规模增长（如链表递归深度 n），辅助空间为 O(递归深度)，**不算 O(1)**。

- 复杂度分析中调用栈与堆上容器一样计入空间。
- O(1) 空间要求用迭代 + 常数个变量（如快慢指针 + 原地反转链表）。
- 递归深度大时（如 n=10^5）还有栈溢出风险。

## 4. 反转链表三步的顺序与自环陷阱

出处：LC0234 回文链表（O(1) 空间反转后半段）

标准三步：

```java
ListNode next = cur.next;  // 1. 先保存后继
cur.next = pre;            // 2. 用旧 pre 把当前节点指回上一节点
pre = cur;                 // 3. 最后才前移 pre、cur
cur = next;
```

陷阱：若先执行 `pre = cur` 再执行 `cur.next = pre`，pre 与 cur 是同一节点，
`cur.next` 指向自己形成自环，链表结构被破坏，后续遍历/比较全错甚至死循环。
`pre` 的「上一节点」身份必须在第 2 步使用完之后才能覆盖。

## 5. 数组双指针原地分区：快指针扫描 + 慢指针记写入位置

出处：LC0283 移动零（数组原地筛选/分区）

快指针扫描全数组，慢指针记录「下一个目标元素应写入的位置」；遇到满足条件的元素就放到慢指针位置并前移。
一趟 O(n)、空间 O(1)，且保持元素相对顺序。

适用：移动零、删除有序数组重复项、颜色分类等原地筛选/分区题。

## 6. 闭区间计数：元素个数 = 间隔数 + 1

出处：LC0003 无重复字符的最长子串（滑动窗口长度计算）

闭区间 `[l, r]` 的元素个数 = `r - l + 1`（两端下标都算上）。直观理解：
`r - l` 是「间隔数」（栅栏空隙），元素个数 = 间隔数 + 1（栅栏数）。

滑动窗口 / 子数组 / 遍历题的长度计算都适用，最常错在多减 1 或少加 1。

## 7. 滑动窗口结算时机与公式绑定

出处：LC0003 无重复字符的最长子串（延迟结算写法）

两种合法写法：

- 每步结算：先处理重复（必要时跳 start），再 `max = max(max, i - start + 1)`。
- 延迟结算：if 分支只扩展窗口不结算；else（遇到重复）结算被截断的窗口 `[start, i-1]`，长度 `i - start`；循环结束后补最后窗口 `n - start`。

要点：公式必须匹配结算那一刻窗口的合法性——窗口含 i 且无重复才用 `i - start + 1`；
else 里 i 是重复字符，窗口只能算到 `i-1`，用 `i - start`。

## 8. 相向双指针：两端向中间收，移动条件更差的一侧

出处：LC0011 盛最多水的容器（两端夹逼）

左右指针从数组两端出发，每轮计算当前答案后，移动「条件更差」的一侧：
容器题移动较矮的边（高度是短板，移高边只会更差）；回文验证移动不匹配的一侧。
把 O(n²) 降到 O(n)，空间 O(1)。

适用：盛水容器、接雨水（变体）、验证回文串等两端夹逼题。

## 9. 排序后去重：保留重复值第一次出现，跳过后续重复

出处：LC0015 三数之和（固定第一个数 + 双指针夹逼时的去重）

| 写法 | 效果 |
| --- | --- |
| `i > 0 && nums[i] == nums[i-1]` 时跳过 | 保留该值第一次出现、跳过后续重复 → 同一三元组只输出一次 |
| `i < j-2 && nums[i] == nums[i+1]` 时跳过 | 丢掉重复组里靠前的那个，可能丢掉需要两个相同值的合法组合（如 -1,-1,2），且同一组合可能重复输出 |

要点：去重方向是「跳过已经用过的值」，而不是「跳过重复组里靠前的第一个」；三数之和允许两个位置取相同值，
所以第一次出现必须保留。双指针夹逼找到一组答案后，还要把两端的重复值一并跳过，避免同值不同下标的组合重复输出。

## 10. 链表删除倒数第 N 个：哨兵 + 快慢指针拉开 N 步

出处：LC0019 删除链表的倒数第 N 个结点（一趟扫描）

快指针先走 N 步，慢指针与 pre 从 head / dummy 同步前进；快指针走到 null 时，
慢指针正好指向待删节点，pre 是其前驱。dummy 哨兵让「删头结点」与普通删除共用同一段逻辑。

要点：一趟扫描 O(n)/O(1) 即可完成，不需要先数长度再走第二遍；
哨兵节点（dummy）统一处理头结点删除，避免特判「n == 链表长度」。

## 11. 三路原地分区：两个边界指针 + 一个扫描指针

出处：LC0075 颜色分类（0/1/2 原地排序，一趟扫描 + 常数空间）

0 与 2 各用一个边界指针（p0、p2），扫描指针 cur 负责遍历：

- `nums[cur] == 0`：与 p0 交换，p0++、cur++；
- `nums[cur] == 2`：与 p2 交换，p2--，**cur 不前进**（回看换入值）；
- `nums[cur] == 1`：cur++。

要点：扫描指针要么前进、要么停在原地回看交换进来的值，保证每轮必有进展，不会死循环，整趟 O(n)；
「两端都是 1 且中间全为 1」就是终态，靠 cur 越过 p2 结束，而不是靠 start/end 相撞。

## 12. Floyd 判圈找环入口：先移动后比较 + 第二阶段同速

出处：LC0287 寻找重复数（数组当下标链 i→nums[i]，重复数 = 环入口）

两个阶段：

- **相遇阶段**：slow 每次一步、fast 每次两步，直到相遇。两指针从同一起点出发时，
  必须先移动再比较（`do { ... } while (fast != slow)`，或初始化时让 fast 先走两步），
  用 `while (fast != slow)` 会因初始相等一次都不执行。
- **入口阶段**：slow 放回起点，fast 留在相遇点，两者都每次一步，再次相遇的位置就是环入口。

要点：O(n)/O(1)，不修改数组；「先走还是先比」由两指针初始位置决定——起点相同必须 do-while，
起点错开才能 while。

## 13. 滑动窗口覆盖子串：收缩只删多余、记录后整体前移

出处：LC0076 最小覆盖子串（覆盖判定 = 计数 + 未满足数 count）

覆盖类滑动窗口三件事：

- **扩展**：右指针前进，遇到需要字符（`need[c] > 0`）才 `need[c]--` 并 `count--`；
- **收缩**：只能删「多余」字符（`need[left] < 0`）——`need[left] == 0` 表示恰好满足、删了会破坏覆盖；
- **前进**：记录答案后，把左边界关键字符还回（`need[left]++`、`count++`、`left++`），窗口整体继续走。

要点：收缩用 `need[left] <= 0` 会把恰好满足的字符也还回去却不更新 count/left，覆盖状态与 count 脱节
（count 可能变负数），后续窗口全部失真。

注意：扩展时「判断 count 是否减」必须用 `need[c]--` **之前**的值——先减后判（减完再问
`need[c] > 0`）会让首次遇到的必需字符（减后为 0）永不触发 count--，count 恒不变、覆盖永远判不出来；
正确写法是先判（`need[c] > 0` 则 count--）再无条件减，或减后判断 `>= 0`。

## 14. 滑动窗口最值：单调队列（双端队列存下标）

出处：LC0239 滑动窗口最大值（窗口内最值，一趟 O(n)）

双端队列存**下标**，值从队头到队尾单调递减（队头 = 当前窗口最大）。两个方向的弹出各管一件事：

- **弹队尾**（入队前）：`nums[peekLast()] < nums[i]` 的全弹——新元素更大且更晚，被弹者永远当不了最大；
- **弹队头**（读答案前）：`peekFirst() < 窗口左边界` 的弹出——下标已滑出窗口（过期），必须淘汰。

要点：弹队尾是「比大小淘汰」，弹队头是「下标过期淘汰」，两者缺一不可；
队列存下标而不是值，才能判断过期。窗口左边界 = `i - k + 1`（或用独立左指针）。

注意：过期条件必须是 `peekFirst() < i - k + 1`（等价 `<= i - k`）；写成 `< i - k`
会漏掉恰好滑出窗口的那一格（下标 == i-k 已过期），递减/全负数用例仍会错。

## 15. 旋转有序数组二分：先判有序半段，再用值域归属 target

出处：LC0033 搜索旋转排序数组（旋转后仍有一半严格有序）

每轮三分步：

1. 中点：`mid = left + (right - left) / 2`（不能写成 `(right - left) / 2`，left > 0 时落在区间外）；
2. 判有序半段：`nums[left] <= nums[mid]` 说明左半段有序（闭区间左端）；
3. 值域归属：左半段有序时，仅当 `nums[left] <= target < nums[mid]` 才搜左，否则搜右；
   右半段有序时，仅当 `nums[mid] < target <= nums[right]` 才搜右，否则搜左。

要点：不能只拿 target 和 nums[mid] 比大小——必须同时检查 target 是否落在有序半段的
值域 `[nums[left], nums[mid])` / `(nums[mid], nums[right]]` 内，否则会把 target 错误丢出区间。

注意：① target 恰好等于 nums[mid] 时必须能命中，循环内要显式判断 `nums[mid] == target` 返回
（或分支条件含等号、边界收到 mid）；② 有序半段判定用 `nums[left] <= nums[mid]` 而不是 `>`——
区间只剩两个元素时 mid == left，`>` 恒 false 会进错分支。

为什么：旋转数组只有一个「山谷」（旋转点处大→小掉落），从任意位置切两半，最多一个半边含山谷，
所以必有一半有序；只有有序段能用值域判断 target 归属。左半段 `[left, mid]` 有序 ⇔ 没跨山谷 ⇔
`nums[left] <= nums[mid]`（`==` 只在 mid == left 的单元素段发生，天然有序）；若 `nums[left] > nums[mid]`，
山谷在左半段内，右半段 `[mid, right]` 才有序，此时仅当 `nums[mid] < target <= nums[right]` 搜右。

## 16. 二分下界（lower bound）的区间端点：right 取 n 还是 n-1

出处：LC0034 在排序数组中查找元素的第一个和最后一个位置（找 `>= target` 的第一个位置）

| 写法 | 循环条件 | 可返回的范围 | 空数组行为 |
| --- | --- | --- | --- |
| `right = nums.length`（右端点开区间） | `while (left < right)` | `[0, n]`，含插入点 n | 循环不执行，返回 0，语义正确 |
| `right = nums.length - 1`（右端点闭区间） | `while (left < right)` | `[0, n-1]`，表达不了 n | `right = -1`，循环不执行返回 0，解引用越界 |

要点：

- 「第一个 >= target 的位置」是 lower bound，target 可能大于数组中所有元素，此时答案是插入点 `n`，**答案在初始区间之外**；只有右端点取开区间 `n` 才能表达它。
- 闭区间 `[0, n-1]` 配 `while (left < right)` 在区间缩到只剩一个元素（`left == right`）时直接退出，**从不验证那个元素是否满足条件**：target 大于所有元素时停在 `n-1`，返回 `n-1` 而非 `n`。
- 该差一在「last = lower_bound(target+1) - 1」的组合里会传导成整体右边界差一：目标值在数组末尾（含单元素、全相同）时，结束位置报成 `n-2`。
- 空数组时 `right = nums.length - 1 = -1`，循环一次不执行直接 `return left`（0），上层再 `nums[left]` 就抛 `ArrayIndexOutOfBoundsException`。

要点口诀：二分前先问「答案会不会在区间之外」——lower bound / upper bound / 插入点这类问题答案可以是 n，右端点就必须是开区间；只有答案保证在数组内的查找（如查 target 是否存在）才允许闭区间端点。

## 17. 第 k 小 / 中位数的排名换算：1 基第 k 小 vs 0 基下标

出处：LC0004 寻找两个正序数组的中位数（两数组找第 k 小，迭代排除 k/2）

辅助函数若以「第 k 小」（1 基）为语义，代码有这些特征：

- 出口用 `nums[p + k - 1]` 直接返回（从起点 p 数起的第 k 个）；
- `k == 1` 返回当前头部较小值（1 表示「第 1 小」）。

调用方如果按 0 基下标算「中间位置」（如 `totLen / 2`）并直接当 k 传入，会整体偏小 1：

| 场景 | 0 基下标写法（错） | 1 基第 k 小（对） |
| --- | --- | --- |
| 奇数总长 totLen | `k = totLen / 2` | `k = totLen / 2 + 1` |
| 偶数总长 totLen | `k = totLen / 2 - 1`、`totLen / 2` | `k = totLen / 2`、`totLen / 2 + 1` |

换算关系：0 基下标 i 对应第 i+1 小。totLen=1 时若传 `totLen/2 = 0`，辅助函数算 `p + k - 1 = -1` 直接越界。

要点：调用前先确认被调函数的 k 是「第几个」（1 基）还是「下标」（0 基）；「第 k 个」的下标永远是 `起点 + k - 1`，反过来「下标 i」的排名永远是 i+1。

## 18. 递归反转链表：新头 vs 原后继（head.next.next = head）

出处：LC0206 反转链表（递归写法）

递归版 `reverseList(head.next)` 返回的是「反转后子链表的**新头**」，即原链表的尾节点；
它是最终要返回的答案，不是负责接回头部的那一端。

错误写法：`ListNode newHead = reverseList(head.next); newHead.next = head;` —— 把 head 接到了新头后面，
中间节点全部丢失（例：[1,2,3,4,5] 输出 [5,1]）。

正确接回：让「head 原来的后继」（现在位于反转后子链表的**尾部**）指回 head，即
`head.next.next = head; head.next = null;`，最后返回新头。

要点：分清两个角色——返回值（新头，最终返回）与 `head.next`（原后继，负责指回头部）；
递归层里能访问到原后继的唯一途径就是 `head.next`，因为它在反转后的子链表里已经被移到尾部。

## 19. LRU 哈希表+双向链表：两结构必须同步增删，哨兵判身份不判值

出处：LC0146 LRU 缓存

`map` 负责 O(1) 定位节点，双向链表负责维护使用顺序，两者必须同步更新，漏一步就会整个错位：

| 操作 | map | 链表 | size |
| --- | --- | --- | --- |
| 插入新 key | `map.put(key, node)` | 新节点插到 head 后 | `size++` |
| 命中 get / 更新已有 key | 不变（节点不变） | 先 cut 再 moveToHead | 不变 |
| 容量满时淘汰 | `map.remove(被逐出节点的 key)` | cut 掉 tail 前节点 | `size--` |

要点：

- 节点里必须存自己的 key，否则淘汰时不知道从 map 删谁。
- `size` 必须随插入/淘汰同步增减；只初始化不维护，`size == capacity` 永远不会成立，淘汰逻辑等于不存在。
- 哨兵节点用身份判断（`cur == head || cur == tail`），不要用 `value == null` 之类的值特征猜，值会变、身份不会变。

## 20. 递归收集结果：用局部列表+helper 参数，避免实例字段跨调用累积

出处：LC0094 二叉树的中序遍历（递归写法）

递归/回溯需要一个收集结果的列表时，两种安全做法：

- 入口方法内 `new` 列表，传给递归 helper 作为参数累加（推荐）；
- 用实例字段收集，但**入口每次先 `clear()`**。

坑：实例字段且不重置时，本地 main 多次调用同一实例，上一次的结果会残留串到下一次（例：第二个测试期望 `[]`，实际拿到第一个测试的结果）；
同时该字段若声明在提交标记区之外，提交包装后 `dfs` 引用它直接编译失败（找不到符号）。

要点：凡是「一次调用产生一份结果」的方法，收集容器的作用域要么限定在调用内（局部变量+参数传递），要么入口显式重置；声明位置也要放进提交区。

## 21. 迭代中序：cur 指针驱动 + 左链一次压栈，访问后 cur=cur.right

出处：LC0094 二叉树的中序遍历（迭代写法）

迭代中序遍历的骨架：

- 外层 `while (cur != null || !stack.isEmpty())`，用 `cur` 指针驱动；
- 内层**先把 cur 自己压栈**，再 `cur = cur.left` 直到 cur 为 null（只压左孩子、当前节点不入栈，首次弹栈就是 null → NPE）；
- 弹栈访问节点，然后 `cur = cur.right` 继续下一轮。

错误写法：每次循环从栈顶重新检查 `node.left` 并压栈——左孩子指针从未改变，同一个左子节点会被反复压入，死循环直至 OOM；
访问后若不把 `cur` 移到右孩子（而是把右孩子 push 进栈后继续看栈顶），同样会重蹈重复压栈；
另外空树（root 为 null）不能直接入栈，否则 peek 后取 `node.left` 直接 NPE。

要点：保证「每个节点只压一次」的关键是访问后把 `cur` 移到右孩子，而不是回到栈顶重新走左链；
节点本身入栈与 `cur = cur.right` 两步缺一不可。

## 22. BST 校验：上下界递归时，未收紧的一侧要继承而非重置为 ±∞

出处：LC0098 验证二叉搜索树

递归 helper 带 `(node, upper, lower)`，验证时：

- 左子树：`helper(left, node.val, lower)` —— 只收紧 upper，lower **继承**；
- 右子树：`helper(right, upper, node.val)` —— 只收紧 lower，upper **继承**。

错误写法：把没变化的一侧重置成 `Long.MIN_VALUE` / `Long.MAX_VALUE`，等于丢掉祖先约束
（例：根 10 → 右子树 15 → 15 的左子树 6，若 lower 被重置为 MIN，就漏掉 `6 > 10` 的检查，误判合法）。

要点：递归下降时，只有「靠近根的一侧」边界收窄，另一侧是当前路径上祖先给的约束，必须原样传下去。

## 23. 序列化/反序列化顺序一致性 + 队列栈进出配对

出处：LC0297 二叉树的序列化与反序列化

| 配对 | 语义 |
| --- | --- |
| `offerLast` + `pollFirst` | 队列（FIFO），先入先出，层序 |
| `offerLast` + `pollLast` | 栈（LIFO），后进先出，右子树优先的深搜序 |
| `offerFirst` + `pollLast` | 队列（FIFO），等价层序 |

要点：用 Deque 当队列时，「进」和「出」必须在两端配对；`offerLast` 配 `pollLast` 只是能跑，但顺序变成了栈序。
序列化与反序列化是「编码 / 解码」一对，字符串的顺序约定必须完全一致——层序序列化就按层序重建（先左后右），
否则两端各按各的顺序理解，还原出的树结构错位（例：正确层序 1,2,3 被序列化成右子树先行的 1,3,2，反序列化按左先读就串位）。

验证法：固定一棵树，看 `deserialize(serialize(t))` 是否与原树逐节点一致；失败时先打印 serialize 输出，人工按层序核对第几个 token 应该是谁。

## 24. 记忆化/哈希表：先定死 map 的 value 语义，value 必须是最终要比较的量

出处：LC0128 最长连续序列

用 map 做记忆化或统计前，先明确 key→value 存什么：

- 最终要比较的量（连续长度、最大值、次数）就必须直接存这个量本身；
- 中间定位值（链起点、前驱位置、偏移量）不能当最终量用。

错误示范：把「链起点再往前的数（`left - 1`）」存进 map，再拿它和 `max` 比较，结果是无意义数值；
跳链循环 `left -= map.get(left)` 用存储值当步长，存了负值时 `left` 会前后振荡，死循环。

要点：写 map 方案先回答一个问题——「key 查出来这个 value，我要用它做什么？」如果它最终要被比较/求和，
那它就该直接是那个数；如果只是定位用的中间值，就另存一份真正的结果。
无前驱的孤立数，长度基础值必须是 1；若公式里恒多 +1（如 `num - left + 1` 对孤立点算出 2），单元素/断开序列就会全错。

## 25. 链式记忆化：存在性判断基于全集，不能基于已处理集合

出处：LC0128 最长连续序列

算 `f(x) = 1 + f(x-1)` 时，`x-1`「在不在」必须问**全集**（所有输入先去重放入），
不能问「处理到当前为止见过没有」。否则输入乱序时前驱后到，`x` 被过早判定为孤立点，缓存值过期；
后面前驱进来了也没人回头重算 `x`（示例：`[100,4,200,1,3,2]` 得 2 而非 4，因为 3 先于 2、4 先于 3 到达）。

两种可行结构：

- 一个 map 全量放入（值标记「存在但未算」），按需递归/循环算长度，算过的直接返回；
- 一个 HashSet 存全集（只做存在性判断）+ 一个 HashMap 只做记忆化。

要点：记忆化缓存的值只在「查询依据稳定」时才不会过期；存在性依据必须是输入集合本身，而不是遍历进度。

## 26. 网格连通分量 DFS：四方向偏移 + 越界守卫 + 发现即计数

出处：LC0200 岛屿数量

网格连通题（岛屿、被围绕区域、填海造陆等）的统一骨架：

- 方向偏移只放**上下左右**四组（`{-1,0},{1,0},{0,-1},{0,1}`）；放成 8 组会把斜对角误连成同一块。
- `dfs` 开头先判越界，**出界才返回**；守卫写反（在界内却 return）会让所有在界调用直接返回。
- 主循环遇到「未访问的陆地」就计数 +1，并让 dfs 把整块标记完；dfs 不需要返回值参与计数。
- 空网格：先判 `m == 0`，再取 `grid[0].length`，顺序反了直接 AIOOBE。

要点：连通分量计数 = 「发现新块」时 +1，而不是对每个元素累加或取最大块大小；
越界守卫先写「什么情况安全退出」，再写「正常处理」。

## 27. 回溯枚举组合：空输入要提前返回，终止条件对空串直接成立

出处：LC0017 电话号码的字母组合

回溯枚举（字母组合、子集、排列等）里，终止条件 `len == 目标长度` 对空输入**一开始就成立**，
会把空串当成一个合法组合加入答案（`""` → `[""]`）；题目要求空输入返回空列表时，需在进入递归前单独返回。

另注意测试工具盲区：若规范化时把空串转成空内容，`[]` 与 `[""]` 无法区分（都显示 `[]`），
这类边界要用 `size() != 0` 之类的显式断言兜底，否则本地全绿、力扣 WA。

要点：先想清楚「长度为 0 是不是题目要的输出」；递归枚举类题目在入口处统一处理空输入。

## 28. 回溯枚举子集：两种框架不可混用，递归起点必须前进

出处：LC0078 子集

子集/组合类枚举有两种等价回溯框架，一次只能选一种：

- 框架 A（每个下标选/不选）：递归参数传下一个下标，分支是「加入」与「不加入」，不需要 for 循环；
- 框架 B（起点推进）：for i 从 start 起，只走「加入」分支并递归 (i+1)，「不加入」由循环自然推进，循环体内只有一个递归调用；
- 共性：下一层起点必须基于当前选择前进（i+1），传旧 index 会让同一元素重复入选（如 [1,3,3]）、子集重复、递归树超过 2^n 爆炸；
- 每次进入递归就把当前列表副本加入答案，空集由根节点自然产生。

要点：把两种框架叠用（for 循环里同时写「加完递归」和「删完递归」）会让每个状态被重复展开；
递归起点传错（index+1 而非 i+1）是这类题最隐蔽的爆炸源——本地跑小样例靠运气能过，跑满长度直接 OOM。

「不选」的位置要具体到 case：起点推进里 i 从 start 推进到 start+1 就是放弃 start——nums=[1,2,3] 时 i=1 分支的 list 从未包含 1，
跳过 1 的动作就是循环推进本身；讲解时禁止用「隐含/显然」带过，必须配这种逐层 case。

## 29. 递归枚举必须显式终止：决策下标越界即返回，不能访问越界元素

出处：LC0078 子集

选/不选框架没有 for 循环，终止条件必须显式：

- 递归参数是下一个待决策下标，当 index == 数组长度时，没有元素可决策，先返回；
- 子集题每个节点都是答案，越界前那层加入即可，但访问 nums[index] 前必须保证在界内；
- 从「起点推进」改成「选/不选」时，for 循环隐式的越界保护会消失，必须补上显式 base case，否则 AIOOBE。

要点：换框架时检查边界出口是否仍然存在；递归访问数组下标前，先保证下标在界内。

## 30. 答案收集时机绑定框架：选/不选只在叶子加答案，起点推进每节点加

出处：LC0078 子集

答案收集时机绑定回溯框架：

- 起点推进框架：每个节点形成的列表互不相同，进入 dfs 即可加答案；
- 选/不选框架：每个子集唯一对应一棵「叶子」，内部节点的列表与某个叶子重复，只能在叶子（所有元素决策完）加答案；
- 判断标准：同一个列表是否会被多条路径重复到达。

要点：换框架后，除了递归参数和终止条件，答案收集时机也要一起检查。

## 31. DP 填表顺序满足依赖方向 + 答案更新必须校验状态

出处：LC0005 最长回文子串

- dp[i][j] 依赖 dp[i+1][j-1]（左下方），按 i 正序、j 内层正序填会读到未计算的格子，必须按子串长度从小到大填（或 i 倒序）；
- 记录答案/最优解前必须确认 dp[i][j] 为 true：只看两端字符相等就更新会把非回文（如 abca）当成答案；
- 具体 case：abca 的 dp[0][3]=dp[1][2]=false，但若 ans 更新不看 dp，会错误返回 abca。
- 长度 2 的 base 不能走转移：dp[i][i+1] 已在初始化置位，主循环若再执行 dp[i][j]=dp[i+1][j-1] 会读到无效下三角（dp[i+1][i]=false）把 true 覆盖，所有偶数长度回文断链（aa→a、abba 丢失）；长度 2 应直接判两端相等，或转移前先排除 j==i+1。

要点：写 DP 先画依赖图确定填表顺序；从 dp 取值更新答案时，先校验状态本身成立。

## 32. 贪心最远可达：先判当前位置可达再更新，不可达立即返回

出处：LC0055 跳跃游戏

- 维护 farthest = 当前能到的最远下标，遍历每个位置 i：
  - 先判 i > farthest：当前位置都够不着，后面更够不着，直接返回 false；
  - 再更新 farthest = max(farthest, i + nums[i])；
  - 一旦 farthest >= n-1 返回 true。
- 顺序不能反：只更新不判可达，会让不可达位置的大跳跃把 farthest 推过终点，下一轮误判为 true。
- 具体 case：[1,1,1,0,5,0] 实际最远只到下标 3，位置 4 的 5 不可达，答案应为 false。

要点：贪心维护「最远可达」时，每个位置在更新前必须先确认自己可达；检查 → 更新 → 提前返回的顺序决定正确性。

## 33. 滚动数组：初始化已代表第 0 行，循环起点要偏移到 1

出处：LC0062 不同路径

- Arrays.fill(dp, 1) 已代表第一行（一路向右只有 1 条路径），外层循环应只处理第 2..m 行，即从 i=1 开始共 m-1 次；
- 若循环仍从 i=0 开始，第一行会被额外更新一遍，等于多算一行：m=1,n=10 应得 1 却得 10，3x2 应得 3 却得 4；
- 通用检查：写出初始化语义后，确认循环覆盖的区间与之不重叠；滚动数组常见错误就是「初始化一行 + 再跑 m 行」= m+1 行。

要点：状态初始化与循环起点的行数要对齐：init 占一行，循环只跑剩余 m-1 行。

## 34. 滚动变量原地更新：先存旧快照再整体替换，答案跟踪对象与状态语义一致

出处：LC0152 乘积最大子数组

- 把二维 dp 压成两个滚动变量时，转移公式的输入必须是「上一轮」的两个旧值；先更新 max 再算 min，min 的候选里就混进了本轮新 max（状态污染）；
- 正确做法：每轮先用旧 max/min 算出新值，再整体赋值（先保存快照，或用临时变量）；滚动只改存储方式、不改转移语义；
- 答案变量也要跟对对象：dpMax 的滚动结果才对应「最大」，答案应与其比较；把 ans 与 min 比较会丢掉已出现的最大值；
- 具体 case：nums=[-2,-3,-1]，正确过程 i=1 应得 max=6、min=-3、ans=6；原地更新 + 跟 min 比较会算出 i=1 的 min=-18，最终返回 -2 而非 6。

要点：滚动压缩只改存储、不改语义：两个状态必须在同一旧快照上计算，答案更新对象与状态定义一一对应。

## 35. DP 初始化必须覆盖该下标全部合法决策，不能只取一种

出处：LC0198 打家劫舍

- 递推起点状态要完整：dp[1] 表示前两间的最优，应同时包含「偷第 1 间」与「只偷第 0 间」两种候选（max(nums[0], nums[1])），只存 nums[1] 等于强制第 1 间必偷；
- 具体 case：nums=[2,1,1,2]，正确起点 dp[1]=2，才能在 i=3 得到 dp[1]+2=4；起点只存 1 时 i=3 只能算出 1+2=3，返回错误；
- 修复后一维 dp 单调不减（dp[i]≥dp[i-1]），答案直接取 dp[n-1] 即可，末尾再 max(dp[n-1], dp[n-2]) 是冗余（无害）。

要点：写 DP 时先写出「下标 x 的状态语义」，初始化时逐项核对它应包含哪些候选，别让起点丢情况。

## 36. 字符串匹配 DP：前缀长度语义 + 循环含端点 + 星号分支三要素

出处：LC0010 正则表达式匹配

- dp[i][j] 用前缀长度语义（0..len，共 len+1 个状态），循环必须遍历到 s.length() 与 p.length()（含端点），否则最后一行/列和答案格永不填充；取字符一律 charAt(i-1) / charAt(j-1)；
- 星号分支三要素：零次走 dp[i][j-2]；一次及以上走 dp[i-1][j]，且要求 i>0、s.charAt(i-1) 匹配 x（x 为 '.' 或等于该字符）；两条取或；
- 具体 case：s="aa"、p="a*"，若 j 只循环到 p.length()-1，dp[2][2] 从未填，答案错误返回 false；s="ab"、p=".*"，若星号匹配漏掉 '.' 通配，正确 true 却返回 false；
- 取 s.charAt(i-1) 前必须先保证 i>0，否则 i=0 时直接数组越界。

要点：dp 的每个边界格都要被循环覆盖；分支访问字符串前先确认下标存在。

## 37. 值域 [1,n] 数组原地归位（cyclic sort）

出处：LC0448 找到所有数组中消失的数字

- 值 x 应放下标 x-1，就位判断用 `nums[i] == i+1`（不是 `i-1`）；
- 把 `nums[i]` 换到目标位前先检查目标位是否已有同值：已有说明该值是重复的，跳过当前下标；否则交换可能无变化、扫描指针不前进而死循环；
- 扫描指针每轮要么就位、要么前进，保证每轮必有进展，整趟 O(n)；第二次扫描时 `nums[i] != i+1` 的位置 i+1 即缺失数字。
- 具体 case：`[1,2,3]` 用错条件 `nums[i] != i-1` 会在 index=0 处自我交换死循环；`[1,1]` 在 index=1 时目标位 nums[0] 已有 1，无重复守卫则交换不变死循环。

要点：写「值放回位置」的原地算法时，先写清「值 x → 下标 x-1」的映射，再核对就位判断与重复/已占位分支，确保指针每轮必前进或就位。

## 38. 子数组和=前缀和之差：map 计已见前缀，先查后登记

出处：LC0560 和为 K 的子数组

- map 存「已出现的前缀和 → 次数」；单层循环里先查 `prefix[j]-k` 累加答案，再登记当前 `prefix[j]`，顺序不能反（反了会把空子数组/当前前缀算进去）；
- 初始 map 放入空前缀 0：约定 A（prefix[i]=nums[0..i]，虚拟 prefix[-1]=0）与约定 B（prefix 长度 n+1，prefix[0]=0）都要放，否则漏掉所有从下标 0 开始的子数组；
- 查询目标是 `prefix[j]-k`，登记键永远是当前 `prefix[j]`，两者不可混；
- 必须是单层循环：map 随 j 前进累积「j 之前出现过的前缀」；双层循环会把同一批前缀重复配对，导致重复计数。

要点：前缀和计数题的 map 语义是「已见过的前缀和频次」，每一轮固定「先查目标、再登记自己」，循环层数与 map 累积方向一一对应。


## 39. 计数/收集时机绑定终点：别把判断下放到子递归入口

出处：LC0437 路径总和 III（双重 DFS 计数）

| 场景 | 正确做法 |
| --- | --- |
| 枚举「以 X 为终点的向下路径」并计数 | 判断绑定在「把 X.val 计入路径和」之后，每节点恰好检查一次 |
| 新起点 / 顶层入口的初始状态 | cur=0 不代表任何真实路径，不能拿来和 target 比较 |

要点：

- 把 `cur + X.val == target` 的判断放到**进入左右孩子时**执行，等于对同一条「以 X 为终点」的路径检查两次（左分支一次、右分支一次），计数变成 2 倍（示例 3→6）。
- 入口处 `cur=0` 是「路径还没包含任何节点」的初始状态；target=0 时它会制造虚假命中：空树直接 dfs(null,0) 得 1，每层新起点调用再各加一次，叠加出 17/21 这类数字。
- 判定时机应绑定「当前节点值已计入路径和」这一事件，而不是子递归入口或初始状态。

## 40. 回溯删除最小化：先算最小删除预算，连续相同只删第一个

出处：LC0301 删除无效的括号（Hard，回溯）

- 一遍扫描算出必须删的数量：`)` 在 balance=0 时出现 → 多余右括号 +1；扫完 balance 剩余 → 多余左括号数。最小删除总数 = 两者之和，之后 DFS 以此为预算，超过即剪枝。
- 枚举「保留/删除」两分支时，共享容器（StringBuilder/List）必须递归后撤销（deleteCharAt/remove），否则兄弟分支拿到被污染的现场。
- 去重：连续相同的括号删任意一个结果相同，只在「连续段第一个」上触发删除分支，同一结果只生成一次。
- 条件判断警惕恒真陷阱：`c != '(' || c != ')'` 对所有字符恒 true（'非A或非B' ≠ '非(A且B)'），导致删除分支永远不可达。

要点：删除类回溯三件套 = 预算（先算最小删除数）+ 撤销（共享容器还原）+ 去重（连续相同只删第一个）；叶子收集时校验合法性（balance==0）。
